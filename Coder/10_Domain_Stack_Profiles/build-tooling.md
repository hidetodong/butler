# Frontend Build Profile

## 1. 适用条件

- 仅在当前项目明确使用对应前端构建栈时启用。
- 未命中相关前端构建栈时，不应将本文件内容视为默认通用约束。

## 2. 技术栈基线

- 构建工具：Rsbuild
- Bundler：Rspack
- 包管理：优先使用 pnpm

## 3. 基本原则

- 优先使用官方能力解决构建问题。
- 非必要不覆盖底层打包配置。
- 构建配置服务于模块边界，不服务于炫技。
- 环境差异通过明确配置管理，不写死在源码里。

## 4. 推荐关注点

- alias：统一路径引用
- 环境变量：按环境注入，不把敏感配置写入源码
- 多入口 / 子应用：仅在明确需要时开启
- 静态资源：明确媒体、图标、配置资源边界

## 5. 性能建议

- 大型页面或编辑器按路由或模块拆分。
- 重计算逻辑放入纯函数或 worker 候选层。
- 重依赖按需加载。
- 面板类 UI 组件避免全量响应式深监听。

## 6. Monorepo 协作建议

对于中大型项目，可按以下维度拆包：

- `apps/`：具体应用
- `packages/ui`：基础组件
- `packages/domain`：领域模型与规则
- `packages/shared`：公共工具
- `packages/plugins`：插件集合

包边界原则：

- UI 包不得反向依赖业务应用包。
- Domain 包尽量保持框架无关。
- Plugin 包通过契约接入，不直接耦合页面实现。
- Shared 包只放真正跨域复用内容。
