# Code Review 通用审计准则

本文件定义"什么是好代码"的通用底线。审查时，本准则与已激活的 `10_Domain_Stack_Profiles/` 共同构成完整审计口径。

## 1. 逻辑与健壮性 (Logic & Robustness)

- **边界处理**：是否处理了空值、零值、空集合等边界输入？异步操作是否有错误处理？
- **单职责原则**：一个函数或组件是否只做了一件事？是否存在承担过多职责的"上帝函数"？
- **防御性编程**：外部输入（用户输入、API 响应、URL 参数）是否在系统边界处做了校验？内部代码是否避免了多余的防御？
- **状态一致性**：多处修改同一状态时，是否有竞态或不一致风险？

## 2. 可读性与命名 (Readability & Naming)

- **语义化命名**：变量名、函数名是否能准确表达其含义？是否存在单字母变量或含义模糊的缩写？
- **魔术值**：硬编码的数字和字符串是否被提取为命名常量？
- **结构清晰**：控制流是否简洁？嵌套层级是否超过 3 层？是否存在可提前返回简化的分支？
- **注释质量**：注释是否在解释"为什么"而非"是什么"？是否存在过时或误导的注释？

## 3. 性能 (Performance)

- **无谓计算**：循环内是否有可提到循环外的不变计算？是否存在重复的遍历或查询？
- **资源泄漏**：定时器、事件监听、订阅、连接等资源是否在生命周期结束时正确清理？
- **数据结构选择**：频繁查找是否使用了 Map/Set 而非数组遍历？

## 4. 安全 (Security)

- **注入防护**：涉及 HTML 渲染、SQL 拼接、命令执行的地方是否有输入过滤或参数化？
- **敏感信息**：是否有密钥、token、密码硬编码在代码或提交历史中？
- **权限边界**：涉及权限判断的逻辑是否在服务端执行，而非仅依赖前端校验？

## 5. 领域专项审计

以上为通用审计维度。技术栈专项审计规则（如 Vue 3 响应式开销、TypeScript 类型严谨性等）由当前任务已激活的 `10_Domain_Stack_Profiles/` 提供。

审查时，review-engine 会自动合并通用准则与已激活 profile 中的审计相关规则，形成完整审计口径。未命中任何 profile 时，仅按本文件的通用维度执行审查。
