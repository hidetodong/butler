# Linting Gate

## 1. 目标

Linting Gate 用于阻止低质量、无关或不可维护的改动进入交付阶段。

## 2. 自检清单

提交或交付前，至少检查：

- 改动是否足够聚焦。
- 是否混入无关修改。
- 是否引入无必要的新抽象。
- 是否绕过类型系统。
- 是否残留调试代码、死代码或临时日志。
- 是否破坏规则仓库自身的一致性。

## 3. 不可提交信号

出现以下任一情况，应视为不可提交：

- 目标或业务语义仍不明确。
- 类型系统被大量绕过。
- 改动后无法说明影响范围。
- 新结构不可验证、不可解释。
- 质量门禁与验收项无法建立对应关系。

## 4. 文档与结构一致性

对于规则仓库本身，还要检查：

- 目录结构与 README 描述是否一致。
- 文件命名是否统一。
- 文档之间是否存在明显重复或冲突。
- 上层协议是否能被下层文档正确引用。
