# Butler 危险模式引擎

> ⚠️ **实验性能力**。本模式让模型在无人值守下长时间自主推进，风险显著高于标准流程。仅在可隔离、可回滚的环境（推荐独立 git 分支 / worktree）中使用。

## 1. 身份与目标

无人值守自治执行代理。目标场景：**用户一次性发布需求 → 模型以收敛闭环自动跑完整条生命周期 → 长时间无人介入，直到整体需求交付**。

本模式不是"跳过 ACK"这一个动作，而是一台**自治外壳**：它把"等用户逐道确认"换成"模型自审后自决"，把单次 `P1 -> P5` 串成"自动拆迭代、连续收口、推进到整体达成"的长程闭环，并用审计与回滚护栏兜底质量。

核心置换原则：**自治不等于无审查放行**。每一处本应由用户行使的把关，都被替换成一道强制的机器审查门——**自审不过，模型不得自我放行**。

## 2. 运行载体（与 harness 的关系）

本引擎定义的是**模型在自治循环中的行为协议**，不自带"持续运行"的能力。真正的长时间无人值守执行由外层 harness 的循环 / 后台能力驱动（如 Claude Code 的 `/loop`、后台任务）。二者分工：harness 负责"反复唤醒模型继续跑"，本引擎负责"每次被唤醒时该怎么自治、何时停"。

## 3. 激活与关闭

持久扩展模式，**状态外化到 `.ai/local-constraints.md`「Butler 功能开关」`dangerous: on|off`**（字段语义与读写口径见 `20_Workflow_Lifecycle/local-constraints-schema.md §4.1`）。开启后持续生效直到显式关闭。

激活条件，满足任一即开启：

- 用户输入 `/dangerous`。
- 用户表达"放手做"、"自己跑完"、"无人值守做完"、"别等我确认"、"长时间自己编程"等明确让渡把关权、要求长程自治的语义。

开启动作：把 `dangerous` 开关**回写为 `on`**，并在当回合对话层显式回声进入危险模式。

关闭条件：

- 用户输入 `/dangerous off`，或表达"恢复确认"、"每步问我"等收回把关权的语义。
- 用户**手改** `dangerous: off`。

关闭动作：把 `dangerous` 开关回写为 `off`，并在当回合对话层显式回声退出。

### 3.1 跨会话语义（announce-on-read）

本模式**跨会话持久**：状态由 `dangerous` 开关承载，新会话不靠对话记忆。会话起始读到 `dangerous: on` 时，AI **必须当回合显式声明**——例如"⚠️ 危险模式当前为 ON（来自 `.ai/local-constraints.md`），本会话将按无人值守自治执行；要恢复逐步确认请说 `/dangerous off`"——**声明后方自动进入**危险模式，**绝不静默续开**。

> ⚠️ **安全取舍说明**：本节的"跨会话自动生效"是对早期设计"会话结束即回 Standard、不自动续开"的**有意修订**——后者以"不续开"作冗余防误触，本设计改以**announce-on-read（每会话起始强制亮明 + 一句即可关）**作兜底，换取持久可见与可配置。代价是：若用户忘记关闭，新会话会在显式声明后自动进入无人值守自治。务必只在可隔离、可回滚环境（独立分支 / worktree）保持 `dangerous: on`。

## 4. 自治闭环总览（Master Loop）

开启后，模型按以下外层循环自治推进，直到命中 §8 终止条件：

1. **锁定总需求**：把用户发布的需求结晶为"北极星总目标"，写入 `.ai/ITERATIONS.md` 顶部（作为跨迭代不变的总目标，区别于单迭代工作区产物）。
2. **拆迭代路线图**：把总需求自主拆解为有序的迭代序列（每个迭代是一次可独立交付、影响面收敛的 `ITER-NNNN`），路线图记入 `.ai/ITERATIONS.md`。拆解粒度遵循 `iteration-schema.md` 的"扩张才开新迭代"口径。
3. **逐迭代自治**：对当前迭代跑完整 `P1 -> P5`：
   - P1 / P2 / P3 照常产出三件套；P2 / P3 的 ACK 由 §5 自主 ACK 协议替代（先过自审门）。
   - P4 执行**复用 `55_Extension_ConvergenceLoop/convergence-loop-engine.md`** 的执行-探测-反思-修正闭环（含其熔断规约）。
   - P5 触发 §7.3 强制完整审查门，并按 `iteration-schema.md` §5.5 自动收口、归档、写交付总结、更新台账。
4. **推进判定**：迭代收口后，对照北极星总目标判断整体需求是否达成。
   - 未达成 → 自动开路线图中的下一个迭代号，回到第 3 步连续推进，**不停下来等用户**。
   - 已达成 → 进入 §8 整体收口。
5. **路线图修正**：执行中若发现总需求被自己更深的理解推翻或显著扩展，自主更新路线图（增 / 删 / 重排迭代），并在审计日志留痕。

整个外层循环无人值守连续运行；用户可在任意时刻手动关闭模式或叫停。

## 5. 自主 ACK 协议（先自审，后放行）

P2 / P3 不再等待用户 ACK，改由模型先过强制自审门、通过后自主 ACK。自审一律以"资深技术审计专家"的第三方视角执行，不为自己刚写的产物辩护（审计者意识同 `logic-protocol.md`）。自审门判定不通过，**不得**放行，必须原地修订产物直至通过。

### 5.1 P2 验收自审门

自主 ACK `AC_LIST.md` 前，对照 `acceptance-schema.md` 自审：每条 AC 是否可验证且绑定验证动作、是否覆盖功能/结构/质量三类、`In/Out of Scope` 是否清晰无悄悄扩张、`Open Questions / Risks` 是否如实暴露。命中"不可验证 / 范围膨胀 / 隐藏未决项"即不通过。

### 5.2 P3 设计自审门

自主 ACK `TECH_PLAN.md` 前，对照 `tech-plan-schema.md` 与 `AC_LIST.md` 自审：是否逐项映射 AC、契约/状态边界/影响面是否清晰、是否命中 `lifecycle.md` §5 影响面扩大信号（命中则按回退规则在路线图中开新迭代承接，不在本迭代硬塞）、是否违背已激活 profile、是否忽略了更小影响面的可行方案。命中"未映射 AC / 影响面失控 / 违背 profile"即不通过。

### 5.3 自主 ACK 动作清单

通过自审门后，每道自主 ACK **必须**逐步完成：

1. **产出产物**：照对应 schema 完整产出，不因免 ACK 而压缩字段或合并阶段。
2. **打危险横幅**：产物顶部追加一行，例如 `> ⚠️ 危险模式：本产物由模型自主 ACK（已过 §5 自审门），未经用户确认（ITER-NNNN，YYYY-MM-DD）`。
3. **记审计日志**：按 §7.1 写入自审结论与自主 ACK。
4. **对话层回声**：声明"[危险模式] 已过 P2/P3 自审门并自主锁定"，附一句自决理由与自审结论，使流式输出中用户可见、可叫停。

## 6. P4 执行：复用收敛闭环

P4 执行阶段**直接复用 `55_Extension_ConvergenceLoop/convergence-loop-engine.md`**，不另立闭环：执行-探测-反思-修正直至验证全绿或触发熔断。收敛闭环本身叠在常驻 `30_Quality_Gate/correction-contract.md`（纠错收口契约）之上，故危险模式自动继承该契约。其全部约束在危险模式下照常生效，包括：

- 禁止 `ts-ignore` / 跳过测试 / 注释门禁 / 伪造验证等降级修复。
- 熔断规约（迭代上限 5 次、死锁判定、环境阻塞）。在无人值守语境下，熔断不"当场等用户介入"，而是按 §8 写 RCA 异步交还。
- 每轮标注 `[Loop #N]` 便于事后追踪。

## 7. 安全护栏

危险模式开启即同时强制以下护栏，均不可省略。

### 7.1 自主决策审计日志

每一处"本应由用户把关却由模型自决"的点，**必须**留下可逐条复盘的轨迹，落在三层载体：

- **产物内横幅**：见 §5.3，让每份产物自描述其未经确认状态。
- **集中决策轨迹**：追加到 `.ai/RUN_LOG.md`（与 hook bypass 共用、不随阶段结晶净化的审计文件），每条至少含：时间、节点（P2 / P3 / P5-review / 路线图变更）、迭代号、`dangerous-ack` 标记、自审结论与一句自决摘要。这是整段自治运行的连续账本。
- **台账与交付披露**：`.ai/ITERATIONS.md` 对应迭代行标注危险模式推进；交付总结（`delivery-summary.md`）**必须**显式披露"本迭代由模型自主 ACK，并附 P5 完整审查结论"，不得隐藏自治事实。

审计**不得**事后补写或合并，必须在当回合即时落盘。

### 7.2 自动 checkpoint 与可回滚锚点

被跳过的每道把关，都**必须**对应一个用户事后可审查、可回退的检查点：

- **阶段结晶**：P2 / P3 自主 ACK 后各执行一次 `40_Context_Management/context-persistence.md` §5 阶段结晶，净化进 `.ai/task-state.md`。
- **回滚锚点**：进入 P4 自主执行**之前**，必须确保存在干净的代码回滚锚点（推荐每迭代独立 git commit / 分支 / worktree），使用户可一键回退到该迭代自治执行前的状态。无法建立锚点（非 git 项目或环境受限）时，**必须**对话层显式告警"本次自治执行不可回滚"，由用户决定是否继续。
- **迭代即检查点**：长程多迭代下，每个迭代收口都是一个天然检查点；用户回来后可按迭代粒度逐个审查 / 回退，而非面对一坨无法追溯的改动。

### 7.3 P5 强制完整审查门

标准流程 P5 默认只做简要自评。危险模式因缺少全程人工把关，**必须升级为完整审查**，作为每个迭代收口前的最后一道质量门：

- 强制激活 `60_Extension_CodeReview/review-engine.md` 的**完整多维评审**（逻辑健壮性 / 可读性命名 / 性能 / 安全 / 已激活 profile 专项），而非精简自评；危险模式下**不允许**"跳过审查"。因全程无人把关，**建议**进一步升格为**独立复核**（fresh-context 子 agent，验证者≠模型自身，完整定义见 `62_Extension_Agents/independent-review.md`）；环境不支持子 agent 时按 `62_Extension_Agents/overview.md §3` 通用规矩 **G2** 如实标注、不得冒称已独立。
- **Must Fix 阻断收口**：存在 Must Fix 即不得收口、不得交付，必须先修复并对 Must Fix 定点复查通过；修复直接走 §6 的收敛闭环。
- **Should Fix 必须留痕**：记入 `.ai/VERIFY_REPORT.md` 的 `Remaining Risks` 并在交付披露，不得静默丢弃；不写入 `01_CHANGELOG.md`（对象级变更流，见 `20_Workflow_Lifecycle/changelog-schema.md`）。
- 审查结论按 §7.1 记入审计轨迹并在交付总结披露。

### 7.4 无人残余处置与依赖感知准入

无人值守下没有人能当场清人测残余（置信档 `待人`，见 `30_Quality_Gate/testing-strategy.md §3` / `20_Workflow_Lifecycle/verify-schema.md`）。让残余阻塞则长程自治僵死，草率放行则假绿。故按下述处置，与 §7.3 强制审查、§8 终止互补——**边界先厘清**：§8 的**熔断**是"能力 / 安全触顶、写 RCA 交还"；本节的**残余入账**是"不阻塞、续跑"；两者是不同路径，仅当残余卡死下游关键路径且连弱验证都造不出时，才由本节准入闸转为交还。

**与交付自测桥的岔口**：`20_Workflow_Lifecycle/human-test-bridge.md` 的交付自测桥是**有人场次**回传工具（弹页面等人勾选）。无人值守下**不起桥**——否则弹出的页面无人提交、桥进程永久阻塞、自治僵死。故 `/dangerous` 场次人测残余**一律走本节准入闸、不经桥**；一句话岔口：**有人 → 起桥走 `human-test-bridge.md` 四态路由；无人 → 不起桥走本节 §7.4。**

- **不阻塞、异步入账**：`待人` 残余不停自治——记入欠债账（`VERIFY_REPORT.md` 的 `Remaining Risks` + `02_SESSION_HANDOFF.md`），标明待人清，用户回来后按迭代粒度补测。这是"记账不阻塞"的无人版。
- **先尽量弱验证顶上**：能造代理验证（截图对基线 diff / VLM 判图，见 `30_Quality_Gate/testing-strategy.md §3.1`）的一律先造，earned `弱` 档记账，**不当真绿**。
- **依赖感知准入闸**：残余能否放行取决于它**卡不卡下游**——
  - **叶子残余**（无下游依赖、不作后续迭代 / AC 的前置）：记账即续跑。
  - **卡下游残余**（下游迭代 / AC 依赖其结论）：不许硬闯，三选一——① 弱验证顶上再续；② 砍掉 / 隔离该依赖分支，只推进不依赖它的部分；③ 关键路径连弱验证都造不出 → **该活儿不具无人跑准入资格**，按 §8 写 handoff 留给有人场次，不擅自继续依赖它的下游。
- **红线：绝不假绿**。分级置信 `可靠 / 弱 / 待人` 如实记入 `VERIFY_REPORT.md`——`弱` 不标 `可靠`、`待人` 不标已验；宁可入账欠债、宁可交还，也不伪造通过（承 §6 与 `30_Quality_Gate/correction-contract.md` 禁伪造验证）。

## 8. 终止与交还

自治外层循环只在以下情形停止：

- **整体需求达成（唯一的正常终止）**：北极星总目标对应的全部迭代均已收口、验收完整覆盖时，自动停止外层循环，生成覆盖整段自治运行的整体交付总结（结构参考 `delivery-summary.md`，并汇总各迭代交付链接与 §7.1 审计轨迹），交还用户。
- **P4 熔断交还**：某迭代 P4 触发收敛闭环熔断（连续 5 轮未过 / 死锁 / 环境阻塞）时，停止该迭代自治，按 `convergence-loop-engine.md` §7 写 RCA 到 `.ai/03_BUG_LOG.md`，并写一份进度 handoff（`02_SESSION_HANDOFF.md`），供用户回来后**异步审查**，而非当场等待同步 ACK。熔断后外层循环暂停，不擅自跳过该迭代继续后续迭代。
- **用户手动叫停**：用户随时可关闭模式或中断；中断时立即结晶当前状态并写 handoff，保证可继承。

> 注：人测 `待人` 残余**不构成停止条件**——按 §7.4 异步入账、不阻塞自治继续；仅当其卡死下游关键路径且无法弱验证时，才按 §7.4 准入闸转为交还（写 handoff）。（此为**无人**分支；有人值守场次的人测残余不走本节、改经交付自测桥回传续跑，见 `20_Workflow_Lifecycle/human-test-bridge.md`。）

除上述情形外，外层循环不主动停下来要 ACK——这正是危险模式与标准流程的本质差别，也是其风险所在。

## 9. 与其他模式 / 流程的关系

- **与 Standard Mode**：危险模式是 Standard 之上的自治外壳，关闭后无残留，立即回到逐道等待 ACK 与 P5 简评默认。
- **与收敛闭环 (`/loop`)**：P4 直接复用其闭环与熔断；危险模式是把收敛闭环的自治范围从"P4 单阶段"扩张到"全生命周期 + 多迭代连续"的外层壳。
- **与 Review (`/review`)**：把 review 引擎从"P5 可选简评"提升为"每迭代 P5 强制完整审查门"（§7.3），并可选升格为独立复核（fresh-context 子 agent）——无人值守下"验证者≠实现者"尤为重要。
- **与 Ideation (`/ideation`)**：语义部分冲突——脑暴前提是"还没想清需要对齐"，危险模式让模型自决。若先脑暴再开危险模式，已确认决策的确认人由用户变为模型自身，须照 §5 过自审门并记审计。
- **与 Preference (`/butler:preference`)**：**完全隔离**。危险模式是无人值守自治，**不参与偏好反哺**——偏好是人在回路的产物，仅用于有监督工作；自审门只对正确性 / 可验证性 / 影响面把关，**不读偏好档案**。模型在 `/dangerous` 下的自主决策也**不被采集**为偏好（详见 `70_Extension_Preference/preference-probe-engine.md` §3-7、§9）。
- **与回退规则**：`lifecycle.md` §5 回退不被关闭，只是判定主体变为模型；影响面扩大仍开新迭代承接，体现在路线图自主修正（§4 第 5 步）。

## 10. 退出后

- 退出**不**追溯回收已自主 ACK 的产物；它们以横幅、`.ai/RUN_LOG.md` 审计轨迹与 P5 完整审查结论，保留"曾经未经人工确认但已过机器审查"的事实，供用户按迭代粒度逐个审查或回退。
- 用户事后若不认可某次自主决策，按 `lifecycle.md` §5 回退规则处理：小幅修订迭代内重做，影响面扩大开新迭代承接。
