# intake-schema（需求录入三层契约）

> **本契约是 `.ai/INBOX.md` 这条路径上唯一的规则真源**（自 MILE-0016 R7 生效，R8 删掉上一代契约后成为唯一）。
> **谁在写盘**：`.ai/INBOX.md`、`.ai/milestone-backlog/` 与待办区索引的写入者是 `tools/intake/intake.py` 一家，它照的是本契约。动作边界见 `intake-workflow.md`。
> **遇到分歧听谁的**：凡涉及这三层的读写格式，**一律以本文件为准**。

需求从产生到开工要过三道关：随手记一句（闪念口）、想清楚值不值得做（孵化区）、真的开工（执行分流）。本文件把这三层各自长什么样、状态怎么转、什么条件下能往下走一层定死。它**只定数据形态**，不定命令怎么调、参数怎么传、回执怎么打印。

**目录落点的现状与将来**：孵化区当前的目录名是 `.ai/milestone-backlog/`，本文件全篇按这个真实路径写。MILE-0016 R9 会把它改成更中性的名字（因为它将来装的不只是里程碑那一档），届时本契约随同批改，不提前按将来的名字写。

## 1. 第一层 · 闪念口 `.ai/INBOX.md`

### 1.1 定位

闪念口回答一件事：**我当时想到了什么，后来怎么处理的**。它不是原文仓库，不是任务台账，也不是历史日志。一条闪念就是一句话加一个去向，重到需要展开论证的东西属于下一层。

### 1.2 结构

整个文件只有一张表，放在固定的二级标题 `## 闪念` 下。表头逐字固定：

```md
## 闪念

| 闪念键 | 记于 | 一句话 | 状态 | 去向 |
|---|---|---|---|---|
| 2026-08-20-inbox-too-heavy | 2026-08-20 | 收件箱那套双指纹太重，没人用得起来 | incubated | .ai/milestone-backlog/inbox-rebuild.md |
```

**不设受管区块标记**。受管区块标记指的是 `<!-- xxx:begin -->` / `<!-- xxx:end -->` 那种成对注释，机器靠它认边界、然后把整块推倒重写。本层只有两种写法——在表尾追加一行、改某一行的状态列和去向列——没有整块重写这回事，标记就是纯负担。

### 1.3 字段

| 字段 | 取值 | 约束 |
|---|---|---|
| 闪念键 | `YYYY-MM-DD-<kebab 短句>` | 全文件唯一；同日撞名在尾部接 `-2`、`-3` |
| 记于 | `YYYY-MM-DD` | 与闪念键的日期部分一致 |
| 一句话 | 自由文本 | 一行写完，不换行、不嵌表格；写「想到了什么」，不写论证 |
| 状态 | 见 §1.4 封闭枚举 | 不得出现枚举外的值 |
| 去向 | 路径 / 迭代号 / 一句话原因 / `—` | 取值随状态定，见 §1.5 |

**闪念键为什么长这样**：日期加短句，人一眼能读，机器能当唯一键用。**不得**改用递增号池（带固定前缀的四位数字全局计数器，得有人维护「下一个号是几」；上一代收件箱契约用的就是这种，已随 R8 退役），**也不得**引入内容指纹认亲（拿哈希比对「这条是不是变过、是不是同一条」）。理由是闪念本来就是随口记的一句话，没有「同一条内容的第二个版本」这个概念；真重复记了两条，人自己删一条比机器认亲便宜得多。先例现成：`.ai/references/prd/` 底下的需求目录早就是日期加 slug。

### 1.4 状态：四态封闭枚举

| 状态 | 含义 |
|---|---|
| `new` | 刚记下，还没决定怎么办 |
| `incubated` | 已进孵化区，正在想值不值得做 |
| `done` | 已经办了 |
| `dropped` | 决定不办 |

这四个值是**封闭枚举**：不得新增、不得用同义词、不得留空。

### 1.5 合法转移：穷举四条

| 转移 | 触发 | 去向列写什么 |
|---|---|---|
| `new → incubated` | 在孵化区建了草稿 | 草稿路径 `.ai/milestone-backlog/<候办键>.md` |
| `new → done` | 当场就办完了 | 迭代号（如 `ITER-0117`）或一句话说明 |
| `new → dropped` | 当场决定不办 | 一句话原因 |
| `incubated → dropped` | 孵化区草稿被撤回（见 §3.4） | 一句话原因 |

除此之外的转移一律非法。特别地：

- **终态不回头**。`done` 和 `dropped` 是终态，**不得**转回 `new` 或 `incubated`。同一件事过一阵又想起来，那就是**一条新闪念**——新日期、新键、状态 `new`。允许回退等于给状态机开一个环，而这一层没有任何机器检查能拦住环里的错。
- **`incubated` 不直接转 `done`**。草稿真被提升或开工时，闪念行按 §3.5 回写为 `done`，写的是执行分流的结果，不是闪念口自己在跳态。

### 1.6 清理纪律

- 终态行（`done` / `dropped`）在「去向」指的东西真正落地之后，**可以整行删掉，不留墓碑**。跟 `.ai/debt.md` 一个规矩：还清了就删，不留一行「此处曾有一笔」。
- `new` 行**不得删除**，只许按 §1.5 转移。否则「记了但被悄悄抹掉」这条路就通了，闪念口就不再可信。
- `incubated` 行不得删除；它的命运由孵化区那份草稿决定。

## 2. 第二层 · 孵化区 `.ai/milestone-backlog/`

### 2.1 定位与既有真源

孵化区是「想清楚值不值得做」的地方。它的索引表、候办键规则、一方向一文件纪律、与 `current` 指针的关系，真源在 `20_Workflow_Lifecycle/milestone-schema.md §4.5`，本文件不重抄。**本文件只加一件事：规模分档。**

### 2.2 规模字段

每份草稿顶部必须恰好标明三行，各出现一次：

```md
候办键: <文件名 slug>
候办状态: deferred
规模: milestone
```

`规模` 是**封闭三档**：

| 规模 | 含义 |
|---|---|
| `milestone` | 够一个版本方向，要拆成多个迭代 |
| `iteration` | 一个迭代能收口 |
| `undecided` | 还判断不了多大 |

### 2.3 按档定结构

| 规模 | 草稿必须有的段落 |
|---|---|
| `milestone` | 四段：范围评估 / 理解阐释 / 拆分路线图 / 范围演进记录（即 `milestone-schema.md §5` 的四段） |
| `iteration` | 两段：要解决什么 / 暂缓原因 |
| `undecided` | 两段：想做什么 / 卡在哪 |

**`iteration` 档为什么只要两段**：迭代真开起来的第一件事就是 P1 重写 `.ai/CONCEPT.md`，草稿里写再详细的拆分路线图也会被覆盖，属于白写。留「要解决什么」是为了将来自己看得懂，留「暂缓原因」是为了知道什么时候该捡回来。

**`undecided` 档的「卡在哪」是强制的**，而且必须**点名一个具体缺口**——缺哪份数据、缺哪个决定、缺哪个前置件。「还没想好」「再看看」这类话不算数。这是本档的出区压力：写不出卡在哪，说明这条根本不配占孵化区一个位置，应当直接撤回（§3.4）。

### 2.4 改档

档位允许改，升降都行。改档必须同时做两件事：

1. 把新档要求的段落补齐（升档要补，降档要把不再要求的段落留着或删掉都可以，但要求的段落必须在）。
2. 在草稿里记一行改档原因，写明从哪档改到哪档、因为知道了什么。

只改 `规模:` 那一行、不补段落，是非法状态。

## 3. 第三层 · 执行分流

### 3.1 三条出口，封闭

一份孵化区草稿只有三种下场，没有第四种：

| 出口 | 允许的规模档 | 前置条件 | 动作真源 |
|---|---|---|---|
| 提升为里程碑 | 只有 `milestone` | 当前没有 active 里程碑 | `20_Workflow_Lifecycle/milestone-schema.md §7.1` |
| 开为迭代 | 只有 `iteration` | 当前没有 active 迭代 | `20_Workflow_Lifecycle/iteration-schema.md §5.1` |
| 撤回 | 任意档 | 无 | 本文件 §3.4 |

`undecided` 档**不得直接出区**，必须先按 §2.4 定档到 `milestone` 或 `iteration`，才能走前两条；实在定不了档就走撤回。这是 `undecided` 的第二道出区压力。

**ideation（探索）不是出口**。探索是孵化的手段——用它把一个方向想清楚、把「卡在哪」填实——探完了这份草稿仍然要走上面三条之一。不得把「已完成 ideation」当作一种终局状态。

### 3.2 两侧原子

无论走哪条出口，**删草稿文件和删索引行必须一起做**，中间不留只删了一侧的状态。

现成的兜底是审计里的 `milestones.backlog_set` 检查：`.ai/MILESTONES.md` 待办区的索引行集合，必须与 `.ai/milestone-backlog/` 目录下的文件集合完全相等。漏删任一侧，下一次 `scripts/audit-project-state.py` 就会红。

### 3.3 提升 / 开工的前置为什么是「没有 active」

butler 同时只跑一个 active 里程碑、一个 active 迭代。前置条件不满足时，正确动作是**等**，不是把草稿删掉硬开——草稿留在孵化区不占任何编号，等着不花成本。

### 3.4 撤回

撤回是「决定不做了」，不是「暂时不做」（暂时不做就是继续待在孵化区）。撤回要做三件事：

1. 删草稿文件 + 删索引行（§3.2 的两侧原子）。
2. 在 `.ai/MILESTONE.md §5.4`（范围演进记录）追加一行，写明撤回了哪个候办键、因为什么。
3. 若该草稿源自某条闪念，按 §3.5 回写闪念行。

### 3.5 回写闪念

若草稿的源头是一条闪念（闪念行状态为 `incubated`、去向指着这份草稿），出区时必须回写那一行：

| 出口 | 闪念行改成 |
|---|---|
| 提升为里程碑 | 状态 `done`，去向填里程碑号 |
| 开为迭代 | 状态 `done`，去向填迭代号 |
| 撤回 | 状态 `dropped`，去向填一句话原因 |

草稿若不是从闪念来的（比如讨论中直接落的候办），没有闪念行要回写，此步跳过。

## 4. 三层之间不重复的东西

- 闪念口只存一句话和去向，**不存**论证、不存范围、不存路线图。要展开就进孵化区。
- 孵化区只存「值不值得做」的判断材料，**不存**执行计划。执行计划是迭代 P3 的 `.ai/TECH_PLAN.md`。
- 执行分流不产生自己的状态，它只是把草稿交给既有的里程碑 / 迭代生命周期，**不建**第三套状态机。

## 5. 本契约管不到的地方

- `/butler:inbox` 的命令、子命令、参数与回执格式：归动作层 `intake-workflow.md`，本文件不定。
- 孵化区目录改名：归 MILE-0016 R9，届时本文件同批更新。
- 本契约的任何一条都**没有机器检查兜底**。三层结构写得对不对、`undecided` 的出区压力管不管用，R7 已经真跑通「记闪念 → 孵化」一段，其余动作路径的真实使用要等后续迭代自然发生。
