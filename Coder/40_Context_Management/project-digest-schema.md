# project-digest-schema（.ai/PROJECT.md 格式契约）

本文件是 `.ai/PROJECT.md` 的唯一结构契约。何时前滚维护由 `iteration-schema.md §5.5` / `milestone-schema.md §7.4` 的收口步负责；冷启动如何读由 `context-persistence.md §6` 负责。

## 1. 定位

`.ai/PROJECT.md` 是项目的**常驻全貌摘要**，回答"这系统现在整体是什么、为何如此、有哪些长期约束与欠债"。它是**状态取向**（所有迭代变更的积分），与变更流取向的 `ITERATIONS.md`、瞬时取向的 `02_SESSION_HANDOFF.md` 互补。

冷启动时它是**第一读**：先读 PROJECT.md 抓住系统全貌与现状，再读 ITERATIONS 看时间线、读 handoff 看断点，最后按指针钻代码。没有它，新会话只能从一堆迭代 delta 倒推全貌（管中窥豹）。

### 四产物边界（不得越位）

| 产物 | 取向 | 答什么 |
|---|---|---|
| `.ai/PROJECT.md` | 状态（积分） | 系统现在整体是什么、为何如此 |
| `.ai/ITERATIONS.md` | 变更流（delta） | 一步步怎么走到今天（迭代时间线） |
| `.ai/02_SESSION_HANDOFF.md` | 瞬时 | 现在卡在哪个断点 |
| `.ai/MILESTONE.md` | 版本范围 | 当前大版本圈了什么、拆成哪些迭代 |

## 2. 约束

- 总长度 ≤ 1500 tokens（约 handoff 的 3 倍；它是摘要不是百科）。
- 状态取向：只写"现在仍然成立的整体事实"，不写变更历史（归 ITERATIONS / deliveries）、不写当前任务断点（归 handoff）。
- 指针化：深内容（完整架构、实现、决策始末）指向真源（代码 / `deliveries/` / `architecture-overview` / 关键 schema），不在本文件内嵌。
- overwrite 维护：前滚时覆写当前结论，不在文末追加历史层。

## 3. 必填字段

| 字段 | 说明 |
|---|---|
| **目的** | 这系统是什么、给谁解决什么问题。1-3 句。 |
| **架构与模块地图** | 主要组成部分 + 各自职责 + 指向其真源的指针。 |
| **关键长期决策与不变量** | 跨迭代仍成立的核心决策（含"为什么"）与必须守住的不变量；能防止新会话做出相反决策的那些。 |
| **现行约束** | 长期生效的边界 / 纪律（技术、流程、业务）。 |
| **已知长期欠债** | 跨迭代未还、需新会话知晓以免重复踩坑或误判的债。 |
| **指针** | 深内容真源路径（代码入口 / deliveries / architecture-overview / 关键 schema / 台账）。 |

## 4. 模板骨架

H2 顺序与 §3 表格一致，不得调整：

````markdown
# Project Digest

## 目的

<!-- 这系统是什么、给谁解决什么。1-3 句。 -->

## 架构与模块地图

<!-- 主要组成部分 + 职责 + 指针。一行一个部分。 -->

## 关键长期决策与不变量

<!-- 跨迭代仍成立的核心决策（带"为什么"）与不变量。能防止新会话做出相反决策的那些。 -->

## 现行约束

<!-- 长期生效的边界 / 纪律。 -->

## 已知长期欠债

<!-- 跨迭代未还的债，防新会话重复踩坑。无则写"无"。 -->

## 指针

<!-- 深内容真源路径：代码入口 / deliveries / architecture-overview / 关键 schema / 台账。 -->
````

模板规则：

- H1 固定 `# Project Digest`，不得改写。
- 6 个 H2 顺序固定、不得增删；落盘时占位注释必须替换为实际内容。
- 某字段本轮无内容写"无"，不省段。

## 5. 维护：收口前滚

- **触发**：每次迭代 / 里程碑收口（`iteration-schema.md §5.5` / `milestone-schema.md §7.4` 的收口步）。
- **判据**：本迭代有没有改变某条**长期事实**（架构、不变量、现行约束、长期欠债）？有则前滚对应字段、无则不动。
- **成本**：多数迭代只动 0-2 行或完全不动；PROJECT.md 不是每收口必重写，避免维护膨胀（合 `maintenance-boundaries.md`）。
- **形态**：覆写当前结论，不堆历史层。

## 6. 写作口径

- 字段正文讲人话、不啰嗦、分层渐进展开，口径以 `artifact-style.md` 为准（单一来源，不在此重复）。
- 状态取向自检：每写一条先问"这是现在仍成立的整体事实，还是一次变更 / 一个断点？"——后两者分别归 ITERATIONS / handoff，不写进本文件。

## 7. 与其他规则的关系

- 本文件负责 `.ai/PROJECT.md` 的格式契约。
- `context-persistence.md` 负责冷启动读序与状态外化。
- `iteration-schema.md` / `milestone-schema.md` 的收口步负责前滚触发。
- `mcv-deployment.md` 负责部署时创建种子。
- `handoff-spec.md`（`02_SESSION_HANDOFF.md`）是瞬时断点入口，与本文件互补、不重叠。
