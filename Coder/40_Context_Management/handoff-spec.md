# 02_SESSION_HANDOFF.md 格式契约

本文件是 `02_SESSION_HANDOFF.md` 的唯一结构契约。何时触发蒸馏、如何维护状态文件，由 `context-persistence.md` 负责。

## 1. 定位

`02_SESSION_HANDOFF.md` 是冷启动**入口**，不是自足包。它的目标是让新会话能**定向、开工、不踩雷**。完整 context 由状态文件承载，handoff 通过指针引用。

其中项目的**状态全貌**由项目全貌产物承载（两态：`.ai/project/` 知识文件夹，或未迁移暂态的单文件 `.ai/PROJECT.md`；格式见 `project-digest-schema.md`）：handoff 给"此刻断点"、全貌产物给"系统整体是什么"，二者互补不重叠，handoff 的状态指针可引用它。冷启动完整读序（含两态第一读）见 `context-persistence.md §6`。

## 2. 约束

- 总长度 ≤ 500 Tokens
- 只服务跨会话恢复，不承担对人交付总结职责

## 3. 必填字段

| 字段 | 说明 |
|---|---|
| **任务断点** | 当前正在进行的 AC 条目与阶段 |
| **关键决策摘要** | 已确定的核心决策（接口契约、被否方案及理由），不需要全部，只需要防止新会话做出相反决策的那些 |
| **环境脏点** | 未提交的代码、临时关闭的 Lint 规则、待安装的依赖；完整路径 P5 若已有自动道证据热区，给出 `.ai/verification-evidence/` 指针，不复制测试结论或日志 |
| **已知风险** | 已发现但决定延后处理的问题，防止新会话重复踩坑 |
| **唤醒指令** | 新 Session 启动时 AI 应执行的第一条命令 |
| **状态指针** | 完整状态文件的路径（如 `.ai/task-state.md`），供新会话按需深入读取 |

## 4. 模板骨架

新会话冷启动入口的固定结构如下，H2 顺序与 §3 表格一致，不得调整：

````markdown
# Session Handoff

## 任务断点

<!-- 当前正在进行的 AC 条目与阶段（P1/P2/P3/P4/P5）。一句话定位。 -->

## 关键决策摘要

<!-- 能"防止新会话做出相反决策"的核心结论：已确认的接口契约、被否方案及理由。不必穷举。 -->

## 环境脏点

<!-- 未提交代码、临时关闭的 lint 规则、待安装依赖、未推送的 tag / branch。 -->

## 已知风险

<!-- 已发现但决定延后处理的问题，防止新会话重复踩坑。 -->

## 唤醒指令

<!-- 新 Session 启动后 AI 应执行的第一条命令或读取动作。 -->

## 状态指针

<!-- 完整状态文件路径（如 `.ai/task-state.md`）。简单任务若 handoff 已自足，可省略本节，详见 `context-persistence.md` §6。 -->
````

模板规则：

- H1 固定为 `# Session Handoff`，不得改写
- 6 个 H2 顺序固定，不得增删；"状态指针"在简单任务中可省，其余 5 项必须出现
- 每个 H2 下的占位注释（`<!-- ... -->`）落盘时必须替换为实际内容，不得保留

## 5. 生成流程

AI 执行冷启动蒸馏时，必须按以下步骤序列写出 `.ai/02_SESSION_HANDOFF.md`，不得跳步：

1. **来源确认**：按优先级选定蒸馏来源——`.ai/task-state.md` > P1-P3 产物链（`CONCEPT.md` / `AC_LIST.md` / `TECH_PLAN.md`） > 当前对话上下文。若来源缺失或陈旧，先按 `context-persistence.md` §5 执行阶段结晶，再蒸馏。
2. **字段映射**：按 §3 表格顺序逐字段填写。每填一项前先自问"这条信息能否防止新会话做出相反决策或重复踩坑"，否则不写。
3. **长度自检**：总长度 ≤ 500 tokens。超出时优先压缩"关键决策摘要"与"已知风险"的措辞，不得通过删减字段满足限额。
4. **完整性自检**：H1 与 §3 必填字段齐全；除"状态指针"在简单任务中可省外，其余字段不得为空或仅留占位注释。
5. **落盘**：写入 `.ai/02_SESSION_HANDOFF.md`，覆盖式更新，不保留历史版本。

反模式（蒸馏时禁止的产出形态）：

- 不得写思考过程、失败尝试与已废弃方案
- 不得复制大段代码、终端日志或文件 diff
- 不得罗列"已完成清单"——属于 `task-state.md` 的阶段结晶职责
- 不得把 handoff 写成对人交付总结——属于 `delivery-summary.md` 与 `deliveries/` 的职责
