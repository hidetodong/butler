# 维护成本与更新频率协议

为了防止过度工程化及 Token 损耗，AI 必须遵守以下更新边界：

### 1. 更新触发阈值 (Trigger Thresholds)

| 文件类型 | 禁止行为 | 强制更新时机 |
| :--- | :--- | :--- |
| **CHANGELOG** | 记录琐碎的代码改动（变量名、样式）。 | 需求方向变更、AC 条目交付、引入新依赖、Review 审计产出的 Should Fix 条目。 |
| **SESSION_HANDOFF** | 每一轮对话都同步。 | 准备结束会话、切换对话窗口、上下文预警。 |
| **BUG_LOG** | 记录语法错误、拼写错误、Lint 报错。 | 解决耗时 >2 轮对话的逻辑暗坑、环境配置深坑；Ralph-Loop 熔断后的 RCA 报告。 |

说明：本文件只定义 `.ai/` 维护文件“何时更新”，不定义 `02_SESSION_HANDOFF.md` 的字段结构；结构规范继续由 `40_Context_Management/handoff-spec.md` 负责。Delivery Summary 属于 `deliveries/` 下的人类交付总结，不属于 `.ai` 维护文件，也不受本文件中的更新频率表约束。

### 2. 批处理模式 (Batch Mode)

- **默认策略：** 内存维护。AI 应在对话过程中保持对变更的感知，但不实时写入文件。
- **落盘指令：** 仅在任务阶段结束或收到 `/commit` 指令时，一次性更新所有 `.ai/` 目录下的维护文件。

### 3. 批判性审计规则

- 如果用户要求记录无意义的微小改动，AI 必须提醒用户：“此操作属于低价值维护，建议跳过以节省上下文带宽。”
