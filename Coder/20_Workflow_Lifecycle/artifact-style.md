# Artifact Style

## 1. 目标与定位

- 四个 schema（`concept-schema` / `acceptance-schema` / `tech-plan-schema` / `verify-schema`）规定四件套**填哪些字段**；本口径规定**字段里的话怎么写**：讲人话、不啰嗦。
- 本口径与字段结构各管各的：**不得**增删或改动任何字段，只约束往字段里写的内容。
- 为什么需要：四件套首先是给 AI 续接用的，但人也会读、会复盘。没有书写纪律时，正文会越积越多内部黑话、把一件事重述好几遍，读起来像内部机器日志、不像给人看的东西——这正是迭代化本想消除的"产物膨胀"在内容层的翻版。
- 与对话层分工：`00_System_Prompt/presentation-protocol.md` 管对话框里怎么把方案说清楚，`delivery-summary.md §8` 管 P5 交付摘要的散文口吻；**本口径管产物文件层**（四件套写进文件的内容）。三者分层，互不覆盖。

## 2. 讲人话（反黑话）

- 字段正文**必须**让一个不懂 butler 内部机制的人也能读懂。
- 能用大白话说清的，**不得**用内部黑话当简写。典型反面词（不限于）：`零改动护栏`、`护栏`、`正交`、`高注意力区`、`BLUF`、`fresh-context 子 agent`。
- 判据——**这个词是在指代任务的真实对象，还是只是偷懒的简写？**
  - 是真实对象（这次任务改的就是它，如 `schema`、`rule-card`、`ack-frozen`）：**应**照常用它的名字，但顺带一句话说清它是什么，不靠读者自己懂。
  - 只是简写（一个大白话词就能替代）：**必须**换成大白话。
- 结构锚点不算黑话、必须保留：字段名（`Goal` / `AC Status`…）、AC 编号、文件路径——它们是跨阶段读取的锚点，不是给人读的散文。

## 3. 反啰嗦（反注水）

- **必须**一律用 bullet，不写大段铺陈；一条能说清的就一条，一句能说清的就一句。
- 嵌套**不得**超过 2 层。
- **不得**复述模板里的提示语（如把 `# Goal 本次任务要解决什么问题` 原样抄进正文），也**不得**把上一阶段产物已写过的内容再抄一遍——引用即可（如"目标见 CONCEPT，不重述"）。
- 宁缺毋滥：某字段本轮没有内容，写"无"或"N/A"，**不得**为凑字数硬编。
- 分流行的升级信号**只列名**（如"多文件改动、设计取舍"），**不得**给每条加括号小作文。
- VERIFY 的 AC 回填用紧凑式 `[x] ACn ✓ <一句话证据>`，**不得**把 AC 原文整条重抄再展开成一段。

## 4. 渐进展开与分层（同时对人和 AI 友好）

「对人友好」和「对 AI 友好」不是取舍、是同一件事：让人读着累的（信息糊成一团、关系藏着不挑明、引用默认你懂），同样让 AI 干得不稳。唯一偏差是 AI 比人更需要精确引用（路径 / 符号 / payload）——用分层吸收掉，不靠删精度来讨好人。

把产物当**一份文档、多种阅读深度**来写：

1. **顶部先放一句话意图（gist）**：用 2-3 句白话说清"干嘛 + 为什么"，让冷读者（人或 fresh-context 的 AI）先抓住意图再看细节。**不得**让读者自己从背景 + 标题 + 一堆目标里拼意图。
2. **一行一个意思**：**不得**把多步 / 多约束用箭头链（`A → B → C`）或括号串塞进一行；多步就列成有序步骤，每步一个干净锚点。
3. **承重引用首次出现给一句话解释**：被反复指代的关键符号 / 文件 / 表，第一次出现时一句话说清它是什么——不止 butler 黑话，也含**项目领域**的（如 `getCaptureText`、`captures` 表）；别假设读者脑子里已装着代码。
4. **不串层**：散文层就纯散文（**不**夹密集符号），精度层就用干净引用列表（路径 / 符号 / payload 各占一行）。串在一起两头不讨好——精度打断叙述、关系又藏进密集行里。
5. **不啰嗦 ≠ 极限压缩**：§3 的"反啰嗦"针对**填充与重述**，不是让你把关系压没、把台阶撤掉。该展开的关系要展开、该铺的 gist 要铺；省的是冗余，不是确定性。

分层骨架样例（CONCEPT，可照抄）：

```md
> 分流: 完整 | 命中升级信号: 多文件改动、契约变更 | YYYY-MM-DD

# 一句话
把 X 和 Y 彻底解耦：以前 X 要跨进去用 someFn 读数据，现在改成 Y 建任务时
就把数据写进任务里、X 只读任务。顺手删掉已搬走、现在没用的旧代码。

# Goal
- G1 …（一行一个意思）
- G2 …

# 影响范围（执行依据，精度单独成层）
- 改 tools/x/src/db.ts：删 someFn
- Payload: {a, b} → {a, b, data}
```

反例（别这样）：把 `重建镜像 → 服务器 pull → 切换（守单消费者 + --remove-orphans）→ 端到端验证等价` 全塞进一行——人看着累、AI 执行到中间没干净锚点；应拆成有序步骤。

## 5. before / after 对照（可照抄）

取自本仓真实历史产物，左边啰嗦 / 黑话，右边讲人话。

分流行（CONCEPT 顶部）——只列名，不加括号小作文：

```md
before
> 分流: 完整 | 命中升级信号: 契约变更（新增对话层呈现行为契约，贯穿各阶段输出）、跨模块影响（影响 P1-P3 所有方案输出 + 须与 §8 划清边界）、多文件改动（≥5）、设计取舍（落点：新建文件 vs 扩 identity） | 2026-06-22

after
> 分流: 完整 | 命中升级信号: 契约变更、跨模块影响、多文件改动、设计取舍 | 2026-06-22
```

AC 回填（VERIFY）——紧凑式，黑话换大白话：

```md
before
- [x] AC17: 零改动护栏——git status 改动名单不含 VERSION/CHANGELOG/四 schema/hooks/…；上述文件 git diff --stat 零行变更。

after
- [x] AC17 ✓ 不该动的文件确实都没碰（版本号、改动记录、四件套模板等逐个核对过）。
```

## 6. 边界

- 不改字段结构——四件套字段以四个 schema 为准。
- 不管对话层——对话呈现以 `presentation-protocol.md`、交付摘要以 `delivery-summary.md §8` 为准。
- 书写质量不做 hook 机械门禁——它不是封闭枚举那种可机械校验的项，靠本规则 + 收口前自检兜底。

## 7. 收口前自检

- 收口前**应**扫一遍本迭代四件套：命中第 2 节反面词、或第 3 节的整段重述 / 超 2 层嵌套，就地改掉再归档。
