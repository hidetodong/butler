# Presentation Protocol

## 1. 目标

让 AI 在对话框里呈现方案时**结构固定、易读**，消除两类毛病：标号忽 `ABC` 忽 `123` 忽 `a)` 的随机切换，以及开场堆砌大段概念。

本协议只约束**对话层呈现形式**，不改变任何产物文件的内容与字段（呈现层与产物层正交）。

## 2. 适用范围

**适用**（必须套用本协议）：

- P1-P3 的方案提案、技术取舍说明。
- 多方案 / 多选项的对比与推荐。
- 阶段性分析、影响面说明等较长输出。

**不适用**（豁免，不强行套骨架）：

- 简短问答、单点确认、纯澄清提问。
- 进度汇报、状态播报。
- P5 完整交付后的对话摘要——走 `20_Workflow_Lifecycle/delivery-summary.md` §8 的散文口径（见 §9）。

## 3. 结论先行 (BLUF)

- **必须**在开头先给一句话结论 / 建议，再展开依据。
- **不得**用大段背景或概念铺垫开场；概念解释一律后置或精简（见 §6）。
- 读者应在第一行就知道"结论是什么、你建议怎么做"。

## 4. 统一标号（可执行口径）

同一次输出内标号体系必须统一，按下列固定口径：

- 无序要点**必须**用 `-`。
- 有序步骤 / 排序项**必须**用 `1. 2. 3.`。
- **不得**用字母标号（`A)` / `a)` / `A.` / `a.`）作为列表层级。
- 多级嵌套**必须**用缩进的 `-`，不得在同一输出里混用多套标号体系。

## 5. 选项表格化

- 当对比 **≥2 个**方案 / 选项时，**必须**用表格，不得用并列长段落堆叠。
- 建议固定列：`方案 / 选项 | 优势 | 代价·取舍`，可按场景增列（如「影响面」「适用场景」）。
- 单一方案或无需对比时不强制表格，按 §3 / §4 呈现即可。

## 6. 概念后置与收尾下一步

- **决策与建议前置**，必要的概念 / 背景解释精简后置，不与结论抢开场。
- 方案输出**结尾应给明确的「建议 / 下一步」**（如"建议选 B → 下一步出 TECH_PLAN"、"需要你 ACK"）。

## 7. 对话也说人话（三条硬标准）

对话层的方案 / 分析 / 选项等较长输出，除了 §3–§6 的结构，还**必须**守「说人话三条硬标准」——术语先解释、比喻要落地、别让英文 / 变量裸奔。

- 三条的完整定义与判据是**跨对话与文档的通则**，真源在 `20_Workflow_Lifecycle/artifact-style.md §2`；本协议只声明对话层同受约束，**不重述定义**（单一来源，避免对话一套、文档一套地漂移）。
- **发长文前自检**：在对话框里发一段较长输出前，扫一遍三条——有没有术语没解释、比喻没落地、英文 / 变量裸奔；命中就地改掉再发。
- 结构锚点（字段名 / AC 编号 / 路径）与 §3–§6 一样保留、不受影响。

## 8. 弹性条款

- 本协议是**默认固定 + 弹性**：默认按 §3-§7 套骨架，但 §2 豁免清单内的输出**不强行套**。
- 内容极短或一句话能说清时，不得为了套骨架而注水；结构服务于易读，不是形式负担。
- 把握不准是否"较长输出"时，倾向轻量——宁可简洁，不要僵硬。

## 9. 与 §8 交付摘要的边界

二者按**场景分工**、互不覆盖：

- `delivery-summary.md` §8 管 **P5 最终交付摘要**：3-6 句散文、禁编号小节。
- 本协议管**过程中**的方案 / 选项 / 分析呈现：结构化、统一标号、表格。

即"过程结构化、交付散文化"。不得用本协议的表格骨架去写 P5 交付摘要，也不得用 §8 的散文口径去敷衍过程方案呈现。

### 标准骨架样例（可直接套用）

````md
结论：建议方案 B（兼容性最好、改动可控）。

关键点
- 改 3 个文件，影响面不跨模块
- 不动现有契约

可选方案
| 方案 | 优势   | 代价        |
|------|--------|------------|
| A    | 实现快 | 破坏向后兼容 |
| B    | 稳     | 多一层封装  |

建议：选 B → 下一步出 TECH_PLAN。
````

本样例自身遵守 §3-§7：结论先行、`-` 统一标号、选项用表格、结尾给下一步、说人话（无裸奔黑话）。
