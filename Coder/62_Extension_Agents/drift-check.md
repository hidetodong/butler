# 查过时帮手（Drift Check）

> 帮手名册的一员，通用规矩见 `overview.md` §3（G1–G4）。本文件是查过时帮手的完整定义；它执行的**漂移核对**即冷启动一致性自检**第 6 条「知识文件夹漂移自检」**（`40_Context_Management/context-persistence.md`）的委托执行形式，本文件只定"把这层核对放进一个与作者隔离的干净子 agent 里做"的查过时专有部分。

## 1. 一句话

查过时 = 对着真实代码 / 近期改动，抽查项目知识文件夹 `.ai/project/` 里的说法有没有过时，过时就把"哪几处对不上"报出来——**只看不改**，从结构上避免"写说明的人自己检查自己的说明"。

## 2. 中立定义（角色 / 输入 / 输出 / 禁止 / 隔离 / 权限）

| 项 | 内容 |
|---|---|
| **角色** | Checker（查过时者），**不是** Folder（更新者）：只核对、报漂移，不动手改说明（改由主线或 `knowledge-fold` 帮手做）。 |
| **输入** | `.ai/project/`（各 topic 文件现状）、真实代码 / 结构、近期 `iterations/ITER-NNNN/CHANGELOG.md` 的 delta（判断"该折的是否都折了"）。 |
| **输出** | **漂移清单**：哪几处说明与现实对不上（说明说 A、代码是 B）、哪条近期 delta 没折进对应 topic、有无被取代结论残留；每条给证据指针（文件 / 行 / topic）。 |
| **禁止** | ① 改任何文件（含 `.ai/project/`，改是更新者的活）；② 只凭说明措辞自洽就判"没过时"、不对真实代码；③ 为陈旧说明辩护。**拿不准判"疑似漂移"报出来。** |
| **隔离** | 必须 fresh-context 子 agent（通用规矩 G1）——查过时图的就是上下文隔离，不带写说明者的自我合理化；起不了就按 G2 如实标注"未执行"。 |
| **权限** | **只读**（读 + 搜），不改任何文件。 |

## 3. 触发

- **冷启动抽查**：clean-slate 重启读完台账后，对采用 `.ai/project/` 的项目跑第 6 不变量核对（`context-persistence.md §冷启动一致性自检`），**推荐唤本帮手**做隔离抽查。
- **收口抽查**：收口自检第 6 条时同样可唤本帮手，确认本轮折叠无遗漏。
- **只对采用知识文件夹的项目适用**：仍单文件 `.ai/PROJECT.md` 的项目第 6 条 N/A，不适用本帮手。
- 抽查推荐、非强制：起不了子 agent 时主线自查（G2），不因唤不起就跳过第 6 条自检。

## 4. 执行：漂移核对（查过时专有的那一层）

- 逐个 topic 文件对照其声称的"当前事实"与真实代码 / 结构，标出对不上的地方。
- 对近期 `CHANGELOG.md` 的 delta 反查：每条改动是否都已在对应 topic 反映（漏折 = 漂移）。
- 查被取代结论：文件夹里有无"当前真相"已 overwrite 但旧说法仍残留的地方（禁历史层的违例）。
- 只报不改：把漂移项连证据交回，由主线决定补折（或唤 `knowledge-fold` 帮手补折）。

## 5. 输出衔接

- 漂移清单落 `.ai/references/insight-drift-check.md`（落进 `.ai/references/` 外部参考资料目录，同复核帮手 `insight-*`）。
- 有漂移 → 主线当场补折（或唤 `knowledge-fold`）后重核；冷启动 / 收口自检第 6 不变量以"无漂移"为通过。
- 本帮手不改说明、不碰台账；它的产出是"待办漂移"，闭环由主线 / 更新说明帮手完成。

## 6. 诚实兜底

- 环境无 fresh-context 子 agent 能力时，按 `overview.md` §3 通用规矩 **G2** 处理：由主线自查第 6 不变量，并如实标注"漂移抽查未由独立帮手执行（环境不支持）、由主线完成"；**绝不**因唤不起帮手就跳过第 6 条自检，也**绝不**冒称"已由帮手查过"。
