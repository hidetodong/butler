# 帮手名册（Butler Agents）

## 1. 帮手是什么

"帮手"是 butler 为完成某项专门工作、**临时另起的一个干净子 agent**（fresh-context sub-agent，指一个不带当前对话历史的新上下文）——它拿到明确输入、按一份中立定义干完一件事、把结果还回来。

- 帮手 = **一份定义资料**：说清它是谁、给它什么、还你什么、能碰什么。定义放在本目录（butler 规则里），**用时才读**。
- 用法：要派某帮手时，读它的定义、临时起一个干净子 agent 执行——跟现有 `/review`（复核）一模一样。
- **不下发到项目**：帮手定义不拷进任何目标项目；目标项目用时按 butler 规则读定义即可，避免每个项目存副本、日久漂移。

为什么非"干净子 agent"不可、不用同对话里的技能（Skill，指载入当前对话运行的指令包）：Skill 在**同一个对话**里跑，给不了"干净新脑子"；检查类帮手（复核 / 查过时）图的就是**上下文隔离**——另起的子 agent 看不到主线的推理链，才不会自己给自己打分、自己糊弄自己。

## 3. 通用规矩（所有帮手都适用 · 唯一真源）

G1–G4 是**所有帮手的共同底线**，写在此处当唯一出处；各帮手定义与相关规则（`60_Extension_CodeReview` / `65_Extension_Dangerous` / `20_Workflow_Lifecycle/verify-schema` 等）**引用**它、不再各写一遍。

- **G1 干净上下文**：检查类帮手（复核 / 查过时）**必须**另起干净子 agent 执行，不带主线（作者）的推理链。单模型环境下，"独立"不来自更强的模型，而来自**上下文隔离**——只喂规格与产物、不喂作者的推理链与自我合理化，让它拿规格当尺子核对。这才是结构性的"验证者 ≠ 实现者"。
- **G2 叫不起来就如实说**：若运行环境**起不了干净子 agent**，**不得**退回主线自评再冒称"已独立复核 / 已折叠 / 已查过"。必须如实标注"这步没做（环境不支持）"、当作风险摆出来（落到 `Remaining Risks`），由用户决定是否手动另起 agent。**绝不假装做过。**
- **G3 权限靠约定 + 如实说**：每个帮手定义里写清它能碰什么（复核只读；更新说明只准写 `.ai/project/`）。本轮权限是**契约约定**，不追工具层硬拦（可选增强、留后续）；约定 + G2 诚实兜底即当前防线。
- **G4 帮手 = 中立定义资料**：每个帮手是一份大白话中立定义（角色 / 输入 / 输出 / 禁止 / 隔离 / 权限），跨模型跨宿主通用；butler 用时读、临时起子 agent，不往项目发文件。

## 4. 加载方式

- 本总述与各帮手明细**触发式加载**：只在需要派帮手时读，**不进冷启动必读**（同全体扩展模块，不占冷启动预算）。
- 主线要"知道有哪些帮手可用"，靠 `Coder/README.md` 目录说明里的一行指针即可；真要派某帮手时，才读它的明细定义。

## 5. 维护

- 加 / 删 / 改帮手：在**同一次编辑**里一起改本总述（名册表）+ 对应帮手定义文件（co-edit），保持一致。
- 冷启动一致性自检兜底：名册每个帮手 ↔ 有对应定义文件 ↔ 权限声明一致。
- 这套"总述 + 分文件 + 登记"结构是 MILE-0003 知识文件夹（`.ai/project/`）的一次内部预演——先在三个帮手上跑顺，大文件夹照抄同款结构。

## 6. 生态说明（对外措辞校准）

帮手定义是 butler 自己的中立格式，不依赖某家工具。相关事实按此表述、避免以讹传讹：

- 没有哪家的"子 agent 定义格式"是全行业统一标准。`.claude/agents/`（Claude Code 存放子 agent 定义的目录）是 **Claude Code 独有**，别家（Cursor / Copilot / Codex）不读。
- Anthropic 真正跨家的是 **MCP**（Model Context Protocol，给 AI 配外部工具的协议）和 **Agent Skills**（`SKILL.md` 技能包，截至 2026 上半年 30+ 家工具采纳）。
- **AGENTS.md** 是 **Sourcegraph 的 Amp 团队发起**（当初是单数 `AGENT.md`）、后经 OpenAI 的 Codex 推广成复数带火的**仓库级说明**规范——**不是**"帮手定义"格式。
