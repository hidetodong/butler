# Butler 偏好探针引擎

> ⚠️ **实验性能力**。本模块在长期工作中采集用户的设计与取舍倾向、蒸馏成跨项目通识，并在**有监督**场景把它作为提议参考。它的价值与风险都来自"让模型带着对你过往选择的推测去提议"，必须严守 §3 安全底线。

## 1. 身份与目标

偏好探针是 butler 的一条**偏好蒸馏回路**:`采集 → 蒸馏 → 反哺`,拆成两层:

- **数据回路(采集 + 蒸馏)**:经一次性同意后**默认常驻**的只读观察者——观察你的高信号决策、在收口边界蒸馏成画像、保持画像温热。
- **影响回路(反哺)**:**opt-in**——仅在**有监督工作**中把画像作为提议参考。

目标产物是一份**被多项目背书、跨项目可迁移的通识**:回答"这个人怎么设计、怎么取舍"。

核心定位:**探针是挂在迭代旁边的只读观察者 + 外置账本,不在产物链里,坏了也不连累迭代**(隔离纪律见 §8)。一条贯穿全文的原则:**偏好是人在回路的产物——只学你亲手做的选择,只在你在场时影响提议**。

## 2. 两层结构与开关

### 2.1 数据回路（采集 + 蒸馏）:默认常驻

经一次性同意(§2.4)后,在 **butler 托管项目**(含 `.ai/`)默认运行:采集你的高信号决策、在收口边界蒸馏成画像。全程**只读外置存储、从不写 `.ai/`、不被 hook 拦截**。蒸馏默认开,使 `profile.md` **一直保持温热**——这样一旦开启反哺,画像当场可用,不必再从零攒。

默认运行**受项目级抑制开关约束**(§2.5):本项目 `.ai/local-constraints.md`「Butler 功能开关」`preference: off` 时,**不在本项目**采集/蒸馏/反哺(其他项目不受影响)。

### 2.2 影响回路（反哺）:opt-in

**默认关**。`/preference reback on` 开启后,模型在**有监督**决策(P2/P3 提案、AskUserQuestion 选项排序)时把画像作为参考。**仅作用于有监督工作**,绝不参与 `/dangerous` 无人值守自治(见 §7、§3-3、§9)。

### 2.3 命令

| 命令 | 含义 |
|---|---|
| `/preference on` / `off` | **隐私总开关**:off = 停采集 + 蒸馏 + 反哺、保留已存数据;on = 恢复默认(数据回路开、反哺关) |
| `/preference reback on` / `off` | **影响回路**开关,默认关 |
| `/preference distill` | 手动触发一次蒸馏 + 维护(见 §6) |

开关变更**必须**在当回合对话层显式回声当前状态。`off` 期间本引擎全部规则不生效。

### 2.4 同意协议（方案 A·先问后看）

数据回路虽默认常驻,但**首次必须取得一次性全局同意**:

- **触发**:在任一 butler 托管项目**首次**命中可采集决策、且 `$PREF/config.md` 无 `consent` 记录时,**全局问一次**。披露三点:记什么(**仅决策倾向的抽象,不含业务数据/密钥/代码**)、存哪(外置 `$PREF`,与仓库解耦)、怎么关(`/preference off`)。
- **同意** → 写 `consent: granted, YYYY-MM-DD` 到 `config.md`,此后**全局常驻、不再询问**,并按 §4.1 惰性自举。
- **拒绝** → 写 `consent: declined`,采集保持关、不再骚扰,直到用户主动 `/preference on`。
- **同意前不写任何信号**,探针完全惰性——先问,后看。

### 2.5 项目级抑制开关（per-project）

全局 consent(§2.4)决定"**能不能**采集",项目级开关决定"**这个项目要不要**采集"。后者持久在本项目 `.ai/local-constraints.md`「Butler 功能开关」段的 `preference: on|off`(默认 `on`):

- **生效优先级(三层全放行才在本项目运行)**:全局 `/preference off`(§2.3 隐私总开关)> 外置 `$PREF` `consent`(§2.4)> 项目 `preference` 开关。即:全局未 off **且** consent=granted **且** 本项目 `preference ≠ off`,三者全真,探针才在本项目采集/蒸馏/反哺。
- `preference: off` **只抑制本项目**:不改全局 consent、不动 `$PREF` 数据、不影响其他项目;本项目 `signals/<project>.md` 不再新增条目。缺该字段 = 视为 `on`(不抑制)。
- **非双真源**:项目开关与全局 consent 分管不同层面(全局=能不能、项目=要不要),故不构成第二真源。consent/signals/profile 的真源仍**唯一**在外置 `$PREF`(§4),项目开关**不双写**外置状态、不是其镜像。
- **低风险、无需声明**:不同于 `/dangerous` 的 announce-on-read,preference 是只读观察者,会话起始读到 `preference` 值**直接遵循**即可,无需显式声明。
- 字段语义、读写口径与 legacy 兼容以 `20_Workflow_Lifecycle/local-constraints-schema.md §4.1` 为准。

## 3. 安全底线（硬约束,不可省略）

无论 confidence 多高,以下约束一律生效:

1. **先验非权威**:偏好是对你过往选择的**推测(prior)**,不是事实。真源是 `signals/`(证据),`profile.md` 只是可重新蒸出来的派生解释。
2. **绝不覆盖当前指令**:偏好与用户当前显式指令冲突时,**一律以当前指令为准**,并在 `signals/` 反向记一条信号(见 §5)。
3. **绝不替代正确性把关**:反哺只影响**有监督提议**(默认值/选项排序),只是"这选项像不像你的风格"的提示,**不替代**任何正确性/可验证性/影响面判断;偏好相符**不能**为错误产物背书。
4. **低置信不作依据**:`confidence = low` 的偏好**不得**作为提议默认依据,只可提示"此处倾向不明、值得向用户澄清"。
5. **情境层不跨项目反哺**:情境限定条目只在命中其情境时供有监督参考,**不**跨项目迁移(见 §7)。
6. **不侵入迭代数据流**:探针**从不写 `.ai/`**、不进产物链、不被 hook 拦截、坏了不阻塞迭代(见 §8)。
7. **只学真人选择**:**只采集用户本人的决策**;模型自决(尤其 `/dangerous` 自审门的自主 ACK 与自主决策)**一律不采集**。否则会把"模型对你的猜测"记成"你的偏好",形成自我强化污染(见 §5、§9)。

## 4. 外置存储契约

偏好数据**完全存在 butler 仓库之外**,butler 只定义契约。

### 4.1 路径发现与惰性自举

路径发现按优先级依次尝试,命中即停,确定后记为 `$PREF`:

1. **环境变量**:`echo $BUTLER_PREF`,非空则用。
2. **默认路径**:`~/.butler/preferences/`(不存在则创建)。
3. **用户提供**:以上不可用时,向用户询问一次存储根路径。

**惰性自举**:取得 §2.4 同意后**首次采集**时,若 `$PREF` 尚不存在,**自动创建**并从 butler 仓库 `templates/preference/` 拷骨架(`config.md` / `profile.md` / `signals.example.md`)作为起点。**无需**预先运行 `preference-init.sh` 或 `/preference on`;该脚本保留为**可选的显式初始化**手段。

### 4.2 目录布局

```txt
$PREF/                       (默认 ~/.butler/preferences/)
├── signals/                 # 证据真源:append-only,按项目分片
│   ├── <project-slug>.md
│   └── ...
├── profile.md               # 派生产物:通识层 + 情境限定区
└── config.md                # 同意状态(consent)+ 参数(晋级阈值等)
```

- `signals/<project>.md` **按项目分片**:每条带情境标签,单文件体量有界,**跨项目背书**靠扫描整个 `signals/` 目录算出。
- `profile.md` 是唯一的跨项目蒸馏产物,真源以 `signals/` 为准、可被重新蒸馏。
- `config.md` 记 `consent` 状态;缺失参数按 §6.4 默认值运行。

### 4.3 `signals/<project>.md` 单条字段

| 字段 | 说明 |
|---|---|
| 时间 | YYYY-MM-DD |
| 情境 | 项目类型 / 技术栈 / 所处阶段 |
| 决策类型 | AskUserQuestion 选择 / P2·P3 打回 / 范围演进 / 直接纠正 / 显式标记 / 指令冲突反例 |
| 选择 vs 否决 | 选了什么、否决了什么(**含是否选了非推荐项**——强信号) |
| 上下文 | 一句话 |
| 为什么 | 可选 |

### 4.4 `profile.md` 单条字段

| 字段 | 说明 |
|---|---|
| 陈述 | 倾向 X 而非 Y |
| scope | `跨项目通识` 或 `情境限定(条件: …)` |
| 适用范围 | 架构 / 取舍 / 流程 / 风格 |
| confidence | low / med / high |
| 背书 | 几个不同项目背书 + 引用 signals 条目 |
| 状态 | active / stale + 更新日期 |

`profile.md` 分两区:**通识层在上**(scope = 跨项目通识,反哺真源),**情境限定区在下**(scope = 情境限定)。

## 5. 采集协议 Capture（数据回路·默认常驻）

数据回路开启期间,在决策**已经发生之后**做事后 append(或按 §8 批到收口边界 flush),不打断当前动作。

**自动捕获(高信号结构化事件)**:

- AskUserQuestion 选择——**记录是否选了非推荐项**(强信号)。
- P2 `AC_LIST.md` / P3 `TECH_PLAN.md` 被打回——记录改了什么。
- 迭代内修订、里程碑范围演进。
- code review 中用户的反馈与取舍。
- 用户直接纠正("不要这样,应该…")。
- **指令冲突反例**(§3-2):偏好与当前指令冲突、以当前指令为准时,记一条反向信号。

**显式标记**:用户或 AI 说"记住这条偏好"时,直接写一条高信号条目。

**只学真人选择(§3-7)**:以上一律指**用户本人**的决策。**模型自决不采集**——`/dangerous` 无人值守期间,模型自审门的自主 ACK / 自主决策**一律不记**;但你本人在该模式下的真实决策(**发布总需求、中途叫停纠偏、回来后的事后审查接受/打回**)**照常采集**。

**隐私边界**:只记**决策倾向的抽象**,**不得**记录业务数据、密钥、具体代码内容或敏感信息。拿不准是否敏感时,不记。

## 6. 蒸馏协议 Distill（数据回路·收口边界触发）

蒸馏只在 §8 安全边界触发,把信号归纳为偏好并维护其状态。默认开,使画像温热。

### 6.1 候选提取 Candidate

从 `signals/` 归纳候选偏好,每条挂其证据条目。

### 6.2 跨情境背书核验 Corroboration

统计该候选在**几个不同项目/情境**里一致复现。单项目内重复**不**累加为跨项目背书。

### 6.3 晋级判定 Promotion

- **≥ 晋级阈值个不同项目一致** → 进**通识层**(scope = 跨项目通识)。
- **只在单一情境成立** → 留**情境限定区**(scope = 情境限定,带条件)。
- **跨情境出现矛盾** → **情境化拆分**("A 情境倾向 X、B 情境倾向 Y"),**绝不**强行升通识。
- `confidence` 由背书的**不同项目数 × 一致性**决定:1 项目=low,2 项目=med,≥3 项目且无矛盾=high。

### 6.4 维护 Maintenance

维护是蒸馏过程的一部分,**不是常驻进程**:

- 新证据**强化**或**推翻**旧条;被跨情境新证据推翻的通识 → **降级或重新拆分**。
- 长期无新证据,或被近期选择反复推翻的条目 → 标 `stale` 降权。
- `config.md` 默认参数:晋级阈值 = 2 个不同项目;stale 判定 = 连续相关决策长期未复现或被反例覆盖(可调)。

## 7. 反哺协议 Feedback（影响回路·opt-in·仅有监督）

`/preference reback on` 期间,在模型做决策时把偏好作为参考读入**模型思考上下文**(不写任何产物文件):

- **唯一场景:有监督工作**——标准模式 P2/P3 提案、AskUserQuestion 选项排序:可参考**通识层**,把用户常选项前置或设默认,但**不得替用户 ACK**,用户随时否决。
- **情境层**:仅在当前项目命中其情境条件时可选参考,**不**跨项目迁移(§3-5)。
- **绝不参与 `/dangerous`**:危险模式是无人值守、模型自决,**不读偏好**。让模型在你不在场时按你的偏好自决,等于**冒充你**,且会把模型自决污染回采集(§3-7);危险模式的对齐靠它自己的自审门 / 审计 / 回滚 / P5 强审,**不靠偏好**。

反哺只影响模型的**提议**,被用户当前指令压过(§3-2)。

## 8. 时机与隔离纪律

| 动作 | 触发时机 | 落点 |
|---|---|---|
| 采集 Capture | 数据回路默认开;决策发生后(事后 append,或批到收口边界 flush) | 写 `$PREF/signals/` |
| 蒸馏+维护 Distill | 数据回路默认开;**只在安全边界**:迭代收口 / 里程碑收口 / `/preference distill` | 读 signals、写 `profile.md` |
| 反哺 Feedback | `reback on` 时;**仅有监督**决策点(P2/P3 提案、选项排序) | 读 `profile.md` 入思考上下文 |

**绝不在 P1~P5 任何阶段中途跑蒸馏维护**:维护只发生在迭代数据流已冻结归档之后。

**与迭代数据流的隔离(结构性保证)**:

1. **存储隔离**:探针数据全在 `$PREF/`(外置),**从不写 `.ai/`**;产物链(四件套/台账)在 `.ai/` 内,两套文件零重叠。
2. **单向数据流**:只有"迭代 → 探针观察",**无"探针 → 迭代产物"**;采集把选择的抽象拷贝出去,从不回写 CONCEPT/AC_LIST/TECH_PLAN。
3. **时序隔离**:采集是决策**已发生之后**的事后 append(改不了选择);蒸馏只在收口边界,那时迭代已冻结。
4. **失败隔离**:外置存储缺失/不可写/探针报错时,迭代**照常推进**;探针是 best-effort,**不是门、不被 hook 拦截**,坏了不卡 phase_gate、不阻塞收口。
5. **hook 隔离**:phase_gate 只校验 `.ai/` 四件套,探针写的位置与之零交集,**不新增任何 hook**。

## 9. 与其他模式 / 流程的关系

- **与 `/dangerous` 危险模式**:**完全隔离——既不反哺,也不采集其自主决策**。偏好是人在回路产物;危险模式是无人值守自治,其自审门只对正确性/可验证性/影响面把关、**不读偏好档案**,模型在 `/dangerous` 下的自主决策也**不入信号**。(这是对旧设计的纠正:`/dangerous` 从"主要消费方"反转为"完全隔离"。)
- **与 lifecycle / iteration / milestone**:采集挂在决策点与收口边界,**不改产物链、不改阶段状态机**;迭代/里程碑收口仍各以 `iteration-schema.md` / `milestone-schema.md` 为准。
- **与 Claude Code memory**:**不依赖**任何 harness memory;真源是外置文件,跨 AI 工具通用。(未来如需桥接 memory 作召回加速,以外置文件为准,memory 仅可选镜像。)
- **与 `/review`**:review 中用户的取舍是高价值采集源(§5),但探针不改变 review 引擎本身。

## 10. 实验性边界与已知风险

| 风险 | 缓解 |
|---|---|
| 过拟合(单项目口味冒充普适) | 跨情境晋级阈值;单项目重复不晋级(§6) |
| 偏好过期 | stale 降权;被近期反例推翻即降级(§6.4) |
| 情境误用(情境偏好套到不相干项目) | scope 分层;情境层不跨项目反哺(§3-5) |
| Echo chamber(模型自以为懂你就不问了) | **结构性消除**:反哺只在有监督(你随时否决),且只学真人选择、不采集模型自决(§3-7)——模型的猜测无法回灌成你的偏好;另低置信必澄清(§3-4)、先验非权威不覆盖当前指令(§3-2) |
| 侵入迭代数据流 | §8 五条隔离;探针不在产物链、不被 hook 拦截、坏了不阻塞 |
| 默认采集的知情问题 | §2.4 一次性同意(先问后看);同意前不写任何信号;`/preference off` 随时全停 |
