# Butler 偏好探针引擎

> ⚠️ **实验性能力**。本模块让模型在长期工作中采集用户的设计与取舍倾向、蒸馏成跨项目通识，并在无监督场景下作为自决参考。它的价值与风险都来自"让模型带着对你过往选择的推测去自决"，必须严守 §3 安全底线。

## 1. 身份与目标

偏好探针是 butler 的一条**偏好蒸馏回路**:`采集 → 蒸馏 → 反哺`。

- **采集**:在有监督工作中观察用户的高信号决策（选择、打回、纠正），记成原始信号。
- **蒸馏**:把信号归纳成偏好陈述，凭**跨情境一致**晋级为**跨项目通识**。
- **反哺**:在无监督长程编程（`/dangerous`）等场景，把通识层喂给自审门，补上"用户本人会怎么选"这一维。

目标产物是一份**被多项目背书、跨项目可迁移的通识**:回答"这个人怎么设计、怎么取舍"，而不是某个项目的局部口味。

核心定位:**探针是挂在迭代旁边的只读观察者 + 外置账本,不在产物链里,坏了也不连累迭代**（隔离纪律见 §8）。

## 2. 激活与关闭

持久扩展模式（语义同 `/dangerous`、`/loop`），开启后持续生效直到显式关闭或会话结束，跨迭代有效。**默认关**——它实验性，且需在有监督工作期就开着采集才攒得出通识，故用户应早开、长开。

激活/指令:

- `/preference on`:开启采集与反哺。
- `/preference off`:关闭;关闭后不采集、不反哺,已存数据保留。
- `/preference distill`:手动触发一次蒸馏+维护（见 §6），可在任意安全边界使用。

开启与关闭都**必须**在当回合对话层显式回声一次当前状态。未激活时,本引擎全部规则不生效。

## 3. 安全底线（硬约束，不可省略）

无论 confidence 多高,以下约束一律生效:

1. **先验非权威**:偏好是对你过往选择的**推测（prior）**,不是事实。真源是 `signals/`（证据），`profile.md` 只是可重新蒸出来的派生解释。
2. **绝不覆盖当前指令**:偏好与用户当前显式指令冲突时,**一律以当前指令为准**,并在 `signals/` 反向记一条信号(见 §5）。
3. **绝不替代正确性把关**:在 `/dangerous` 自审门里,偏好只**加一维**"像不像用户的选择",**不替代**自审门对正确性/可验证性/影响面的把关;偏好相符不能为错误产物背书。
4. **低置信不自决**:`confidence = low` 的偏好**不得**作为无监督自决依据,只可作为"建议向用户澄清"的提示。
5. **情境层不跨项目自治反哺**:情境限定条目默认**不**参与跨项目无监督反哺,只在命中其情境时可选参考(见 §7）。
6. **不侵入迭代数据流**:探针**从不写 `.ai/`**、不进产物链、不被 hook 拦截、坏了不阻塞迭代(见 §8）。

## 4. 外置存储契约

偏好数据**完全存在 butler 仓库之外**,butler 只定义契约。

### 4.1 路径发现（Path Discovery）

按优先级依次尝试,命中即停,确定后记为 `$PREF`:

1. **环境变量**:`echo $BUTLER_PREF`,非空则用。
2. **默认路径**:`~/.butler/preferences/`(不存在则创建)。
3. **用户提供**:以上不可用时,向用户询问一次存储根路径。

### 4.2 目录布局

```txt
$PREF/                       (默认 ~/.butler/preferences/)
├── signals/                 # 证据真源:append-only,按项目分片
│   ├── <project-slug>.md
│   └── ...
├── profile.md               # 派生产物:通识层 + 情境限定区
└── config.md                # 参数:晋级阈值等
```

- `signals/<project>.md` **按项目分片**:每条带情境标签,单文件体量有界（契合"文档有界、横向铺开"），**跨项目背书**靠扫描整个 `signals/` 目录算出。
- `profile.md` 是唯一的跨项目蒸馏产物,真源以 `signals/` 为准、可被重新蒸馏。
- `config.md` 缺失时按 §6.4 默认值运行。
- 首次 `/preference on` 时,可把 butler 仓库 `templates/preference/` 下的骨架（`config.md` / `profile.md` / `signals.example.md`）拷贝到 `$PREF` 作为起点;骨架只给可落地的初始结构,字段定义仍以本节为准。

### 4.3 `signals/<project>.md` 单条字段

| 字段 | 说明 |
|---|---|
| 时间 | YYYY-MM-DD |
| 情境 | 项目类型 / 技术栈 / 所处阶段 |
| 决策类型 | AskUserQuestion 选择 / P2·P3 打回 / 范围演进 / 直接纠正 / 显式标记 / 指令冲突反例 |
| 选择 vs 否决 | 选了什么、否决了什么（**含是否选了非推荐项**——强信号） |
| 上下文 | 一句话 |
| 为什么 | 可选 |

### 4.4 `profile.md` 单条字段

| 字段 | 说明 |
|---|---|
| 陈述 | 倾向 X 而非 Y |
| scope | `跨项目通识` 或 `情境限定(条件: …)` |
| 适用范围 | 架构 / 取舍 / 流程 / 风格 |
| confidence | low / med / high |
| 背书 | 几个不同项目背书 + 引用 signals 条目 |
| 状态 | active / stale + 更新日期 |

`profile.md` 分两区:**通识层在上**(scope = 跨项目通识,反哺真源),**情境限定区在下**(scope = 情境限定)。

## 5. 采集协议 Capture（混合）

激活期间,在决策**已经发生之后**做事后 append,不打断当前动作。

**自动捕获(高信号结构化事件)**:

- AskUserQuestion 选择——**记录是否选了非推荐项**(强信号)。
- P2 `AC_LIST.md` / P3 `TECH_PLAN.md` 被打回——记录改了什么。
- 迭代内修订、里程碑范围演进。
- code review 中用户的反馈与取舍。
- 用户直接纠正("不要这样,应该…")。
- **指令冲突反例**(§3-2):偏好与当前指令冲突、以当前指令为准时,记一条反向信号。

**显式标记**:用户或 AI 说"记住这条偏好"时,直接写一条高信号条目。

**隐私边界**:只记**决策倾向的抽象**,**不得**记录业务数据、密钥、具体代码内容或敏感信息。拿不准是否敏感时,不记。

## 6. 蒸馏协议 Distill

蒸馏只在 §8 安全边界触发,把信号归纳为偏好并维护其状态。

### 6.1 候选提取 Candidate

从 `signals/` 归纳候选偏好,每条挂其证据条目。

### 6.2 跨情境背书核验 Corroboration

统计该候选在**几个不同项目/情境**里一致复现。单项目内重复**不**累加为跨项目背书。

### 6.3 晋级判定 Promotion

- **≥ 晋级阈值个不同项目一致** → 进**通识层**(scope = 跨项目通识)。
- **只在单一情境成立** → 留**情境限定区**(scope = 情境限定,带条件)。
- **跨情境出现矛盾** → **情境化拆分**("A 情境倾向 X、B 情境倾向 Y"),**绝不**强行升通识。
- `confidence` 由背书的**不同项目数 × 一致性**决定:1 项目=low,2 项目=med,≥3 项目且无矛盾=high。

### 6.4 维护 Maintenance

维护是蒸馏过程的一部分,**不是常驻进程**:

- 新证据**强化**或**推翻**旧条;被跨情境新证据推翻的通识 → **降级或重新拆分**。
- 长期无新证据,或被近期选择反复推翻的条目 → 标 `stale` 降权。
- `config.md` 默认参数:晋级阈值 = 2 个不同项目;stale 判定 = 连续相关决策长期未复现或被反例覆盖(可调)。

## 7. 反哺协议 Feedback

激活期间,在模型做决策时把偏好作为参考读入**模型思考上下文**(不写任何产物文件):

- **主:`/dangerous` §5 自审门**——自审时读**通识层**,若当前自决与高 confidence 通识冲突,**必须在审计日志(`RUN_LOG.md`)显式标注并三思**;这是**加审,不是硬否决**,正确性把关仍以自审门为准(见 §3-3）。
- **次:标准模式 P2/P3 提案与 AskUserQuestion 选项排序**——可参考通识层,把用户常选项前置或设默认,但不得替用户 ACK。
- **情境层**:仅在当前项目命中其情境条件时可选参考,**不参与跨项目无监督自治反哺**(§3-5）。

反哺只影响模型的**提议**,被用户当前指令压过(§3-2）。

## 8. 时机与隔离纪律

| 动作 | 触发时机 | 落点 |
|---|---|---|
| 采集 Capture | 决策点发生后(事后 append,运行中) | 写 `$PREF/signals/` |
| 蒸馏+维护 Distill | **只在安全边界**:迭代收口 / 里程碑收口 / `/preference distill` | 读 signals、写 `profile.md` |
| 反哺 Feedback | 模型做决策时(P2/P3 提案、`/dangerous` 自审门) | 读 `profile.md` 入思考上下文 |

**绝不在 P1~P5 任何阶段中途跑蒸馏维护**:维护只发生在迭代数据流已冻结归档之后。

**与迭代数据流的隔离(结构性保证)**:

1. **存储隔离**:探针数据全在 `$PREF/`(外置),**从不写 `.ai/`**;产物链(四件套/台账)在 `.ai/` 内,两套文件零重叠。
2. **单向数据流**:只有"迭代 → 探针观察",**无"探针 → 迭代产物"**;采集把选择的抽象拷贝出去,从不回写 CONCEPT/AC_LIST/TECH_PLAN。
3. **时序隔离**:采集是决策**已发生之后**的事后 append(改不了选择);蒸馏只在收口边界,那时迭代已冻结。
4. **失败隔离**:外置存储缺失/不可写/探针报错时,迭代**照常推进**;探针是 best-effort,**不是门、不被 hook 拦截**,坏了不卡 phase_gate、不阻塞收口。
5. **hook 隔离**:phase_gate 只校验 `.ai/` 四件套,探针写的位置与之零交集,**不新增任何 hook**。

## 9. 与其他模式 / 流程的关系

- **与 `/dangerous` 危险模式**:主要消费方。激活偏好探针后,`dangerous-engine.md` §5 自审门获得**可选**的偏好维度;未激活偏好探针时,危险模式照常工作,自审门不依赖偏好。
- **与 lifecycle / iteration / milestone**:采集挂在决策点与收口边界,**不改产物链、不改阶段状态机**;迭代/里程碑收口仍各以 `iteration-schema.md` / `milestone-schema.md` 为准。
- **与 Claude Code memory**:**不依赖**任何 harness memory;真源是外置文件,跨 AI 工具通用。(未来如需桥接 memory 作召回加速,以外置文件为准,memory 仅可选镜像。)
- **与 `/review`**:review 中用户的取舍是高价值采集源(§5),但探针不改变 review 引擎本身。

## 10. 实验性边界与已知风险

| 风险 | 缓解 |
|---|---|
| 过拟合(单项目口味冒充普适) | 跨情境晋级阈值;单项目重复不晋级(§6） |
| 偏好过期 | stale 降权;被近期反例推翻即降级(§6.4） |
| 情境误用(情境偏好套到不相干项目) | scope 分层;情境层不跨项目反哺(§3-5） |
| Echo chamber(模型自以为懂你就不问了) | 低置信必澄清(§3-4);先验非权威、不覆盖当前指令(§3-2） |
| 侵入迭代数据流 | §8 五条隔离;探针不在产物链、不被 hook 拦截、坏了不阻塞 |
