# 原始信号示例（仅参考，勿拷入 signals/）

> 真实信号按项目落在 `$BUTLER_PREF/signals/<project-slug>.md`，append-only。
> 字段定义见 `preference-probe-engine.md` §4.3。每条信号必须带情境标签，
> 否则算不出「跨几个项目背书」，通识无从晋级。

## 单条格式

```md
- 时间: 2026-06-09
  情境: butler 规则仓库 / 文档体系 / P3 设计阶段
  决策类型: AskUserQuestion 选择（选了非推荐项）
  选择 vs 否决: 选「松耦合可选」；否决「强层级必属」
  上下文: milestone 与 ITER 的归属关系强度
  为什么: 要兼容已部署项目与简化路径任务，保留优雅降级
```

## 几类高信号事件示例

```md
- 时间: 2026-06-09
  情境: butler 规则仓库 / 文档体系
  决策类型: 直接纠正
  选择 vs 否决: 选「最小侵入」；否决「把 milestone 写成新阶段」
  上下文: lifecycle.md 是否新增阶段
  为什么: 不破坏既有状态机

- 时间: 2026-06-09
  情境: butler 规则仓库 / 交付结构
  决策类型: AskUserQuestion 选择
  选择 vs 否决: 选「扁平时间线 + milestones 子目录」；否决「版本目录包」
  上下文: deliveries/ 布局
  为什么: 迭代历史要保持一条连续可读时间线

- 时间: 2026-06-09
  情境: 任意项目
  决策类型: 指令冲突反例
  选择 vs 否决: 偏好建议 X，但用户当前要求 Y；以 Y 为准
  上下文: 当前指令压过先验偏好（安全底线 §3-2）
  为什么: 先验非权威
```
