> 区间: v3.0.0 → v3.1.0 · 聚合 ITER-0083–ITER-0089 · **MINOR**

## 对已部署项目的影响

本版新增可信 handoff、有界状态台账和确定性五件套产物链。新项目直接使用新版结构；既有项目不会被升级器自动改写 `.ai/` 历史或当前五件套，状态分片与五件套迁移都必须在项目级迭代中显式执行并审阅结果。

## 迁移步骤

1. `[global-install]` 在 Butler 仓运行 `bash scripts/setup.sh`，刷新 Claude 全局命令、Codex plugin 与 Pi 扩展；执行前需明确确认机器级安装。
2. `[sync-hooks]` 对比目标项目 `.claude/hooks/` 与本版真源；只有 hook 树可识别或尚不存在且 settings 结构合法时才同步，检测到用户漂移立即停止并报告差异。
3. `[regen-entrypoints]` 用统一 renderer 刷新 CLAUDE.md / AGENTS.md 的 Butler 管理区，使冷启动先校验 handoff 新鲜度并使用新版规则卡；marker 异常时停止，不覆盖 user-managed 内容。
4. `[restamp]` 在双入口 marker 校验通过后，把目标项目版本戳对齐 v3.1.0。

## 显式项目迁移

- 状态台账：先运行 `python3 "$BUTLER_PATH/tools/state-ledger/state_ledger.py" inspect --project-root "$PROJECT_ROOT"`，审阅后再运行同命令的 `migrate`，最后以 `check` 校验；工具只迁移 Butler 管理的台账与索引。
- 五件套：只在活跃迭代中先运行 `python3 "$BUTLER_PATH/tools/artifact-pipeline/migration.py" plan --project-root "$PROJECT_ROOT"`，确认 pre/post hash 与 `apply_ready` 后再执行 `apply`；根据 receipt 的 migration ID 执行 `verify`，需要回退时执行 hash-gated `rollback`。
- 历史 `.ai/iterations/` 归档保持只读，不追溯重排章节。
