> 区间: v1.0.0 → v1.1.0 · 聚合 ITER-0008 ~ ITER-0010

## 对已部署项目的影响

- 新增 hook 规则 `ledger_status`（迭代台账状态封闭枚举校验）——需同步 `.claude/hooks/` 副本。
- `.ai/local-constraints.md`「Butler 功能开关」段新增 `preference: on` 字段。
- 本版聚合的 ITER-0008 / ITER-0009 / ITER-0010 **均改过 `templates/rule-card.md`**（迭代状态枚举、preference 开关、交付 HTML 相关纪律）——内联进目标 `CLAUDE.md` 的规则卡因此变化，需重生成。
- 新增交付总结 HTML 模板（`templates/delivery.html.template`）——只影响今后新交付的产出方式，不迁移既有文件。

## 迁移步骤

1. `[sync-hooks]` 比对目标 `.claude/hooks/` 与仓库 `templates/hooks/`（除 `tests/`）。不一致则按 `mcv-deployment.md §5.1` 以 butler 版本为准覆盖；本版起 `rules/ledger_status.py` 应存在。覆盖后按 `mcv-deployment.md §5.3` 跑一次 hook 自检。
2. `[add-field]` 若 `.ai/local-constraints.md`「Butler 功能开关」缺 `preference` 字段，补 `preference: on`（默认 on，安全：实际采集仍需全局同意）；已有则跳过。
3. `[regen-claude]` rule-card 已变更，重生成目标 `CLAUDE.md` 的 rule-card 内联段（按 `mcv-deployment.md §3` 第 2 步），`<!-- user-managed -->` 保护区内容原样保留。
4. `[restamp]` 版本戳 → v1.1.0。

## 不需要动作

- `templates/delivery.html.template` 是 butler 侧模板，今后收口时按需取用，无既有目标文件要迁移。
- 迭代台账状态枚举是规则约束、由 `ledger_status` hook 机械保证，无需改目标已有台账内容（若已写入非法值，hook 会在下次写入时拦截提示）。
