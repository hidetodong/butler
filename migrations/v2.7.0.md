> 区间: v2.6.1 → v2.7.0 · 聚合 ITER-0047（butler 命令命名空间系统地基 · MILE-0005 R1）· **MINOR（向后兼容能力新增）**

## 对已部署项目的影响

- **对目标项目 `.ai/` 部署面无结构迁移（`[no-op]`）**：ITER-0047 改的是 butler 仓自身的**命令文件布局**（`.claude/commands/butler-prd.md` → `.claude/commands/butler/prd.md`，新增 `.claude/commands/butler/review.md`）+ **全局安装脚本**（`scripts/setup.sh` 由逐文件软链改成软链整个 `butler/` 命名空间目录）+ 文档。这些都不在逐项目部署产物里——目标项目的 `.ai/` / `deliveries/` / `origin/` / `CLAUDE.md` / `.claude/hooks/` 均无任何结构变化。
- **命令走全局软链、非逐项目模板**：命令**不进** `templates/`（`git diff v2.6.1..v2.7.0 -- templates/` 为空），不随基地车部署逐项目落地。因此内联规则卡、hook 体系、`settings.hooks-snippet.json` 均无更新 → 无需 `[regen-claude]` / `[sync-hooks]`。
- **改名破坏面被关在「个人命令别名」这一层，不触碰目标项目契约**：本版把命令 `/butler-prd` 破坏性改名为 `/butler:prd`（并把 `butler-prd.md` 收进 `butler/` 子目录作命名空间前缀）。这只影响**维护者自己在会话里敲哪个命令名**——butler 的 semver 语义按**目标项目部署契约 / 规则体系**定范围（见 `versioning-schema.md`），那一面零变化（`[no-op]`）。故整体定 **MINOR**（新增 `/butler:` 命名空间这一可扩展能力），而非 MAJOR。个人命令层的旧名 `/butler-prd` 失效由 `setup.sh` 的迁移清理步兜底（见下）。
- **无其它破坏性变更**：无规则文件重命名 / 删除、无 schema 必填字段增删、无产物链阶段重排、无 hook 拦截契约变更、无命令语义不兼容变更（`/butler:prd` 路由三分支相较 `/butler-prd` 一字未改，仅换了触发名与文件位置）→ 无 MAJOR 级迁移动作。

## 迁移步骤

> 本版对目标项目 `.ai/` 部署面**无结构迁移**（`[no-op]`）；但要在本机把命令从旧的 `/butler-prd` 切到 `/butler:prd`、并拿到新的 `/butler:review`，需一个**机器级**动作（不是逐项目动作）。

1. `[global-install]` **重跑一次 `./scripts/setup.sh`**（在 butler 仓目录下）——它会：①**迁移清理**：若本机还留着旧的扁平软链 `~/.claude/commands/butler-prd.md`（仅当它是软链时才删，绝不误删你自己放的真文件），自动移除；②把 `.claude/commands/butler/` 命名空间目录整体软链进 `~/.claude/commands/butler`，`/butler:prd`·`/butler:review` 等随即在**所有项目**可用（子目录=命名空间，冒号前缀）。幂等、可反复跑；软链常青，之后 butler 仓加/改命令即全局生效、无需再装。这是一次性机器级动作，与逐项目升级无关。
2. `[restamp]` 版本戳 → v2.7.0（按 `mcv-deployment.md §3` 重戳目标 `CLAUDE.md` butler 管理区的 `{{BUTLER_VERSION}}`；`<!-- user-managed -->` 保护区原样保留）。

## 本机一次性动作说明（`[rename]` 已被 setup.sh 兜底 · 与目标项目无关）

> 命令改名的收尾已并进上面的 `[global-install]`，正常无需手工操作；下面仅说明发生了什么，便于排查。

- **旧命令名 `/butler-prd` 停用**：改由 `/butler:prd` 触发（路由行为一字未改）。重跑 `setup.sh` 后旧软链已被清理；若你**跳过**重跑、仍直接敲 `/butler-prd`，会找不到命令——重跑一次即可。
- **旧软链残留自愈**：`setup.sh` 用 `-L` 判定只删软链、`ln -sfn` 的 `-n` 防止把新链接建进已存在的目录软链内部（避免 `butler/butler` 套娃）。反复重跑安全。

## 不需要动作

- `[sync-hooks]`：`templates/hooks/` 与 `templates/settings.hooks-snippet.json` 未改动。
- `[regen-claude]`：`templates/rule-card.md` / `templates/CLAUDE.md.template` 未改动，内联规则卡无更新。
- `[add-field]`：四件套 schema 无字段增删。
- `[split]`：无全貌产物文件夹化需求（命令文件收进 `butler/` 子目录是命名空间前缀，非产物 `[split]`）。
- **逐项目基地车部署**：命令是全局软链、不进目标项目——目标项目侧除 `[restamp]` 外无需任何动作；「换命名空间」是机器级的 `[global-install]`（重跑 setup.sh，含旧软链清理），做一次覆盖本机所有项目。
