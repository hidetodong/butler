## 对已部署项目的影响

- **冷启动全貌产物结构性升级：单文件 → 知识文件夹（破坏性，ITER-0028/0029/0031/0032/0034）**：本版把项目全貌产物从单文件薄索引 `.ai/PROJECT.md` 升级为 `.ai/project/` 主题知识文件夹（`00_INDEX` 入口 + 主题集）。已积累单文件 `.ai/PROJECT.md` 的老项目需**按主题拆分文件夹化**（`[split]`）。**两态并存、不强制立即迁**：R6 前部署、尚未迁移的老项目仍受规则的单文件分支支持（冷启动第一读 / 收口前滚 / 第 6 漂移不变量均有单文件回退），可继续单文件运行；下面 `[split]` 是"想迁时怎么迁"的配方，非"必须马上迁"。
- **浓缩规则卡有变（ITER-0027/0033）**：区间内 `templates/rule-card.md` 被修改（`git log v1.7.0..v2.0.0 -- templates/rule-card.md` 非空——补入最小实现纪律、说人话三条硬标准相关强制约束）。部署项目的 `CLAUDE.md` 内联了 rule-card 内容（`{{RULE_CARD_CONTENT}}` 展开），需重新生成才能获得更新后的强制约束条目（`[regen-claude]`）。
- **未改 hook 体系**：区间内 `templates/hooks/` 与 `templates/settings.hooks-snippet.json` 未动（`git log v1.7.0..v2.0.0 -- templates/hooks templates/settings.hooks-snippet.json` 为空）→ **无需 `[sync-hooks]`**。
- **无四件套 schema 必填字段增删**：区间内改动的是工作流规则（`project-digest-schema` 改写、`migration-schema §4`、`iteration-schema §5.5`、`milestone §7.4`、`context-persistence §6`）与新增模块，四件套（CONCEPT/AC_LIST/TECH_PLAN/VERIFY_REPORT）字段结构未变 → **无需 `[add-field]`**。
- 其余（`Coder/` 规则正文升级、新增 `62_Extension_Agents/` 帮手名册、`30_Quality_Gate/implementation-discipline.md`、说人话三条落 `artifact-style`/`presentation-protocol`）均为 butler 仓规则正文，运行时实时读取，随目标项目下次执行相应阶段自动生效，无需迁移既有文件。

## 迁移步骤

1. `[split]` 把单文件 `.ai/PROJECT.md` 按主题拆分为 `.ai/project/` 知识文件夹（按 `40_Context_Management/project-digest-schema.md` 主题集：把单文件内容路由进 `00_INDEX.md` + 各主题文件 `identity`/`architecture`/`capabilities`/`invariants`/`constraints`/`debt`/`frontier`）。**判据**=旧 `.ai/PROJECT.md` 存在**且**目标 `.ai/project/00_INDEX.md` 尚未成形才动。拆出的文件走 `git add`（内容重组非纯改名，`git mv` 不适用，血缘靠本 commit 说明追溯）。**冲突即停**：目标文件夹已部分成形、或旧单文件已被手工改得与预期不符（目标项目漂移），**不覆盖**、停下报告差异、退回用户 ACK——绝不把用户手写内容拆丢。未产生过 `.ai/PROJECT.md` 的更老项目：由升级新建空 `.ai/project/` 种子（`00_INDEX` 首次收口前滚生），无单文件可拆、跳过本步。
2. `[regen-claude]` 按 `mcv-deployment.md §5` 以最新 `templates/rule-card.md` 重新展开目标项目 `CLAUDE.md` 的 `{{RULE_CARD_CONTENT}}` 段。校验：内联规则卡与仓库 `templates/rule-card.md` 一致；仅 rule-card 段更新、`<!-- user-managed -->` 保护区原样保留。目标 `CLAUDE.md` 若被手工改过（漂移）则停下、报告差异、退回用户 ACK，不强行覆盖。
3. `[restamp]` 版本戳 → v2.0.0。
