> 区间: v3.2.0 → v3.3.0 · 聚合 ITER-0093–ITER-0095（MILE-0013）· **MINOR**

## 对已部署项目的影响

本版把项目级 Butler 机器配置从 `.ai/local-constraints.md` 拆到顶层扁平的 `.ai/butler.config.json`。旧 Markdown 在配置文件缺失时仍可兼容只读；一旦 JSON 存在，它就是唯一真源，损坏或歧义均 fail-closed。

## 迁移步骤

1. `[global-install]` 在 Butler 仓运行 `bash scripts/setup.sh`，刷新 Claude 命令、Codex plugin/skills 与 Pi 扩展；这是机器级动作，必须单独确认。
2. `[migrate-config]` 严格读取旧 Active Profiles、「Butler 功能开关」和 Review Policy，在同一升级事务中创建规范 `.ai/butler.config.json`，并只从 `.ai/local-constraints.md` 删除这些机器段。模糊值、冲突 JSON、symlink 或写入故障均拒绝/恢复，不留下半迁移。
3. `[regen-entrypoints]` 从 `templates/rule-card.md` 重生成 CLAUDE.md / AGENTS.md managed block，使会话冷启动统一调用 project-config `resolve`。
4. `[restamp]` 把双入口版本戳对齐 v3.3.0。

## 兼容与回写边界

- 活消费端统一调用 `resolve` 读取；JSON 缺失才回退 legacy Markdown，冲突显式报告。
- 项目开关/profile 回写只调用 `set` 且只写 JSON。legacy 项目先升级，消费端不再改 Markdown。
- 偏好 consent、signals、profile 继续只在外置 `$BUTLER_PREF`；项目 JSON 仅承载本项目 `preference` 抑制开关。
- 不迁移任务阶段、里程碑、授权上限、handoff 或运行日志。
