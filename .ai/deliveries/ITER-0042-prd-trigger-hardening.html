PRD 先行触发加固：堵住 Confluence + MCP + /milestone 的漏切通道

ITER-0042 迭代交付（小版本） 收口 2026-07-12

本次交付目标

  • MILE-0004 建成的「PRD 先行」全生命周期链，实战里被一条真实通道穿透：用户给一份 Confluence 文档地址、AI 经 MCP 直读当 /milestone brief，结果 MILESTONE.md 合成了，但从没提切分、references/prd/ 从没建——PRD 的逐字规格蒸发进上下文、没落盘。
  • 根因是整条切分链软触发、零强制，而「Confluence + MCP 直读 + /milestone」恰好同时穿过三层最薄的纸。本轮三层一起补：把软触发挪到难错过的位置 + 给唯一可观测的落盘点加一道非阻塞自检。

已完成内容

  • ① 注入表按内容分类（改 logic-protocol.md）：外部资料注入从"按来源信号一步定落点"改成两拍——第一拍按来源取内容（Confluence / 经 MCP 直读的文档 / MasterGo / 粘贴文本…都只是取内容的手段），第二拍按内容类型定落点（逐字权威规格 PRD → prd/ 切分、API 契约 → api-、设计 → design-、分析报告 → insight-）。落一条命门：来源 ≠ 落点，落点只由内容是什么决定。装 PRD 的 Confluence 从此走 prd/，绝不因"它是 Confluence / 来自 MCP"默认落 api- 扁平。Fallback（人工粘贴）同样按内容分类——粘贴一份大 PRD 一样走切分。
  • ② 里程碑分类闸前移（改 milestone-schema §6.4）：把"这份 brief 是不是大 PRD"的判断，从末尾一个默认跳过的附录步，提成合成 MILESTONE 之前必过的分类闸：任何外部结构化文档当 brief（对话 / origin/ / MCP 直读），合成路线图前先判——是 PRD 就先切再合成，不是就照旧。判定从"可选、易漏"变成"前置、必过"。
  • ③ 新增 PostToolUse 落盘自检 hook（兜唯一可观测点）：新增一套与现有门禁分离的 PostToolUse 提醒 hook（butler_advisor.py + prd_split_reminder 规则）——写完 .ai/MILESTONE.md 后，若 references/prd/ 还不存在，就经 additionalContext 给模型注入一句条件式自检（"brief 若源自外部权威规格，先切 references/prd/ 再推进；否则忽略"）。配套：Advisory 类型 + pytest 覆盖 + 部署/settings/README 接线。

关键变更 / 用户可感知变化

  • 给一份 Confluence/PRD 链接开里程碑，不再只建 MILESTONE 就完事：内容是 PRD 就会被识别、提议切成 references/prd/ 逐字切片，后续验收能对着真源核。
  • 落点跟"从哪来"脱钩：同一份 PRD，无论来自对话粘贴、origin/ 文件、还是 MCP 直读，都走同一条内容分类——不再有"从 MCP 进来就漏切"的暗门。
  • 漏了会被当场提醒：万一还是没切，写 MILESTONE 时 hook 会注入一句自检提醒，把"漏切"从静默变可见。
  • 提醒绝不挡路：这道 hook 只提醒、永远放行（PostToolUse + fail-open），非 PRD 的普通里程碑读一句即可忽略，写操作结果一字不变。
  • 不用 PRD 的人完全无感：老门禁一行没动，对话录入 / 普通 brief 合成 / 扁平态注入全程未变。
