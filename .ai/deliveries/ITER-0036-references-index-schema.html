本次交付目标

  • butler 里有两个"外部资料收件箱"：一个是 origin/（人类丢原始概念稿的地方），另一个是 .ai/references/（把项目之外的权威资料——接口文档、设计稿、PRD——经处理后存进来，供后续阶段按指针引用、不必让用户反复贴）。
  • 上一个大版本（MILE-0003）给项目自身的全貌产物 .ai/project/ 升级成了"知识文件夹"待遇：有入口地图（00_INDEX）、按主题渐进读、不一次性全部塞进上下文。但 .ai/references/ 当年没被这套待遇覆盖到——它有人管注入（logic-protocol）、有人管目录（mcv-deployment）、有人管"哪些验收源自它"（External References 字段），却从来没有一份 schema 说清楚：references 内部到底长什么样、该怎么读。
  • 新版本 MILE-0004 要做的"PRD 先行 + 版本化改版同步"，全都得踩在"references 有索引、有稳定的模块身份、有版本落盘"这块地基上。本轮（R1）就是先把这块地基浇好：新建一份契约文件，把 references 的结构、读法、身份、落盘形态一次定死。只定契约、不做动作——真正把 PRD 切成片、从 /milestone 触发首切、给验收标准钉版本、改版时同步，都留给后续 R2–R5。

已完成内容

新建 Coder/40_Context_Management/references-schema.md——.ai/references/ 子系统的首份结构契约，八节：

  • §1 定位 + 与 .ai/project/ 的分工：一张表钉死两者不重叠——project 存"项目自身全貌"、是有损摘要（当前真相覆写旧结论）；references 存"项目之外的权威资料"、含无损切片（PRD 原文逐字投影）。一句话记：一个把项目积成有损地图，一个把外部规格无损钉在墙上。
  • §2 两态：小而消化过的资料走扁平态（api- 接口 / design- 设计稿 / insight- 分析报告，一个文件装下、不建索引）；大而结构化的权威规格（典型即 PRD）走知识文件夹态 prd/（索引 + 渐进读 + 无损切片 + 带版本）。
  • §3 prd/ 结构：00_INDEX 入口（叙述 + 模块登记表）；登记表每模块一行——slug（终身身份）↔ 当前标题/章节（会变的门牌）↔ 首见版本 ↔ 当前版本 ↔ 状态（active/removed）。
  • §4 slug 身份规则：slug（模块的终身英文代号，如 save-validation）一次分配、终身不变、只增不改——章节号是会变的门牌、slug 是不变的身份，引用永远指 slug。这是后续 R5/R6 改版"认亲"（新版切片对回旧模块）的锚点。
  • §5 读纪律 digest-and-point：读 prd 先读 00_INDEX 地图 → 按手头任务只钻用到的那片 prd/<slug>.md → 需要更细再顺指针钻源；不一次性读整份 PRD（长 PRD 就是这样省上下文的）。执行默认读 live 最新，回溯才去翻旧版归档。
  • §6 无损 vs 有损硬区分（命门）：00_INDEX（含登记表）可以是摘要（它是找路的地图）；prd/<slug>.md 切片必须逐字原文、无损（PRD 里的精确文案、精确校验规则，少一个字验收就错）。写成硬约束：不得对切片套用 .ai/project/ 那种"当前真相覆写"的概括 / 蒸馏语义。
  • §7 落盘契约：prd/<slug>.md（live 目录、最新版、无版本前缀、执行直读）+ .archive/vN/（改版时把旧版整份冻进来的全量快照、审计/回溯用）。只定"落盘长什么样"，不定"何时怎么冻"。
  • §8 边界：一张前向指针表，把"产生 / 变更动作"（切分 R2 / 入口 R3 / 钉版 R4 / 同步 R5 / 认亲 R6）显式标出、本轮一律不落实现。

Coder/README.md 双处注册：目录结构树 40_Context_Management 下补 references-schema.md；规则说明段补一条（定位 + 与 project-digest 的分工 + 动作属 R2–R5）。守"新增规则文件必须注册"的仓库约束。

关键变更 / 用户可感知变化

  • references 从此有了"内部长什么样"的说明书：以前 AI 往 .ai/references/ 存资料，只知道"往这放"，不知道大资料该怎么组织、怎么读；现在有了明确契约——大 PRD 该切片、该建索引地图、该逐字保真、该带版本落盘。
  • 本轮对日常使用暂无可感知的新动作：R1 是纯契约地基，没有新命令、没有新交互。真正能"把一份 PRD 导进来自动切片、钉版、改版同步"要等 R2–R5 逐块落地。本轮的价值是让后面几块有确定的地基可踩，而不是现在就能用。
  • 一条贯穿整个 MILE-0004 的红线被先立住了：PRD 切片必须逐字原文、绝不能被"顺手概括"。一旦有人拿项目摘要那套有损压缩去套 PRD 切片，PRD 里精确的文案和校验规则就废了——这条红线现在写成了 schema 里的硬约束。
