butler 命令命名空间系统：散文触发词收敛成一整套 /butler:* 真实 slash 命令

MILE-0005 里程碑交付（跨版本聚合） v2.7.0 → v2.10.0 收口 2026-07-14

本次交付目标

  • 一条主线，补 butler 长期停在「散文触发词」的缺口。缺口三层：① 规则正文里 /milestone、/review、/dangerous、/loop、/preference 到处当暗号被引用，但只有 /butler-prd 一个真实命令文件，其余在补全菜单里零存在感；② 全局安装用通用名易与别的插件 / 用户自定义命令撞名；③ 没有统一命名空间、命令能力零成体系。
  • 里程碑目标：把整套 butler 能力都获得一等命令入口——.claude/commands/butler/ 子目录＝Claude Code 的 /butler:<name> 命名空间（冒号是真实调用分隔符），butler: 前缀天然隔离撞名，setup.sh 一条目录软链托管全套、任意项目补全菜单可见可用、加命令自动全局生效。全部走薄壳路由器范式（读对规则进上下文 → 按 $ARGUMENTS 分派 → 委托真源不复述算法），不改任何 Coder/** 规则算法、不下发目标项目。逐项属 semver MINOR。

已完成内容

四个路线项（R1~R4）一条主线闭环。链路顺序：地基 + prd 迁移 + 首命令验证（R1）→ 批量补低风险纯薄壳命令（R2）→ 最宽参数命令〔二级嵌套参数〕（R3）→ 高风险命令加风险闸〔收官〕（R4）。全程复用同一薄壳路由器范本，逐轮抬升复杂度证明范式够用：R1 立范本、R2 证批量可复制、R3 证吃得下二级嵌套参数、R4 证扛得住风险闸——无平行机制。

关键变更 / 用户可感知变化

  • 命名空间地基 + /butler-prd 破坏性迁入（R1）：建 .claude/commands/butler/ 子目录；/butler-prd git mv 迁成 butler/prd.md→/butler:prd（[rename] 配方 + 清旧全局软链 + 正文引用更新）；setup.sh 从「逐文件软链」改为软链整个 butler/ 目录——一条目录软链管全套、加命令自动全局生效、无需重跑 setup。同轮落 /butler:review 验证范本可复制。
  • 批量补三个低风险纯薄壳命令（R2）：/butler:milestone（+status）、/butler:upgrade（原 /butler-upgrade 一并迁触发名）、/butler:ideation。各含「没接 butler 优雅降级」+ 跨 cwd 路径约定段。隔离 HOME 实跑坐实 R1 目录软链自动托管（5/5 可达、setup.sh 未改一行）。
  • 最宽参数命令 /butler:preference（R3）：一个薄壳吃下全批参数面最宽的能力——on/off、reback on|off（全批唯一二级嵌套参数：首 token 是 reback 才读第二 token）、distill、空参=只读状态回声。委托 preference-probe-engine 真源不复述。证明薄壳范式吃得下二级嵌套参数。
  • 高风险命令加风险闸〔收官〕（R4）：/butler:loop（收敛闭环死磕，无参 / 无持久态 / 无 off）+ /butler:dangerous（无人值守自治，空=开启 / off / status 只读，持久态外化跨会话）。唯一新面是风险闸——命令化不得降低「郑重、显式触发」门槛，三招：① frontmatter ⚠️ + ② 第 0 步前置风险提醒 + ③ 把真正的闸交回引擎（不复述护栏、守 DRY；不省风险提醒、门槛不降）。/butler:loop 与 Claude Code 自带 /loop 靠命名空间前缀消歧、harness 引用精确保留加注。
  • 散文触发名成体系迁移：R1–R4 逐轮把命令引用旧名（/butler-prd、/butler-upgrade、/preference、/loop、/dangerous）迁成 /butler:*，并在 logic-protocol 保留旧名识别——旧名与自然语言触发照常工作、新名是命名空间一等入口。
  • 对不装/不用的人无感：命令是靠全局软链的个人工具，不进 templates/、不下发目标项目、目标项目 .ai/ 部署面零变化（逐迭代 [no-op]+[restamp]）；规则卡文案里的旧名原样保留、仍工作。

已知剩余风险 / 延后事项

  • 命令入口已成体系，运行时行为多数未新验：8 命令入口都已结构验证 + 经目录软链可达，但命令只是把既有引擎能力摆上菜单、委托真源执行——未改也未新验引擎运行时行为。尤其 /butler:dangerous（无人值守自治端到端）、/butler:upgrade（真实老项目端到端升级）两笔历史欠债仍悬（见 debt.md）。
  • 命令菜单「可见性」headless 不可实敲：全程用代理验法（文件存在 + 命名空间结构正确 + 经目录软链可达 + setup.sh exit 0）。真正菜单可见需在主检出跑过 R1 的 setup.sh。
  • 双名并存（引擎/文档说 /butler:*、templates 保留旧名）：有意分层——靠 logic-protocol 保留旧名识别接住，目标项目侧规则卡文案不变、旧名仍工作（逐迭代 DD 决策 + migration 说明覆盖，非缺陷）。
  • /butler:loop 与 Claude Code 自带 /loop 用户心智撞名：命令层用 /butler:loop 消歧、dangerous-engine.md:21 加注澄清，但这是 Claude Code 命名空间机制的固有现象、非缺陷。
