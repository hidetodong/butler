Decision Map 本地合同与确定性状态机

ITER-0103 迭代交付（小版本） 收口 2026-08-01

本次交付目标

把 Wayfinder 式依赖图、Frontier 与并行领取能力落成 Butler 的确定性本地状态 Module，同时避免把关键路由和状态转换交给模型临场判断。

已完成内容

  • 新增驻留工具 tools/decision-map/，对外只提供 inspect、plan、apply、verify 四个动作。
  • 为每张 Decision Map 建立单一原子状态、依赖 DAG、派生 Frontier、Fog graduation 和 Claim Lease 合同。
  • 用 revision、state digest、operation receipt、文件锁和原子替换保证并发、幂等与故障恢复。
  • 保持 R1 的单入口、opt-in 与显式 promotion 边界，并将 18 项专项测试接入完整 CI。

关键变更 / 用户可感知变化

  • 用户选择深入 Explore 后，可跨会话保存结构化 Map，并让多个 worker 在互不依赖的 Frontier 上领取决策工作。
  • 模型或 helper 只提交 operation spec；状态机判断转换是否合法，模型的清晰度、大小或置信度不决定 Map 生命周期。
  • 竞争、过期重领、旧 token、重复请求和写入故障都有确定性结果。
  • 本轮没有增加第二个入口，也没有实现 Milestone / Iteration promotion。

高层影响范围

  • 新增 tools/decision-map/ resident Module、CLI、合同文档和专项测试。
  • 更新 Ideation 真源、驻留工具部署说明、Coder / 项目 README、workflow 合同测试与完整 CI。
  • 没有新增 workflow registry ID、宿主命令、远端状态后端，也没有改变 Milestone / Iteration 的所有权。

验证方式与结果摘要

  • Decision Map 专项 18 项、Workflow 合同 12 项全部通过。
  • P5 同上下文风险复核：Must Fix 0、Should Fix 0；三项防御性细节修正后重新通过。
  • 完整 scripts/verify-ci.sh 在 Python 3.12.12 / uv 0.9.28 下 exit 0。
  • 四份 evidence 已归档并通过 archive verifier。

已知剩余风险 / 延后事项

  • applied_operations receipt 会随单张 Map 的操作数增长。
  • 只保证当前 macOS / Linux 本地文件系统；不覆盖跨主机和网络文件系统协调。
  • Claim token 是协调凭据，不是权限认证边界。
  • R3 research helper 与 R4 promotion 仍为 planned，必须由用户显式启动。
