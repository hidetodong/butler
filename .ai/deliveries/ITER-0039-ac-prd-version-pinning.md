# 给验收清单钉住 PRD 版本（改版后也认得当初对的是哪一版）

> ITER-0039 · 里程碑 MILE-0004 第四块（R4）· 收口 2026-07-09 · 监督态自驱（承 R1 契约 + R2 切分 + R3 入口；P5 起独立复核守质量）· 不切版（纯规则接线）

## 本次交付目标

- R1–R3 已经让"一份 PRD → 切成模块切片 → 挂进里程碑"跑通了，但所有指针指的都是"**当前最新**"的切片。真实项目里 PRD 天然会改版（V1.1→V1.2 修个校验规则），一旦改版，之前**已经验收过**的那条验收标准，当初对的到底是哪一版规格，就再也无从查证了。
- 本轮给验收清单（AC_LIST）**钉版**——"钉版"就是在验收标准冻结（你 ACK）的那一刻，把当时 PRD 的版本号记下来、之后**钉住不动**（哪怕 PRD 后来又改了好几版）。再把这个钉住的版本接进技术方案（P3）和验证报告（P5）：方案对着钉住版设计、**验收也对着钉住版核对，而不是对最新版**。这样"这条 AC 当初验收的是 V1.1 的规格"永远有据可查，也给下一块 R5 的改版同步铺好了地基。

## 已完成内容

- **验收清单顶部加一个可选字段 `prd_version`**（`acceptance-schema`）：当这个迭代引用了 PRD 切片时，它记下 ACK 冻结那刻 PRD 的**全局版本号**（一份 PRD 一个版本号，不给每个模块单独编版）。字段**可选**——不用 PRD 的普通迭代、对话驱动的迭代**根本不写这一行**，验收清单顶部一个字都不变。
- **版本号只记在一个地方**：引用某个切片时，锚点是"模块代号 + 顶部那个全局版本号"，但版本号**只存在顶部 frontmatter 一处**，正文里引用切片时不再逐条重抄版本号（解析时自动用顶部的补齐）——防止将来多处各写一个版本号、改出分歧。
- **接进三个阶段模板（P2/P3/P5）**：
  - **P2 验收**：写清楚冻结时怎么绑定、之后怎么钉住；迭代内小修（amend）重新走一遍 ACK 时，如果 PRD 期间恰好改了版，版本号**可以随重冻重绑到新版**。
  - **P3 技术方案**：引用 PRD 切片时版本**跟着验收清单走**（继承那个钉住的版本号），方案不自己另立一套版本。
  - **P5 验证**（本轮的核心兑付点）：核对 PRD 规格时**对着钉住的那一版核、不对最新版核**——同一个迭代里最新版通常就是钉住版（直接读就行）；只有回头复核老迭代（PRD 后来已经改版）时，才去翻当年冻存的旧版快照来核。
- **翻牌收口**：R1 契约文件里"钉版怎么记—属 R4"那两处待办指针，翻成"✅ 已落地"。

## 关键变更 / 用户可感知变化

- **用 PRD 开发的项目，验收从此可追溯到具体版本**：每条引用了 PRD 的验收标准，都钉着"我当初对的是哪一版"。PRD 后面改多少版，都不影响回头审计当年那次验收。
- **验收对的是"当初冻结那一版"，不是漂移中的最新版**：避免"AC 早就冻了、PRD 又偷偷改了、结果拿新规格核旧验收"的错位。
- **不用 PRD 的人完全无感**：`prd_version` 是可选字段，普通迭代的验收清单一字不变、机械门禁（hook）也没给它加任何校验——旧项目、旧清单照常放行。

## 已知剩余风险 / 延后事项

- **钉版协议就位、但要 R5 才首次实战兑付**：本轮只定了钉版"怎么记 / 怎么解析 / 怎么核"，还没有真正冻出旧版快照的动作——回头复核老迭代要读的 `.archive/vN/` 快照，得等 R5 的 `/prd update` 改版同步真跑起来才生得出。在那之前，钉住版永远等于最新版（同迭代内不改版），钉版的跨改版审计价值待 R5 兑现。
