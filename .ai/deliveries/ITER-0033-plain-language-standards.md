# 说人话三条硬标准 + 发长文前自检

> ITER-0033 · 迭代交付（小版本）· 收口 2026-07-07 · MILE-0003 R7 · 监督态自驱（用户点选 R7 + "继续"接力，非 /dangerous；P5 起独立复核守质量）

## 本次交付目标

- butler 一直在说"讲人话"，但这条纪律有两个漏洞：一是**只管四件套**（写在 `artifact-style` 里、适用面写死"四件套字段正文"，交付总结、知识文件夹这些同样给人读的文档不受管）；二是**对话框里没人管**（`presentation-protocol` 只管结构：结论先行、标号、表格，字词该怎么说人话完全没约束）。
- R7 把"说人话"收敛成**三条有名字的硬标准**，定义只写一次、扩到所有给人读的输出，对话层和文档层都守同一份。这是 MILE-0003 三条线里的最后一条（前两条知识文件夹、帮手名册已落），之后就是 R8 切版。

## 已完成内容

- **三条硬标准立起来（真源放 `artifact-style §2`）**：
  - **术语先解释**——术语 / 黑话 / 关键符号第一次出现，顺带一句话说清是什么；能用大白话替代的偷懒简写（如"护栏""正交"）必须换掉。
  - **比喻要落地**（全新）——用比喻帮理解时，得点明"像 X 的 Y"里的 X 到底对应本任务里的谁；接不回真实对象的悬空比喻，删掉直说。
  - **别让英文 / 变量裸奔**——英文术语、变量名、函数名、表名第一次出现，要么中文解释在旁、要么一句话点明它在本项目里是什么；字段名 / 编号 / 路径这类"锚点"除外。
- **适用面从四件套扩到所有给人读的文档**：`artifact-style` 的定位从"四件套字段正文"改成"所有面向人的落地文档"（四件套 + 交付总结正文 + 知识文件夹 + 会话交接等）；收口自检也从"只扫四件套"扩成"发任何长文档前都扫一遍三条"。
- **对话层引用同守、不另写一份**：`presentation-protocol` 新增一节，声明对话里的方案 / 分析 / 较长输出也守这三条——但只**指向** `artifact-style §2` 那份定义，不把三条再抄一遍（避免"对话一套、文档一套"以后各改各的、越走越偏）。
- **同步**：浓缩规则卡 `rule-card`、子系统入口 `README` 两处说明同步收录三条与新的适用面。

## 关键变更 / 用户可感知变化

- **以后所有给人看的输出都有一把统一的尺子**：不管是对话框里的方案、还是落进文件的交付总结 / 知识文件夹，都过同一份"说人话三条"。
- **"简短"不再等于交差**——把话砍短之后还得让不在你脑子里的人接得住，三条就是这句话的可执行清单，发长文前能逐条自检。
- **一处定义、多处引用**：三条只在 `artifact-style §2` 写一次，对话协议、规则卡、README 都只引用它，改一处全体生效。
