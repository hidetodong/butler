# 沟通风格正本瘦身：删掉它自己都在犯的毛病，例子和规矩一条没少

## 本次交付目标

仓根 `communication-style.md` 是走全局 `@import`、每个会话常开的个人语气正本。它讲「往短里写、别注水」，自己却攒了三类冗余：写给人看的元说明、三节之间重复的抽象规矩、以及「把话说顺」那节用三重转折说一件事的散文铺垫。

本次要在**规矩语义零改动、例子零删改**的前提下把这些删掉。目标不是省 token——压掉的量约 628 字节（≈200 token），相对本机插件与 MCP 的几万 token 开销可以忽略。真实目的是消除自我矛盾，并去掉规矩之间的互相稀释。

## 已完成内容

- `communication-style.md` 由 5381 B 压到 4753 B（-11.7%）：引言块删两处元说明；「抓重点」删与「结论先行」同义的首条；「把话说顺」引导段两句压成一句、四条规矩收紧措辞；「别急着抛选择菜单」去填充词。
- 九个小节全部保留、标题与顺序未变——**三节分立不合并**是用户在 P1 拍板的选择，代价是少省约 400 B，换来分类层次和可维护性。
- 「说人话」整节冻结，一字未动；7 行 ❌/✅ 例子逐字保留，953 B 分毫未减。
- 顺带修正一处既有漂移：`.ai/project/capabilities.md` 把本文件记作「8 节」，实际自 v2.10.0 加「把话说顺」后已是 9 节。
- 新增 `.ai/ITER-0097-clause-mapping.md` 条目去向对照表，原版每条内容的保留 / 并入 / 删除去向逐条可查。

## 关键变更 / 用户可感知变化

- **AI 的说话方式不变**。这次改的是规矩的表述密度，不是规矩本身。使用者不该感到语气或详略有任何变化——若感到了，说明改坏了，按剩余风险一节处理。
- **正本路径、文件名、`@import` 链路全部不变**，本机 `git pull` 后下个会话即生效，**无需重跑 `setup.sh`**。
- 唯一整条删除的规矩是「开头一句总览 / 最重要的判断，让我先看到大局，再分层」，它与「结论先行」同义；其独有的「再分层」已并入「结论先行」，没有丢。

## 验证方式与结果摘要

两条机器证据，均 `passed`，路径见下方引用。

- **例子与结构未被破坏**（`style-slim-checks`，覆盖 AC1/AC2/AC3/AC5/AC6/AC7）：脚本从 `git show HEAD` 取原版而非会话内快照，可独立重跑。7 行例子逐行 diff 零差异；9 个小节标题与顺序零差异；与 `artifact-style.md §2` 的六条概念映射锚词全部命中；体积 4753 B 落在验收区间；`capabilities.md` 记载值与实际节数相符；安装脚本与 `CHANGELOG.md` diff 为空。
- **条目没有意外丢失**（`clause-coverage`，覆盖 AC4）：用相似度阈值对两版规矩行做双向覆盖比对，原版 24 条中 23 条有对应，唯一整行消失的是白名单内那条，意外丢失 0、意外新增 0。

需要说清证据的边界：机器能证明例子没被改、结构没塌、链路没断、没有条目在无记录的情况下消失；**证明不了「被删的 12 处确实与他处重复」**，那部分由对照表交人复核，在 `VERIFY_REPORT.md` 里如实标为弱验证。

## 已知剩余风险 / 延后事项

- **AC4 的人判层未经独立复核**。语义等价判断由执行者自评加用户在汇报环节确认，没有 fresh-context 复核者重判。若日后发现某条被误判为重复，在新迭代补回，不追改本迭代归档。
- **措辞品味无机械判据**。改写后的句子是否读起来更好，只能由使用者在日常使用中反馈。
- **发现一处 butler 自身的规则不一致，本迭代未修**：`verify-schema.md §2` 把「人测道小结」列为条件必填字段，但 `tools/artifact-pipeline/artifacts.v1.json` 的 verify_report 段落清单不含该段，写进去会被结构检查判 `drift`。本迭代因 AC4 改判自动道而绕开，但任何真有人测残余的迭代都会撞上。建议另开迭代对齐两处真源。
- 本迭代过程中 AC5 的体积区间被修订过两次，第一次是错的（P3 下调后 P4 撤销）。这不影响交付结果，但说明「拿数字区间当验收项」不是好做法——真正管用的是 AC1 的例子零改和 AC4 的条目覆盖。
