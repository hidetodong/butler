# CONCEPT — ITER-0021

> 分流：完整路径 | 命中升级信号：契约级改动（测试纪律 + 验证回填口径）、多文件接线、跨阶段影响（P5 验证 ↔ 交付） | 2026-07-02 | MILE-0002 R1

## 一句话

`testing-strategy.md` 现在是"分层**建议**"（§2 建议措辞、§3 写"关键路径**手动**验证完成"），没有"能自动就必须自动"的硬纪律，UI / 交互容易随手推给人；且 `verify-schema.md` 的 `AC Status` 只记通过 / 未通过、**不分自动道 / 人测道**，人测残余无结构化落点。本迭代把测试纪律升级为**自动化优先（竭尽自动化，含浏览器自动化覆盖 UI / 交互）**，并在验证报告引入**双道口径**——每条 AC 显式标 auto / human 道，人测道界定为机器不可测残余。

## 背景与判断

- 里程碑归属：MILE-0002 路线项 **R1**（扁平原子，本迭代只做"纪律 + 分道口径 + 验证回填"）。
- 现状扫描：`testing-strategy §2` 用"建议"措辞、§3 列"关键路径手动验证完成"——默认人测是常态，与 MILE-0002"自动化最大化为硬纪律"相悖。
- `verify-schema` 模板 `AC Status` 无分道字段，人测结论 / 残余无处结构化沉淀。
- butler 有 Playwright 浏览器自动化能力 → UI / 交互本可进自动道；纪律必须显式把它们收回自动道，而非默认推人。
- 边界：分级置信（可靠 / 弱 / 待人）、代理验证（截图 diff / VLM 判图）、依赖感知准入 = **R2**，不在本迭代；本迭代只立"两道 + 自动优先"骨架。

## 目标（Goal）

- G1：`testing-strategy.md` 从"分层建议"升级为"**自动化优先**"硬纪律——凡机器能测的必须自动化（含浏览器自动化覆盖 UI / 交互、可编程视觉断言），"关键路径手动验证"改为"默认自动、人测是例外残余"。
- G2：定义**分道口径**——自动道（butler 跑）/ 人测道（机器不可测残余）的判定标准，明确什么才允许落人测道。
- G3：`verify-schema.md` VERIFY_REPORT 增**分道回填**——每条 AC 标 lane（auto / human）+ 人测道结论 / 残余的结构化字段。
- G4：接线与指针同步（README 两文件描述、rule-card 裁决、PROJECT.md 按需前滚）。

## 约束（Constraints）

- 原子迭代：只做纪律 + 分道口径 + 验证回填；**不做**分级置信 / 代理验证 / 依赖感知准入（R2）。
- 不改 P1-P5 状态机、四件套字段脊柱、AC 验收脊柱；verify-schema 只**加**分道字段，不重构既有必填字段。
- 不动 hook 代码，不新造校验器。
- 「交付自测」桥工具是 R3——本迭代只定"人测道"概念与回填格式，**不实现桥**。
- 守本仓五约束（分层 / 产物链 / 无隐式依赖 / 模板单一来源 / audience 标注）。

## 影响范围（Impact Scope）
