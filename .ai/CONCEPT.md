# CONCEPT — ITER-0097 · 沟通风格正本瘦身：砍冗余留例子，守 artifact-style 四条对齐

分流: 完整 | 命中升级信号: 设计取舍、跨模块影响 | 2026-07-30

## Current Understanding

- **一句话**：仓根 `communication-style.md` 是走全局 `@import`、每会话常开的个人语气正本，现在 5381 字节 / 61 行。它有一部分内容是纯冗余——写给人看的元说明、三节之间重复的抽象规矩、以及「把话说顺」那节自己都在犯自己毛病的散文铺垫。本迭代把这些删掉，四组 ❌/✅ 例子一条不动。
- **Goal**：在不改任何一条规矩语义、不删任何一组例子的前提下，去掉正本里的冗余表述，让"讲简短"的文件自己先不啰嗦。
- 省 token 不是目的。压掉的量约 975 字节（≈320 token），相对本机几万 token 的插件与 MCP 开销可以忽略。真实收益是消除自我矛盾（一份讲「别注水」的文件自己注水）和降低规矩之间的互相稀释。
- 现状分布：说人话 1006 B、把话说顺 1664 B（占 31%，全文最长）、引言块 431 B、基调/详略/抓重点合计 766 B、别急着抛选择菜单 611 B、格式 162 B、结尾决策块 511 B、边界 230 B。
- 冗余集中在三处：① 引言块的元说明（「唯一正本」「随 butler 仓走」「经 setup.sh 的 @import 每会话常开、跨机器同步」）对执行零贡献，只对人有意义；② 基调 / 详略 / 抓重点三节互相重复（「结论先行」≡「开头一句总览」，「往短里写」≡「结论 + 关键理由」）；③「把话说顺」开头两句散文铺垫用三重转折说一件事，本身就是它批评的写法。
- **有先例**：v2.6.1 做过同类收紧（77→51 行，约减三分之一），当时走**简化路径直改、未领迭代号**，semver 取 PATCH，`migrations/v2.6.1.md` 为 `[no-op]`+`[restamp]`。本迭代性质相同，但用户明确要求领号走完整路径。
- 预研已完成一版试压稿（会话 scratchpad，非仓内产物），实测 5381 → 4406 B（-18% / -7 行）。**先前对话里"能砍四成"的估计是错的**——那个数字没把例子体积算进去；四组「说人话」例子加两组「把话说顺」例子约占 1.4 KB，而它们正是必须保留的部分。

## Scope

- **In Scope**：只改仓根 `communication-style.md` 一个文件的正文表述。
- **Out of Scope**：不改任何一条规矩的语义；不删、不改写任何一组 ❌/✅ 例子；不新增规矩；不动 `scripts/setup.sh` 与 `@import` 路径（正本路径不变、无需重跑安装脚本）；不动 `templates/`、不下发目标项目。
- **显性约束（硬）**：`Coder/20_Workflow_Lifecycle/artifact-style.md` §2 把本文件定性为"走用户全局通道、对话时须自足的个人语气副本，不归本体系约束"，但要求**内容须与该节对齐**——概念映射为「说人话」四条 ↔ 标准一/二/三（自造缩写归标准一），「把话说顺」里的反翻译腔 ↔ 标准四，「流畅优先于省字」↔ §3「反啰嗦 ≠ 砍成电报体」。压缩不得打破任何一条映射，否则形成双正本漂移。
- **隐性约束**：本文件的「边界」节禁止它引用 butler 内部文件（ITER-0071 交付已确认此边界），所以对齐只能靠内容一致，不能靠加指针；文件必须对话时自足。
- **影响范围**：改动生效面是本机及任何装了 butler 的机器上**所有项目的所有会话**（全局 @import），但生效方式是 `git pull` 后下个会话自动读到，无需机器级动作。目标项目的 `.ai/` / `deliveries/` / `origin/` / `CLAUDE.md` / `.claude/hooks/` 零结构影响。
- **需同步的仓内引用**：`.ai/project/capabilities.md` 与 `HUMAN_GUIDE.md` 描述了本文件的节数（现记为 8 节）；若节数因合并而变化，需一并对齐，否则知识文件夹漂移。
- **项目类型**：Markdown 规则仓，无 Domain / Stack Profile 命中，仅按通用 SOP 与文档写作口径推进。

## Open Questions / Risks

- **待 P2 定的取舍**：基调 / 详略 / 抓重点三节是合并成一节六条（省约 400 B，但丢掉分类层次、日后改某类规矩要在六条里找），还是保持三节分立只做去重（省约 700 B 中的一部分，保住可维护性）。这直接决定最终体积和 `capabilities.md` 里"8 节"的表述是否要改。
- 风险：压缩是主观判断，"哪句是冗余、哪句是必要的喘息"没有机械判据。缓解办法是把「例子零删改」和「与 artifact-style §2 四条映射不破」做成可机械核验的 AC（例子对数计数 + 概念映射逐条比对），把主观部分限制在非例子正文。
- 风险：本迭代收益量小（≈975 B / 320 token），却要走完整五件套 + 交付双格式 + 证据归档 + 知识折叠 + 收口自检。投入产出比明显偏低，属于用户明确选择的流程档位，不是流程判定的必然结果；若用户改主意可随时降到简化路径（`lifecycle.md §2.2`），已开的 ITER-0097 按 §5.6 废弃或直接收口。
