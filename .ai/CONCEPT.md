# CONCEPT — ITER-0022

> 分流：完整路径 | 命中升级信号：跨模块（verify / testing / dangerous）、契约级（置信档）、跨阶段（P5 ↔ 无人自治） | 2026-07-02 | MILE-0002 R2 | ⚠️ 危险模式（P4 起自治；P2/P3 自审门自 ACK）

## 一句话

R1 立了"自动道 / 人测道"两分道，但只有二值（能自动 / 不能自动），缺"自动到什么程度"的**置信刻度**；也没说清"本来要人看的项怎么用弱自动检查顶上"；更没定义"**无人值守时人测残余怎么办**"（会永久阻塞、或被草率假绿）。R2 补三件耦合的事：① **分级置信**（可靠 / 弱 / 待人）② **代理验证**（截图 diff / VLM 判图等弱但真实的自动检查，把感知项从人测道拉回自动道·弱档）③ **依赖感知准入 + 无人残余处置**（卡下游不许无人跑、残余异步入账不阻塞、绝不假绿）。

## 背景与判断

- 里程碑归属：MILE-0002 路线项 **R2**。承 R1（分道口径）——R1 给"哪条道"，R2 给"多大把握 + 怎么提高把握 + 没把握时无人怎么办"。
- 现状：R1 后 `verify-schema` 的 lane 只有 `(auto)`/`(human)` 二值；`testing-strategy §3` 说了"默认归自动道"但没给"本来要人看的怎么变自动"的手段；`dangerous-engine` §8 只处理 P4 熔断，**没处理人测残余在无人值守下的永久阻塞**。
- 预研依据：`docs/research/MILE-0002-dangerous-mode-human-test-resolution.html`（三根承重柱 + 红线）已把方向掰清。
- 三件事耦合：代理验证产出"弱"置信、分级置信给它命名、依赖感知准入据置信决定无人时能否推进——同一迭代内闭环最自然，不拆。

## 目标（Goal）

- G1：**分级置信**——`verify-schema` 分道回填在 lane 上加置信档 `可靠 / 弱 / 待人`（可靠=确定性断言、弱=代理验证、待人=机器不可测残余），如实记录、可审计。
- G2：**代理验证**——`testing-strategy §3` 补：对感知 / 主观类项造"弱但真实"的自动检查（截图对基线 diff、VLM 判读截图、启发式断言），earned `弱` 置信、留在自动道；进一步压缩人测道。
- G3：**依赖感知准入 + 无人残余处置**——`dangerous-engine` 补：无人值守下人测残余不阻塞（异步入欠债账、人有空再清）、卡下游的未验项不许硬闯（弱验证顶 / 砍分支 / 该迭代不具准入资格）、**红线绝不假绿**。
- G4：接线与指针同步（rule-card 按需、README / HUMAN_GUIDE dangerous+verify 描述、PROJECT 前滚）。

## 约束（Constraints）

- 承 R1 不推翻：分道二分（自动 / 人测）不变，R2 只在其上叠置信档，不重构 R1 的 lane 字段。
- 「交付自测」桥（有人值守的残余回传）= R3，本迭代**不实现桥**；R2 的"无人残余处置"专指 `/dangerous` 无人场景（异步入账），与 R3 有人场景互补。
- 不改 P1-P5 状态机、四件套字段脊柱、AC 验收脊柱、hook 代码。
- 红线：绝不写假 verified——分级置信如实标档，`弱` 不冒充 `可靠`、`待人` 不冒充已验。
- 守本仓五约束。
