# MILESTONE — MILE-0008 · Butler 目标可信闭环

> 方向性产物（非冻结、不走 ACK）。本里程碑不追求让 AI 口头声称“100% 有把握”，而是让 Goal 的完成资格可定义、可反证、可复核：方案未通过、问题未回流、证据不足或仍有阻断项时，Goal 不得标记完成。

## 5.1 范围评估

**In Scope（版本级）**

- **目标语义与层级对账**：盘点 Butler 当前散落在 milestone、危险模式北极星、迭代 Goal、AC、task-state、handoff 与宿主原生 goal/task 工具中的目标概念，明确各层职责、状态和单一真源，消除“任务项做完 = 总目标完成”的偷换。
- **Goal Contract**：为非极小任务定义最小目标契约，至少包含预期结果、成功条件、非目标、约束、证据义务、未决风险和与 AC / 路线项的映射；目标只管结果，不复制 AC、方案或任务清单正文。
- **方案准入与反证**：技术方案进入执行前必须经过结构化自审，主动寻找遗漏约束、失败路径、替代方案、影响面和验证盲区，并产出明确的 `pass / revise / blocked` 判定；`revise` 或 `blocked` 时不得靠措辞自我放行。
- **执行中目标校准**：把新发现的问题、假设失效、范围漂移、验证失败和审查意见回流到 Goal → AC → Plan 的正确层级；任务清单完成但目标条件未满足时，自动重规划、修订或诚实停机。
- **完成资格与证据审计**：Goal 只有在 AC 覆盖、机器证据、审查结论、剩余风险和交付状态一致时才能标记完成；Must Fix、未验证关键项、未处置阻断风险或方案判定未通过时机械拒绝完成声明。
- **双宿主适配与回归**：共同目标协议留在 Butler 内核；Claude Code 与 Codex 只做薄适配，覆盖 Codex goal 生命周期、Claude 任务载体、跨会话恢复、危险模式自治以及不支持原生 goal 工具时的诚实降级。

**Out of Scope（版本级）**

- 不承诺 AI 能获得数学意义上的“100% 正确”或消除所有未知风险，不用虚构置信百分比替代证据。
- 不用 Goal 取代 milestone、iteration、AC、TECH_PLAN、task-state 或 VERIFY_REPORT；本轮只明确它们的层级关系与完成门。
- 不把所有极小任务强制升级成完整 Goal 文档，不为一次性单轮修改制造额外台账负担。
- 不把自审包装成独立复核；没有 fresh-context 验证者时必须如实标注审查强度。
- 不扩张 Codex/Claude 宿主本身未提供的底层能力，不假设两端拥有完全相同的 goal API。

**关键交付目标**

- 任一 Goal 都能回答：要达成什么、凭什么算达成、当前为何仍未完成、下一步该回到哪一层修正。
- 方案自审有明确判定和失败原因；未通过的方案不能进入执行或被 Goal 完成动作掩盖。
- “所有任务已勾选”不再单独构成完成依据；完成声明必须引用 AC、验证证据和审查结论。
- 执行中发现问题后有确定的回流路径，不再出现 AI 知道方案有问题却仍沿原计划做完并宣布 Goal 完成。
- Claude/Codex 对同一项目读取同一份目标状态，宿主适配差异不会分裂出两套 Goal 真相。

## 5.2 理解阐释

- **核心问题**：Butler 已经能要求 AI 完成 P1–P5、留下 AC 和验证证据，但“Goal”仍更像一个推进指针。AI 可能把计划任务全部执行完并更新为 complete，同时自己的复盘已经发现方案不够稳、存在遗漏或需要返工。当前规则对“完成了动作”和“达成了结果”的区分还不够机械。
- **问题本质**：缺的不是更多鼓励模型认真思考的提示词，而是一条闭合的目标控制回路：先定义结果与完成资格，方案必须过准入，执行中持续校准，最后由证据和反证审查裁决是否允许完成。任何一环失败都要回流，不能只在最终报告里留一句风险。
- **版本价值**：把 Goal 从会话级意图或宿主任务状态，升级为跨阶段、跨会话、双宿主共享的可审计承诺；降低长任务“看起来做完、其实方案自己都不认可”的假完成率。
- **整体影响**：预计涉及 `identity` / `lifecycle` / `acceptance` / `tech-plan` / `verify` / `review` / `context-persistence` / `dangerous` 等共同规则，以及 Codex skills、Claude commands、模板入口、状态审计器和验证 fixture。具体落点必须在 R1 盘点后收敛，避免先复制新 schema 再制造第二套真源。
- **主要风险**：目标层若与 AC、里程碑和 task-state 重复，会增加文档税并产生漂移；自审门若只有散文要求，会再次退化为口头“已检查”；门槛若无风险分级，会让普通小任务过度流程化。因此设计必须坚持最小契约、分层引用、明确状态机和可执行检查。
- **待澄清但不阻塞开板**：这里暂按“目标体系”同时覆盖 Butler 的跨阶段 Goal 语义与 Codex/Claude 的宿主目标载体理解。R1 会先做能力与失败样本盘点；若你特指 Codex 某个 Goal UI/API，再在范围演进记录中收窄宿主适配面。
