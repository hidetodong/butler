# butler · 项目知识文件夹

butler 是一套面向 AI 辅助工程开发的通用协作 SOP **规则仓库**（全是 Markdown）。它规定 AI 接手工程任务时怎么走一遍"分析 → 验收 → 设计 → 执行 → 验证"，并把每一步的产物结构化落盘，让协作可追溯、可审计、能跨会话从零恢复。使用者：用 Claude Code 等 AI 编程的开发者。**注意：编辑本仓 = 改规则本身，不是拿规则去开发别的软件。**

## 读序 / 地图

冷启动（AI 从零接手、没有任何上下文时）建议这样读：

1. 先读本文件（`00_INDEX`）拿全貌 + 地图。
2. 按手头任务需要，钻下面主题登记表里相关的那几份——**读地图、再定向钻取，不要一次全 slurp**。
   - 想知道"这是什么、边界在哪" → `identity`
   - 想知道"有哪些模块、各管什么" → `architecture`
   - 想知道"现在能做哪些事（命令 / SOP / 工具）" → `capabilities`
   - 想知道"哪些是不能碰的长期决策" → `invariants`
   - 想知道"有哪些硬约束" → `constraints`
   - 想知道"哪里还欠着" → `debt`
   - 想知道"当前在攻什么、下一个瓶颈" → `frontier`
3. 再读 `.ai/ITERATIONS.md`（一步步怎么走到今天的时间线）、`.ai/MILESTONE.md`（当前大版本圈了什么）、`.ai/task-state.md`（现在卡在哪）。
4. 最后按各主题里的指针钻进代码 / 规则真源。

## 主题登记表

| 主题文件 | 管什么 | 边界 |
|---|---|---|
| `identity.md` | 定位 / 目的 / 使用者 / 边界 | 只讲"是什么、给谁、不做什么"，不讲怎么实现 |
| `architecture.md` | 模块地图：每层每个模块管什么 + 成熟度 + 真源指针 | 只摘全貌，目录树 / 分层细节指 `Coder/README.md`、不抄 |
| `capabilities.md` | 现在真能做哪些事：命令 / P1–P5 SOP / 驻留工具 | 只列现状能力 + 指针，引擎正文指各扩展模块 |
| `invariants.md` | 关键长期决策与不变量（含"为什么"） | 只放跨迭代仍成立的硬决策，不放一次性变更 |
| `constraints.md` | 现行约束（写作 / 流程 / 版本 / 测试的长期边界） | 只放长期边界，实现细节指对应 schema |
| `debt.md` | 已知长期欠债 | 只放悬着没还的账，已还的删除不留 |
| `frontier.md` | 当前形态 / 活跃战线 / 下一个瓶颈（变得最快的一层） | 随迭代刷新，旧战线收了就覆盖删除 |
