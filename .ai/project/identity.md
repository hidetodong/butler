# identity（定位 / 目的 / 使用者 / 边界）

## 是什么

butler 是一套**通用协作 SOP 规则仓库**（纯 Markdown，无运行时代码逻辑，只有少量驻留工具）。它定义 AI 接手一个工程任务时怎么分析 / 验收 / 设计 / 执行 / 验证，并把过程产物结构化落盘，使协作**可追溯、可审计、可跨会话从零恢复**。

## 给谁解决什么问题

- **使用者**：用 Claude Code 等 AI 编程助手做工程开发的开发者。
- **解决的问题**：AI 单轮对话容易"断片"——换一个会话就忘了上一轮干到哪、为什么这么设计。butler 把状态外化成磁盘产物（四件套 + 台账 + 知识文件夹），让 AI 冷启动也能读懂现状接着干，不靠对话记忆。

## 边界（不做什么）

- **不是**开发框架 / 脚手架 / 代码库——它不帮你写业务代码，它规定"写代码的过程怎么走"。
- **编辑本仓 = 改规则本身**。在 butler 仓里干活是在改协作 SOP，不是在用这套 SOP 开发别的软件（这条极易混淆，见 `constraints.md`）。
- butler 把自己的规则**部署**到目标项目（叫"基地车部署"）后，目标项目才是"用规则开发软件"的现场。
