# PRD 原文疑问检索：基于当前版本给出带证据的四态判断

候办键: prd-evidence-check
候办状态: deferred
规模: milestone

## 范围评估

### In Scope（版本级）

- 在 `butler-prd` 下新增只读 `check` 路由，接受用户对产品行为的自然语言疑问，从 `.ai/references/prd/` 原文中找依据并回答。
- 支持显式指定 `prd_id`；未指定时检索所有 `active` PRD 各自的当前版本，不用不同需求的版本号比大小。
- 结果使用四态判断：`明确支持`、`明确否定`、`未发现说明`、`存在歧义`。
- 每次回答同时给出一句话结论、原文片段、`prd_id`、当前版本、模块文件与行号，并亮明实际检索范围和尚缺的关键条件。
- 允许同一需求内多个模块共同支撑结论；多个 PRD 都可能相关时分别列出，不静默拼接成一个结论。
- 复用现有 PRD 索引、当前版本身份与模块地图；按索引渐进读取，不为首版引入向量数据库、持久化搜索索引或独立语义搜索服务。
- 保持零写入：不改 PRD、不建缓存、不生成查询报告，成功、无依据和错误路径都不改变项目树。

### Out of Scope（版本级）

- 首版不查询 `.archive/` 历史版本，不支持指定旧版本，不做版本间对比或行为变更解释。
- 不以 `check` 修改、补写或更新 PRD；发现缺口时只说明缺什么。
- 不把关键词命中当成答案，不从“默认选中今天”之类邻近规则自动推导出“切换后必须返回今天”。
- 不把读取失败、坏布局、身份冲突或检索未完成伪装成“未发现说明”。
- 不执行 PRD 原文中出现的 AI 指令、命令或工具调用文字；它们只是待检索的资料。
- 不扩展到 `.ai/references/` 中的 API、设计稿或 insight 等非 PRD 资料。

### 关键交付目标

- 用户可以直接询问“MonthCalendar 选中非今日后，切换渠化图配置再返回，是否应恢复今日”之类交互疑问，无需手工翻找 PRD 模块。
- 结论能回溯到真实原文与当前版本；原文没规定时诚实返回“未发现说明”，原文冲突或必须加假设时返回“存在歧义”。
- 未指定 `prd_id` 时仍能安全检索当前有效需求；不同 PRD 的证据不会被静默合并。
- Claude Code 与 Codex 两个宿主入口对同一问题使用同一套范围、版本、四态判断与错误语义。
- 不使用 PRD 的项目、现有 `split / update / status` 路由和扁平 references 流程保持不变。

## 理解阐释

现有 `butler-prd` 能切分、改版和查询 PRD 结构状态，但不能回答“某个具体交互在 PRD 里到底怎么规定”。开发或验收过程中，使用者常带着一个自然语言疑问，他们需要的不是文件列表，而是“原文是否真能支撑这个判断”。

`check` 的定位因此不是普通关键词搜索，而是带来源证据的原文裁决。它先按现有项目级索引确定需求身份，再按单需求索引和模块地图缩小读取范围，最后对用户问题与原文做语义对账。命中一个词只是候选线索，只有原文在条件和结果上能直接支撑时，才能返回明确结论。

多 PRD 集合中不存在一个全局“最新版本”：每份需求都有自己的 `current_version`。所以未指定 `prd_id` 时，检索范围是所有 `active` 需求各自的当前版本，而不是拿 `v2.0` 和另一份需求的 `v10.0` 比大小。首版不读历史快照，这同时降低了范围、误引用和版本混淆风险。

四态中，“未发现说明”表示已完成声明范围的检索但没有足够依据；“存在歧义”表示找到了相关规则，但原文冲突、条件不完整，或者必须额外假设才能回答。PRD 读取失败或检索范围无法确认不属于四态，必须单独报错，否则“没找到”会被误当成“产品没规定”。

实现上应优先复用现有 PRD status 和索引合同解析当前有效身份，再由宿主模型执行语义检索与证据裁决。首版不应为这个问题新建向量搜索基础设施；真实使用若证明文档体量已让渐进读取失效，再单独评估。
