# AI 用户体验驱动迭代：从结果目标到黑盒体验、修复与复验

候办键: ai-user-experience-driven-iteration
候办状态: deferred
规模: milestone

## 范围评估

### In Scope（版本级）

- 把“在期限内让某类用户完成某个结果”作为体验目标，而不是预先给定功能清单；目标至少说明用户画像、任务、时间预算、成功量规、运行环境与授权边界。
- 让 fresh-context Agent 仅通过对外产品界面和用户文档执行冻结任务，以黑盒方式模拟目标用户；体验阶段不得读取源码、内部实现说明或开发态捷径。
- 在关键路径布置轻量探针，记录耗时、卡点、回退、重试、求助、错误状态和结果与原始意愿的偏差，并把观察事实与修复建议分开。
- 将可复现的体验卡点转成候选修复；普通监督场次只报告证据和建议，已获得明确自治授权时才允许在既有写入范围内修复，不由本能力隐式开启 Dangerous 或 Loop。
- 冻结体验任务、探针和成功量规，由未参与实现的 fresh-context 体验者复跑，对比修复前后结果，防止实现者通过改口径证明自己成功。
- 先在一个真实发布目标上用现有 Agent、浏览器能力、Butler 迭代与旁路回执完成低成本 dogfood，再根据重复性、有效性和成本决定是否产品化。

### Out of Scope（版本级）

- 不宣称单个 AI 体验者等价于真实小白用户，也不替代真实用户研究、可用性测试或产品负责人判断。
- 不建设通用多 Agent 调度平台、画像生成平台或长期遥测系统；没有 dogfood 证据前不新增状态机、命令或强制产物。
- 不允许体验者在模拟用户阶段读取源码，不允许实现者修改冻结任务、探针或成功量规来获得通过。
- 不让模型自主决定产品定位、重大交互取舍、兼容性破坏或授权范围外改动；此类发现只形成带证据的决策输入。
- 不把该能力与 Dangerous、Loop、Review 或 Preference 绑定；它们分别承担授权、自主执行、高强度收敛、审查和真人偏好学习，按各自激活条件独立生效。

### 关键交付目标

- 在真实产品任务中证明 AI 黑盒体验能发现当前需求讨论、测试和代码评审没有暴露的可复现卡点。
- 对被修复的卡点，冻结场景上的体验指标确有改善，并可由未参与修复的体验者重复验证，而不是只产出主观评价。
- 对照少量真人体验或产品负责人复核，识别 AI 体验的有效发现、误报和代表性边界，形成是否继续产品化的 go / no-go 依据。
- 若验证不成立，以一次 dogfood 和结论收口，不为沉没成本继续建设；若成立，再以最小合同接入 Butler，保持现有 P1→P5 与 Goal 真源不分叉。

## 理解阐释

Butler 当前主要保障“把已经提出的需求可靠地做完”：从概念、AC、方案到实现和验证均有稳定产物链，但需求是否来自真实使用、是否能让目标用户更顺利完成任务，仍主要依赖人在上游给出。这个候办探索的是另一条输入路径：用户只冻结结果目标和边界，AI 先作为受限用户实际体验产品，从可观测事实中发现卡点，再把修复和复验钩回正常迭代。

它的潜在价值很高，因为最小闭环从“功能 → 实现 → 测试”提升为“用户结果 → 黑盒体验 → 卡点证据 → 修复 → 独立复验”。同时核心假设尚未被证明：AI 可能无法代表小白，可能把模型偏好误当用户痛点，也可能在体验、实现和自评同源时形成自证循环。因此本方向的第一交付不是新框架，而是一场可失败的真实 dogfood；只有收益和重复性超过现有流程，才进入产品化。

该方向与现有能力保持正交：体验驱动负责发现和验证需求价值；Dangerous 只决定是否让渡过程把关；Loop 仅在用户显式开启时进行高强度纠错；旁路回执可在 MVP 中承载体验结果，但不承担自动扫描、审批或调度。

## 拆分路线图

预计 3 个迭代承接；后续路线仅在前一阶段的 go 判定成立时继续，实际迭代号在启动时绑定。

| 路线项 | 主题 / 范围切片 | 实际 ITER | 状态 |
|---|---|---|---|
| R1 | 零基础设施真实 dogfood：冻结一项发布体验目标，使用现有工具组织多个 fresh-context 黑盒体验、探针记录、旁路回执和独立复验，并与少量真人/产品判断对照，形成 go / no-go 报告 | — | planned |
| R2 | 最小体验合同与证据：仅在 R1 通过后，定义体验目标、冻结场景、探针记录、卡点证据和修复前后对比的最小落盘结构，复用现有 P1→P5、evidence 与 Goal | — | planned |
| R3 | Butler 接线与边界验证：接入监督报告和已授权自治修复两种路径，验证 Dangerous/Loop 正交、体验者与实现者隔离、失败诚实收口及真实项目重复收益 | — | planned |
