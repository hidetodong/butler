# CONCEPT — ITER-0118 · /butler:inbox 命令与工具实现（MILE-0016 R7）

## Current Understanding

R6 把「闪念 → 孵化 → 执行」三层的数据形态定死了，但那份契约现在**一个使用者都没有**。R7 要做的就是把它接上电：`/butler:inbox add | list | handle` 三个动作，加一份确定性工具，再用真实使用跑一遍。

开工前核查出五件事，其中三件会直接改变本轮的做法。

**一、命令名必须复用现有的 `inbox`，不能新开一个 id。**

`workflows/registry.json` 有 12 个工作流，`scripts/sync-workflow-registry.py` 里写死了一个 `EXPECTED_IDS` 集合逐个核对。新开一个 id 会把工作流数推到 13，而**三份人读文档里的工作流个数是散文写的、没有任何机器兜底**（这条已经躺在 `.ai/debt.md` 里）。复用 `inbox` 这个 id 则计数不变，只需要改注册表里那个条目的字段、重写命令与 skill 的正文、再重跑一次投影生成。路线项本身写的也是 `/butler:inbox add | list | handle`，同名重造正是里程碑的原意。

**二、复用 id 就绕不开动 `test_inbox_workflow.py`——而那正是 R6 明确不碰的东西。**

那份 41 行的测试钉着三件事：注册表里 inbox 条目的 `rule_source` 必须**恰好等于** `Coder/40_Context_Management/inbox-workflow.md`；命令薄壳与 Codex skill 的正文里必须出现 `inbox-workflow.md` 和 `origin/` 这两个字样；外加旧规则文件本身的 8 个分类等内容断言。

新命令不扫 `origin/`——里程碑范围里明写「不做隐式 inbox 扫描，不扫 `origin/`、不扫对话历史」。要让测试继续绿，只能在新命令正文里留着 `origin/` 这个词，那就是写一句假话。所以本轮必须把这份测试**拆开**：描述**活接线**的两个用例（注册表指向哪、薄壳读哪份规则）跟着命令走，改指新契约；描述**旧规则文件内容**的那个用例原样留着，等 R8 连同文件一起删。R6 的 AC 里写的「不动这两份 hook 测试」是 R6 自己的边界，不是永久禁令；R7 动它是路线图分段的必然结果，要在范围演进记录里说清楚。

**三、执行分流的两条出口在本轮的 butler 仓上跑不通——这是契约的前置条件，不是缺陷。**

`intake-schema.md §3.1` 定的三条出口里：「提升为里程碑」要求当前没有 active 里程碑，而 MILE-0016 正 active；「开为迭代」要求当前没有 active 迭代，而 ITER-0118 正 active。也就是说本轮在 butler 仓上真实能跑到的只有 `new → incubated`、`new → dropped`、以及 `incubated → dropped`（撤回）。

这件事必须在验收标准里写成明确边界，不能含糊地说「跑通一条闪念到执行」然后拿一次半程当交付。可行的做法是分两处：**butler 仓上跑真实的中间层**（记一条真闪念、孵化成真草稿），**沙箱项目根上跑被挡住的两条出口**（造一个没有 active 的临时项目根，把 `提升` 与 `开为迭代` 各走一遍）。沙箱那半是真实执行但不是真实需求，两者的性质差别要在验证报告里分开写。

**四、旧 inbox 链在 butler 仓里从来没被真实用过——本轮不存在存量数据要迁。**

实测：仓库根没有 `origin/` 目录（既不在磁盘上也不在 git 里），`.ai/INBOX.md` 也不存在。`mcv-deployment.md` 写的是部署阶段只建目录、`INBOX.md` 首次运行收件箱动作时才产生——从没运行过。所以新命令第一次写 `.ai/INBOX.md` 就是建一个全新文件，不需要读旧格式、不需要就地迁移。已部署的**其它**项目另说，那条义务 R6 已经登记进 `.ai/debt.md` 归 R15。

**五、`handle` 的一次写盘要动三个地方，而其中两处的现行流程是模型手工做的。**

按契约，把一条闪念孵化成草稿要同时做三件事：回写闪念行的状态与去向、写 `.ai/milestone-backlog/<候办键>.md`、在 `.ai/MILESTONES.md` 待办区追加一行索引。后两件正是 `milestone-schema.md §7.6`（暂缓入库）现在描述的流程——**由模型按文字步骤手工执行**。本轮让工具确定性地做，是新增能力，必须与 §7.6 对齐口径而不是另立一套写法，否则同一件事就有了两条互不知情的实现路径。

契约还要求这三处**两侧原子**（草稿与索引行同生同灭）。现成的兜底是审计里的 `milestones.backlog_set` 断言（索引行集合必须等于目录里的文件集合），漏写一侧下次审计就红——但那是事后发现，工具本身要保证写一半不落盘。

## Scope

**In Scope**

- **确定性工具** `tools/intake/`：承担全部文件读写与校验，模型不直接编辑 `.ai/INBOX.md`。
  - `add`：追加一条闪念（生成日期化闪念键、撞名退让、状态 `new`、去向 `—`），文件不存在时按契约建表头。
  - `list`：只读列出闪念与孵化区条目，支持按状态与规模筛选。
  - `handle`：执行一次合法状态转移，并按目标出口联动写盘；非法转移一律拒绝并给出原因。
  - 全部写操作先做契约校验（枚举合法性、闪念键唯一、两侧原子），任一校验不过就整次不落盘。
- **命令层重写**：`.claude/commands/butler/inbox.md` 与 `plugins/butler/skills/butler-inbox/SKILL.md` 两份薄壳改为读 `intake-schema.md`、调用新工具；注册表 inbox 条目的 `rule_source`、描述与语义触发词同步更新，并重跑投影生成。
- **动作层规则**：新增或改写一份动作层规则文件，定义三个动作各自的语义边界——什么归工具确定性决定、什么必须问用户、`handle` 的分流决定怎么做出来。
- **拆分 `test_inbox_workflow.py`**：活接线的两个用例改指新契约与新工具；旧规则内容的用例留到 R8。
- **与 `milestone-schema.md §7.6` 对齐**：让 §7.6 指向工具而不是继续描述手工步骤，避免同一件事两条实现。
- **真实 dogfood**：在 butler 仓上用新命令记一条真闪念并孵化成真草稿；在沙箱项目根上把被 active 挡住的两条出口各跑一遍。
- 在 `Coder/README.md` 注册新规则文件；`.ai/MILESTONE.md §5.4` 登记本轮的定序处置；`.ai/debt.md` 按实际情况增减。

**Out of Scope**

- **不删旧链**。`inbox-schema.md`、`inbox-workflow.md`、`tools/inbox/`、`test_inbox_contract.py`、SRC-NNNN、双指纹、scanner 全部留着，退役归 R8。本轮只是让活接线不再指向它们。
- **不改目录名**。`.ai/milestone-backlog/` 到 R9 才改，工具按现实路径写。
- **不做隐式扫描**。不扫 `origin/`、不扫对话历史、不做内容指纹认亲——里程碑范围明写不做，契约也没定义这些。
- **不写迁移配方**。已部署项目里旧格式 `.ai/INBOX.md` 的迁移归 R15。
- **不动 `.ai/MILESTONES.md` 的正式表**，也不改待办区的列结构（R6 已定索引不承载规模）。
- 不切版、不发布、不提交。

## Open Questions / Risks

- **`handle` 的分流决定由谁做出来。** 工具能校验转移合法、能原子写盘，但「这条闪念该孵化还是该丢」是判断。倾向是工具只接受已经定好的目标态、由命令层负责问用户，但这样 `handle` 就退化成一个写盘器、名字有点名不副实。P3 定。
- **孵化区草稿的正文谁来写。** `iteration` 与 `undecided` 档各要两段，`milestone` 档要四段。工具能生成骨架，但内容是语义的。骨架由工具产、内容由模型填，中间的交接点在哪，P3 要定死，否则会出现「工具写了个空壳、模型以为已经写好了」。
- **沙箱 dogfood 算不算数。** 两条出口只能在没有 active 的项目根上跑，那必然是个造出来的临时环境。它证明得了「代码路径通」，证明不了「真实使用下好用」。这个折扣要在验证报告里明说，不能混进「真实 dogfood 已完成」一句话里。
- **风险 · 动 `test_inbox_workflow.py` 会不会提前引爆 R8。** 拆用例时如果连带改了旧规则文件或 `test_inbox_contract.py`，就等于把退役工作拽进本轮。需要一条明确的边界断言：本轮只改活接线相关的两个用例，旧规则文件与另一份测试逐字节未动。
- **风险 · 三处联动写盘的失败模式。** 写了草稿没写索引、或者回写了闪念行但草稿没落盘，都会造出契约里明令禁止的半截态。工具必须先算好全部改动再一次性落盘，且要有一条能重跑的验证证明中断不会留下半截。
