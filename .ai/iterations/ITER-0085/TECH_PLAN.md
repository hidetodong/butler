# TECH_PLAN — ITER-0085

方案状态: pass
方案审查: dangerous-self-review

# Design

1. 把 state-ledger index 升为 schema v2；根 index 只保存最大号、计数和固定区间路由公式，大小不随分片数线性增长。每个 `.md` 冷片配同名 `.json`，独立保存闭区间、路径、行数和哈希。
2. 文件名由固定 50 号区间决定：`ITER-000001-000050.md`、`MILE-000001-000050.md`；超过六位自然扩展，不按现有数据重新平衡。
3. `inspect` 聚合根热表、v1 单冷文件和 v2 分片，再按数字身份唯一化、划热窗口和生成目标分片。
4. `migrate` 用目录内临时文件 + 备份清单成组替换目标，成功后删除不再属于目标集合的旧单冷文件/孤立旧分片；失败恢复。
5. `lookup` 先读有界 index 和根热表；未命中时按公式计算路径，只读一个冷片及其回执；输出 `source`、row 和 `bytes_read`。
6. `check` 枚举受管目录的全部分片和回执重算目标状态，并额外检查 history 目录没有孤立受管文件。
7. 状态审计通过 state-ledger 的共享加载接口或 CLI 导出的全量行对账；AI 冷启动仍不读冷分片。

# Alternatives / Trade-offs

- 按每 100 行动态切片文件更紧凑，但新增历史会导致旧分片重排和路径漂移，否决。
- SQLite 查询更直接，但引入二进制真源和额外依赖，不适合 Markdown 规则仓，否决。
- 年/月分片对同日大量自动迭代不均匀，且身份路由不能直接计算，否决。

# Failure Paths

- v1/v2 同时存在或跨片重复：合并检查后拒绝，不静默选一份。
- 写到一半失败：恢复所有旧文件并移除新文件。
- index 路由元数据异常、目录越界/symlink、分片或回执坏哈希：fail-closed。
- lookup 找不到号：exit 1 的稳定 JSON；输入或状态损坏：exit 2。
