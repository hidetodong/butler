# MILE-0004 R6 · 认亲边缘 + 非回归门 + 收尾（收官）

> ITER-0041 · 里程碑 MILE-0004 第六块·**收官** · 监督态自驱（承 R1–R5 全链）· 不切版（切版是收口后的独立发布动作、待放行）

## 一句话

R1–R5 建成了 PRD 全生命周期链（导入→挂里程碑→钉版→改版同步），但留了一处边缘 + 两个收尾缺口。R6 收官 MILE-0004：① **认亲对账松边**——改版时模块**改名 / 合并 / 拆分**怎么对回旧身份（R5 只做了"新增 / 消失"、这些疑难留到了这）；② **非回归门**——把 MILE-0004 全程"不碰非 PRD 流"的承诺，从散落各迭代 AC 的口头话，固化成 references-schema 里一条**常驻可验证红线**；③ **收尾**——HUMAN_GUIDE 补 `/prd` 用法 + 全 PRD 子系统说人话自检 + flip references-schema §4/§8 R6 指针。做完六块齐，MILE-0004 可收口、可切版。

## 背景（为什么现在做、缺口在哪）

- **认亲边缘断了身份**：R5 改版认亲只到"多了谁 / 少了谁"。一个模块**改了名**（`login-validation` → `auth-validation`），R5 会当成"旧的消失 + 新的新增"两条独立记录——slug 终身身份的链就断了，跨版本审计对不上。合并（俩并一个）、拆分（一个拆俩）同理。这些**跨版本认亲对账**当初显式留给了 R6。
- **非回归只是散落承诺**：MILE-0004 每轮 AC 都写"非 PRD 流一行不动"，但那是**逐迭代的口头红线**、收口即散，没有一处**常驻**契约保证"这个子系统永远是 opt-in 加层"。R6 把它做成可验证门。
- **`/prd` 对人没说明**：`/prd update`·`/prd status` 已成型，但 HUMAN_GUIDE 还没有面向人类用户的用法节。

## 做什么（DD）

- **DD1 · 认亲对账松边（扩 `prd-update.md §4`，不改改版主流程）**：改版检测到"一个 slug 消失 + 一个 slug 新增"时，**启发式提候选**（标题/内容相近 → 可能改名；一消失对多新增 → 可能拆分；多消失对一新增 → 可能合并），**提议 → 用户确认**，绝不自动认。认亲落法：**改名** = 保留旧 slug、只更新标题/章节（守 `references-schema §4` slug 终身，换门牌不换身份证）；**合并 / 拆分** = 按确认落 slug 关系 + 登记表状态。**松边** = 给规则 + 提议确认、不追求全自动全覆盖；拿不准就退回"新增 / 消失"两条独立记录，宁可不认也不误并。
- **DD2 · 非回归门（`references-schema` 加常驻红线节）**：显式列出 PRD 子系统作为 opt-in 加层**不得触碰**的非 PRD 流——对话驱动 / `origin/` brief / 普通 references 注入（`api-`/`design-`/`insight-`）/ 核心 P1–P5 状态机 / 里程碑的非 PRD brief 合成路径；**验证判据 = 改本子系统时这些文件/路径 `git diff` 为空**。把散落 AC 的承诺固化成一处可核对的契约。
- **DD3 · 收尾**：
  - **HUMAN_GUIDE 加"PRD 先行"用法节**：`/prd update`（改版同步：给新版 + 说改了啥 → 检测/重切/冻旧版/报影响面，每步确认）+ `/prd status`（只读看板）的人话说明，摆在里程碑节附近。
  - **flip R6 指针**：`references-schema §4`（合并/拆分/改名认亲边缘）+ `§8` R6 行 flip 为 ✅ 已落地（指 `prd-update §4`）。
  - **全子系统说人话自检**：`references-schema` / `prd-split` / `prd-update` 三份过说人话三条，发现术语裸奔/比喻悬空当场修（dogfood）。

## 边界（不做）

- **不改 R1–R5 已建的主体**：`references-schema` 契约结构（§3 登记表字段不加列）/ `prd-split` 切分算法 / `prd_version` 钉版字段 / `prd-update` 改版主流程（§2 检测 / §3 落盘 / §5 三态 / §6 路由不动，认亲只在 §4 内扩展）。
- **不做全自动认亲**——松边，靠启发式候选 + 提议确认；不追求覆盖所有诡异改法（极端情形退回新增/消失基础态）。
- **不碰非 PRD 流**——本轮恰恰是**亲自守住**那条门，改动只在 PRD 子系统 + HUMAN_GUIDE 用法节。
- 不碰 `project-digest` / `context-persistence` / hook / `VERSION`；**不切版**——切版是收口 MILE-0004 后的独立 `chore(release)` 发布动作（同 MILE-0003 的 v2.0.0 分开走），待用户放行。

## 关键设计约束

- **松边不硬认**：认亲是提议 → 确认，**宁可留两条独立记录也不自动误并**——认错身份比不认更坏（把两个不同模块并成一个 = 规格串味）。
- **slug 终身不变**：改名认亲只换"门牌"（标题/章节）不换"身份证"（slug），守 `references-schema §4` 地基——这是认亲能成立的前提。
- **非回归门可验证**：不是口号，判据是"非 PRD 流文件 `git diff` 为空"这条硬线，任何人可复核。
- **收官不切版**：R6 只补规则收满 MILE-0004；切版（聚合 ITER-0036~0041 + 收口里程碑）是另一个独立发布动作，不混进本迭代。
