# 一句话意图

Butler 只拦自己能判断的项目内流程违规；项目外文件是否可写交给宿主权限系统，危险模式也只能在用户启动时预授权的范围上限内自治。

# Problem

- 当前 hook 把“无法归属当前项目”压成 `OUT_OF_CWD`，再由阶段门禁一律拒绝。
- 这会拦住用户已经明确要求的用户级配置、兄弟仓库和跨仓库写入。
- 本轮真实复现：写 `~/.codex/config.toml` 时，Butler 在宿主授权前先以 `phase_gate` 拒绝。
- 同一个标记还混入了缺失 `file_path`、空路径等坏输入；若简单全部放行，会把解析错误也放掉。

# Users and Scenarios

- 有人模式：用户明确点名项目外路径，宿主负责询问或校验权限，Butler 不重复拦截。
- 危险模式：用户启动前给宿主一个授权上限，Butler 可在上限内动态发现施工项目；超出上限的工作延后或阻塞。
- 项目内写入：仍完整执行阶段门禁、业务扩展保护和台账不变量。

# Constraints

- Butler hook 不能可靠读取并认证对话里的“用户明确授权”，不能自行签发文件系统权限。
- malformed 工具输入与无法解析的补丁必须继续 fail-closed。
- 危险模式替代流程确认，不扩大宿主权限；不能自动设置 bypass。
- 不引入新依赖，不改宿主权限算法，不发布或升级外部项目。

# Scope

- 调整共享 hook 的目标路径分类与规则适用边界。
- 允许同一 Codex patch 对多个可解析项目根分别执行各自门禁。
- 更新危险模式、部署说明、规则卡与 hook README。
- 补单元、集成和完整 CI 回归。

# Out of Scope

- 不实现 Butler 自己的权限弹窗或授权数据库。
- 不让 AI 通过 `.ai/` 文件给自己扩权。
- 不自动修改 Codex、Claude Code 的宿主权限配置。
- 不切版本、不生成 migration、不同步外部项目 hook 副本。

# Risks

- 若把坏输入误分类为外部目标，会形成 fail-open；必须拆开 `UNKNOWN_TARGET` 与 `OUT_OF_PROJECT`。
- 宿主若被用户配置成过宽权限，Butler 不再替宿主兜底；规则必须明确权限真源归宿主。
- 多项目 patch 中任一项目门禁拒绝时，整次 patch 仍应拒绝，防止部分绕过。

# Open Questions

- 无。用户已确认项目外权限交宿主、危险模式采用冻结授权上限并允许上限内动态追加施工项目。
