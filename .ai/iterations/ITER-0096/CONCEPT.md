## Current Understanding

- 用户会主动另起旁路 Agent 处理暂时不属于主迭代注意力中心的工作；成果可能同时包含代码改动、调研、方案和实验结论。
- 当前缺口不是模型替用户审批成果，而是旁路执行者收工后没有一份稳定、短小、可跨上下文读取的回执，用户往往需要重新向主 Agent 解释目标、成果位置、验证事实和续接入口。
- 本迭代采用“协议级能力”：旁路执行者写一份结果回执，用户显式把路径交给主 Agent；主 Agent 对照当前主线吸收事实、亮出冲突，需要方向取舍时仍由用户决定。
- 已确认构思保存在 `.ai/00_IDEATION.md`。该文件只作 P1 输入，不把早期被否的贡献审批状态机带入实现。

## Scope

- 定义旁路工作回执的职责、固定结构、生产与消费流程、代码/调研混合成果表达、共享工作区可信度边界和文件命名规则。
- 提供可复制的 canonical 模板，并在 `Coder/README.md` 与人类使用指南中注册入口，让用户能要求旁路 Agent 产回执、再把路径钩给主 Agent。
- 增加结构与接线验证，证明模板、规则入口和文档示例保持一致；完整 CI 继续作为非回归门。
- 第一版不新增命令或 skill，不建 `00_INDEX.md`，不设未读/接受/拒绝状态，不自动扫描，不自动合并代码，也不允许旁路执行者修改主线四件套、task-state、台账或 session handoff。
- 项目属于 Markdown 规则仓，无 Domain / Stack Profile；仅按通用 SOP、文档契约与现有双宿主边界推进。

## Open Questions / Risks

- 同日同主题文件名冲突采用“先用日期 + 语义 slug；已存在则追加递增短序号且绝不覆盖”的最小规则，不为低频冲突引入全局 ID 台账。
- 共享脏工作区中的路径和内容指纹只能证明当前内容，不能可靠证明作者；回执必须如实说明共享写入，独立提交、补丁或工作树仅作为更强但非强制的代码指针。
- 主 Agent 不默认扫描 `.ai/sidework/`，因此回钩仍需用户提供路径；这是用显式控制换取零状态、零上下文膨胀的有意取舍，真实使用若频繁漏钩再另立需求。
