# 说人话三条硬标准 + 发长文前自检

> 分流：完整迭代（P1–P5）· ITER-0033 · MILE-0003 R7 · 监督态自驱（用户点选 R7，非 /dangerous；P5 起独立复核守质量）

## 一句话

butler 的"讲人话"纪律现在散在一处、还只管四件套——写在 `artifact-style §2`、scope 锁死"四件套字段正文"，而对话层的 `presentation-protocol` 只管**结构**（结论先行 / 标号 / 表格）、完全没有字词级的说人话。R7 把「说人话」收敛成**三条有名字的硬标准**（术语先解释 / 比喻要落地 / 别让英文·变量裸奔），定义**只写一次**落 `artifact-style`、扩到**所有面向人输出**，对话层由 `presentation-protocol` 引用同守，并把收口自检扩成"发长文前自检"。

## 背景（为何现在做）

- MILE-0003 三条线的**最后一条**。知识文件夹（R2–R6）、帮手名册（R1/R4）都已落，说人话是收尾（R7），之后 R8 切 v2.0.0。
- 现状三个缺口：
  - **只管四件套**：`artifact-style §2`「讲人话」+ `§4.3`「承重引用给一句话解释」已含三条里的两条雏形，但 frontmatter 的 scope 写死"四件套字段正文"——交付总结、知识文件夹、handoff 等其它给人读的文档不受这纪律管。
  - **对话层裸奔**：`presentation-protocol` 只有呈现结构，没有任何字词级说人话；对话里堆术语黑话不受约束。
  - **"比喻要落地"缺**：三条里的这一条，现有规则完全没有对应条款。
- 核心痛点（承 MILE-0003 理解阐释）：**"简短"≠"好懂"**。butler 输出容易砍成骨头却仍是黑话，看着专业其实难懂。三条硬标准就是这句话的解药。

## 做什么（三块）

### 块1 · 说人话三条硬标准落 `artifact-style`（定义单一真源）

- `artifact-style §2` 改写为「说人话三条硬标准（跨对话与文档的通则）」，三条各有名字、各带一句话可执行判据：
  - **标准一 · 术语先解释**：术语 / 黑话 / 承重符号首次出现，一句话说清它是什么。判据（真实对象→用名字 + 一句话解释 / 只是偷懒简写→换大白话；结构锚点保留）承现有 `§2`。
  - **标准二 · 比喻要落地**（新）：用比喻帮理解时，比喻必须**落到具体对象**——"像 X 的 Y"要点明 X 对应本任务里的谁；悬空比喻要删，比喻是搭桥的脚手架不是装饰。
  - **标准三 · 别让英文 / 变量裸奔**：英文术语 / 变量名 / 函数名 / 表名首次出现不得裸奔（中文解释在侧或一句话点明它在本项目是什么）；结构锚点（字段名 / AC 编号 / 路径）本就是锚点、保留不算裸奔。承现有 `§2` + `§4.3`。
- 三条是 `artifact-style` 的**单一真源**（跨层通则）；承接并去重现有 `§2/§4.3`，不另起炉灶、不与之矛盾冗余。

### 块2 · `artifact-style` scope 从四件套扩到所有面向人输出

- frontmatter + `§1` 定位：书写纪律从"四件套字段正文"扩到**所有面向人的落地文档**（四件套 + 交付总结正文 + 知识文件夹 + handoff 等）；四件套只是其中一类，不再是全部。
- `§8`「收口前自检」扩为「发长文 / 收口前自检」：逐条扫三条硬标准 + 保留原有反面词 / 整段重述 / 超 2 层嵌套检查，适用对象为所有面向人长文档（不止收口的四件套）。

### 块3 · 对话层 `presentation-protocol` 引用同守（不双写）

- 新增一节：对话层的方案 / 分析 / 较长输出同守说人话三条硬标准；三条的定义是跨层通则、**真源在 `artifact-style §2`**，此处**只声明对话层受约束 + 给对话层的发长文前自检**（发一段较长对话前扫一遍三条），**不重述定义**（守单一来源）。
- `presentation-protocol` 原有呈现结构（结论先行 / 统一标号 / 表格 / 概念后置）语义不变，新节与之并列不冲突；因插节产生的内部 `§` 编号引用同步校正。

### 指针 / 同步

- `rule-card.md` 的 `artifact-style` 紧凑条同步收录三条（与 `§2` 一致、压缩不新增语义），守 README「rule-card 同步收录紧凑口径」。
- `README §目录说明` 两处 scope 描述同步：`presentation-protocol` 条增"说人话三条对话层应用"、`artifact-style` 条从"四件套字段正文的通用书写口径"改"面向人落地文档书写口径 + 说人话三条真源"。

## 边界（R7 不做）

- 不改四件套字段结构、不改 `presentation-protocol` 呈现结构（结论先行 / 标号 / 表格）语义。
- 不改 `delivery-summary §8` 交付摘要散文口径（三条硬标准叠加其上、不冲突，但不动它的字段与散文定性）。
- 不碰 `identity §2`（它已指向 `presentation-protocol`，本轮不扩其正文）。
- 不做 R8（butler 自身也照新结构改造——把自己的 `.ai/PROJECT.md` 迁成 `.ai/project/` 知识文件夹 + 切 v2.0.0）、不切版、不动 hook。
- 不碰知识文件夹结构契约（R2）/ 冷启动读序（R5）/ 维护回路（R3）。

## 关键设计约束

- **单一来源**：三条定义只在 `artifact-style §2` 写一次，`presentation-protocol` 引用不复制（承 CLAUDE.md 模板单一来源 + R1 的 G1–G4 单源模式）。这是本迭代的主设计决策——避免"对话一套、文档一套"漂移。
- **dogfood（自己先照做）**：本迭代自身的四件套 + 交付总结**必须**过三条硬标准（写"说人话"的迭代，不许自己说黑话）；收口前扫、VERIFY 记录。
