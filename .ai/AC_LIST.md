# Goal

保证多个独立方向进入候办时被拆成多个可独立管理的候办块，并各自落一份草稿文件。

# Acceptance Criteria

- [x] AC1：规则明确“候办块 = 一个可独立启动的版本方向”，多方向输入必须先拆成多个块；同一里程碑内部路线项不误拆。
- [x] AC2：每个候办块必须恰好拥有一个稳定候办键、一行台账索引和一份 `.ai/milestone-backlog/<候办键>.md` 草稿，可独立提升与删除。
- [x] AC3：Claude 命令、Codex skill、registry 生成投影一致表达多方向拆分与一方向一文件。
- [x] AC4：状态审计通过多候办正例，并拒绝单文件重复候办键、重复状态声明或身份与文件名不一致。
- [x] AC5：完整 CI、双宿主、现有里程碑连续编号和候办集合审计不回归。

# Constraints

- 自动道：AC1–AC5 全部由结构测试、状态审计或完整 CI 验证。
- 无人值守：危险模式自审冻结，不产生人工验收残余。
- 兼容：已有符合 ITER-0068 契约的单候办草稿继续合法。
