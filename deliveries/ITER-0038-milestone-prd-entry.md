# 把 PRD 切分接进 /milestone 录入（一份输入喂两个海拔）

> ITER-0038 · 里程碑 MILE-0004 第三块（R3）· 收口 2026-07-09 · 监督态自驱（承 R1 契约 + R2 切分机制；P5 起独立复核守质量）· 不切版（纯规则接线）

## 本次交付目标

- R2 让 butler 会把大 PRD 切成切片，但只接了"用户手动丢一份 PRD"这一个入口。真实项目里更常见的场景是：开一个大版本时，手上那份 brief（意图书）**本身就是一份 PRD**——它既讲了"这个版本要做哪几块"（方向），也写了每块的精确文案、校验规则（细节）。
- 本轮把切分**接进 `/milestone` 录入**：当开里程碑用的 brief 判定为大 PRD 时，**同一份输入**既照常合成里程碑路线图（方向层、有损压缩），又顺手触发 R2 的切分机制切成 `references/prd/` 切片（细节层、逐字无损）——这就是"**一份输入喂两个海拔**"。再把两层用指针焊起来：路线图的每一项能钻到它对应的 PRD 切片，切片也能回指它属于哪个里程碑。

## 已完成内容

- **`milestone-schema.md §6.4` 合成协议加"步 6 · 大 PRD 并进分支"**：现有 brief→里程碑的五步合成**一字未动**；新增的步 6 挂在其后——若 brief/`origin/` 材料判定为大 PRD（判据回指 R1 契约 §2），就在合成路线图之外**额外触发 `prd-split`** 切成 `references/prd/`。切分算法本身不抄一遍、以 prd-split 为准。**非 PRD 的普通 brief 走到第五步就停、不进这一步**（非回归保证）。
- **两次确认合并成一次**：以前路线图要你确认一次、切分方案（分几片、每片叫什么、边界怎么划）又要确认一次；现在 PRD 触发时**把两者摆在一起给你一次确认**，不让你点两轮。
- **`§6.4` brief 定位补一段**：讲清一份 PRD 会**同时喂两个海拔**，并强调两份产物身份不同——`origin/` 里那份 PRD 是你自管的**非权威原始输入**（AI 只读、不归档、你可随时清理）；切出来的 `references/prd/` 切片才是 AI 派生、供后续验收对账的**权威投影**。别把两者混为一谈。
- **两海拔交叉指针（双向）**：
  - **方向 → 细节**：`§5.3` 拆分路线图的每个路线项可**选标**它实现的模块代号（如 `→ prd: save-validation`）——想看某块的精确规则，顺代号钻进对应切片。
  - **细节 → 方向**：`prd-split §3` 补一条——由 `/milestone` 触发切分时，切片索引 `00_INDEX` 记一句"本 PRD 服务哪个里程碑"。
  - **映射只存一处**：模块↔路线项的对应关系**单一真源在路线图**，索引侧只回指里程碑号、不把映射再抄一遍（防两头改出分歧）。
- **翻牌 + 顺带纠漂移**：`references-schema §8` 里"从 `/milestone` 触发首切 + 交叉指针"那条从"待 R3"翻成"✅ 已落地"；独立复核顺带发现 README 里 prd-split 的描述还把"/milestone 入口"列为未来 R3，一并改成"已落地"。

## 关键变更 / 用户可感知变化

- **用一份 PRD 开里程碑，会自动同时得到两样东西**：一张有损的方向路线图（好读、好规划），加一套逐字无损的细节切片（验收时对精确文案/校验规则用）。你只需在开里程碑时确认一次切分方案。
- **两层能互相跳转**：里程碑路线图上看到"R3 做保存校验"，能顺指针钻到 `references/prd/save-validation.md` 看那条校验的精确原文；反过来切片也知道自己归哪个里程碑。
- **不用 PRD 开里程碑的人完全不受影响**：这是纯增量的一条分支，普通 brief 的合成路径一字没改（`git diff` 零删除行为证）。

## 已知剩余风险 / 延后事项

- **闭环成型、但还没版本化**：R3 让"一份输入喂两个海拔"跑通了，但切出的切片**还不能被验收标准钉版本引用**（那是 R4）——目前里程碑→切片的指针指向的是"当前最新"切片，尚无版本锚定。
- **交叉映射一致性靠遵从**："映射单一真源在路线图"是规则约束——真到 R4/R5 版本化后，路线项的代号标注与切片索引的回指是否始终对得上，取决于执行遵从（同既有"回指不复述"信任模型）。
