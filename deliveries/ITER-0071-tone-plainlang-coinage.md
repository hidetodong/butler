# ITER-0071 · 说人话补「自造缩写」标准并让产物范例常驻

## 本次交付目标

- 把「掐短常用词、自造只有本仓看得懂的压缩名」这类写法，正式收进说人话标准，之前四条没管到它。
- 让写产物时看得到具体的「改坏了长这样、改对了长这样」范例，而不是只有一句「口径以某文件为准」的指针。

## 背景（为什么改）

这一轮核对了 butler 全部语气治理文件和几份真实产物，结论是：产物层的中文发僵是真问题，但病根不是规则打架，而是加载不对称——管产物语气的正本（`artifact-style.md`）在真正动笔写产物那一刻不在场，而一起被读进来的一堆规格腔 schema（必须/不得条款）声音最大，于是产物就被带成了规格腔。抽检里最扎眼的祸首是自造缩写（像「候办」「折叠回执」「边界守恒逐轮核」这种），而说人话四条原本根本没写这一条。

## 已完成内容

- `artifact-style.md §2` 标准一收编「掐短词 / 自造缩写」：必须用平常说话的完整词；真要用一个新造的简称，第一次出现必须跟一句大白话说清它指什么。
- `artifact-style.md §6` 补一组对照范例，把「边界守恒逐轮核」这类压缩写法还原成正常句子。
- 说清四条的单一真源作用域：butler 体系内别处（`presentation-protocol.md`、`rule-card.md`）只引用、不另写一份；仓根 `communication-style.md` 是走用户全局通道的体系外个人副本，自造缩写归标准一、翻译腔归标准四，内容对齐即可，不算双正本冲突。
- `rule-card.md` 同步：产物书写段加了 3 组现场 ❌→✅ 范例，因为这张卡每会话常驻，等于把「改对了长什么样」直接摆到高注意力区。

## 关键变更 / 用户可感知变化

- 以后写交付总结、commit 正文、知识文件夹时，规则明确不许再把常用词砍一半或者生造压缩名；真要用简称，第一次出现得就地解释。
- 规则卡里能直接看到三组「反例 → 正例」，写产物时照着改，不用再翻别的文件。

## 高层影响范围

- 产物语气治理的两处正本：`artifact-style.md`（完整版真源）和 `templates/rule-card.md`（常驻压缩版）。
- 不动 `communication-style.md`——它自己的边界禁止引用 butler 内部文件，且内容本就不缺这一条。

## 验证方式与结果摘要

- 全仓「说人话四条」引用结构复核干净，没有残留的不一致。
- 改动限定在两个文件，未触碰产物链阶段、hook 契约、schema 必填字段。

## 已知剩余风险 / 延后事项

- 修法 B（把给人读的交付内容隔离到不泡 schema 条款的步骤或子代理去写）本轮未做，留后续——它要动生成流程，比改文案重。
- 本轮不切版本、不写 CHANGELOG / migration，也不推送、不升级外部项目；版本级动作按 `versioning-schema.md §6.1` 归发布路径，按需另提。
- 部署到目标项目的 rule-card 需要下次升级 re-stamp 才能拿到新范例。
