自动化测试最大化 + 人测 web 回环（MILE-0002）

MILE-0002 里程碑交付（大版本） 收口 2026-07-03 · v1.7.0

本次交付目标

  • 补 P5 验证的两处系统性断裂：① 缺"竭尽自动化"的硬纪律，本可自动化的项（尤其 UI / 交互，其实可用浏览器自动化覆盖）容易随手推给人；② 人测结果没有回传通道，闭环断在人这一侧，butler 无法据结果续跑。
  • 大版本目标：P5 的人测从"butler 口头说一句、结果断在人这"变成"结构化分道 + web 桥四态回传 + 后台等待续跑"的可审计闭环；自动化覆盖最大化，人测道只剩机器确实不可测的极少残余。

已完成内容

  • 五件闭环：自动化优先纪律 + 分道（R1）、分级置信 + 代理验证 + 依赖感知准入（R2）、交付自测桥工具（R3）、等待-回收-续跑 SOP（R4）、部署 / 使用文档 + 真 dogfood（R5），覆盖"竭尽自动化 + 人测残余可回传续跑"两端。逐路线项见下方回填。

关键变更 / 用户可感知变化

  • P5 验证升级为"竭尽一切自动化"硬纪律：能自动化的（含浏览器自动化覆盖 UI / 交互）必须自动化，人测道仅留机器不可测残余；每条 AC 显式分「自动道 / 人测道」回填 VERIFY_REPORT.md。
  • 验证结论叠分级置信「可靠 / 弱 / 待人」：感知类可造弱自动检查（截图 diff / VLM 判图）earned 弱档，绝不假绿。
  • 人测残余走 交付自测桥（butler 驻留、Node 零依赖）：外部项目传 JSON 清单 → GitHub 风格分步流程页 → 每项四态 + 备注（通过 / 未通过 / 跳过 / 延后）→ 写 results.json → 自退；桥不拷进目标项目，按路径传参调用。
  • 后台等待续跑闭环：run_in_background 起桥 + 阻塞等待，人提交后进程退出即续跑，按四态路由（通过→收口 / 未通过→纠错 / 跳过→N/A / 延后→入账不阻塞）；无人值守不起桥则走 dangerous §7.4 依赖感知准入闸。

高层影响范围

  • 新增规则 / 产物 / 工具：tools/delivery-selftest/（butler 驻留桥，Node 零依赖）、human-test-bridge.md（P5 下游接线协议）、mcv-deployment §6（驻留工具调用）、HUMAN_GUIDE §5（人测回环）、dangerous-engine §7.4（无人残余依赖感知准入闸）。
  • 接线 / 升级：testing-strategy.md（竭尽自动化 + 分道）、verify-schema.md（分道回填 + 分级置信）、correction-contract（人测 fail 接入纠错）、Coder/README（注册）、templates/rule-card.md（强制约束补入，随 v1.7.0 [regen-claude]）。
  • 未动：P1-P5 阶段状态机、四件套字段结构、AC 验收脊柱、templates/hooks/（无 hook 变更）。
