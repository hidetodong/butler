Decision Work 帮手合同与显式吸收

ITER-0104 迭代交付（小版本） 收口 2026-08-01

本次交付目标

把 Wayfinder 式“并行求证”接入 Butler 已有 Decision Map，同时确保 helper 只产出可审阅事实，不能靠模型临场判断直接改 Map 或推进交付流程。

已完成内容

  • 新增 tools/decision-work/ 四动作 Module，统一不可变 Task Packet 与 Result Envelope。
  • 用一个 helper 合同覆盖 research、prototype、grilling、task；只有 Research 可对显式 claim 的 Decision 组成 batch。
  • 建立四种结果、predecessor 接续、迟到/失败恢复与显式 absorb 合同。
  • 接入 Ideation、帮手名册、驻留工具说明、领域词汇、workflow 边界和完整 CI。

关键变更 / 用户可感知变化

  • Explore 仍是单一 opt-in 入口，不按需求大小、清晰度或置信度自动启用。
  • 前期流程固定为“展示 Frontier → 显式选 ID → claim → prepare → helper/HITL → record → 审阅 → absorb”。
  • 并行的是 Research 求证，不是 Map 写入；其它模式保持单项 serial/HITL。
  • helper 完成、result 落盘或 absorbable=true 都不会自动解决 Decision。

高层影响范围

  • 新增 Decision Work 深 Module、CLI、合同文档和 17 项专项测试。
  • 新增一个 Decision Work 帮手定义，并更新 Agents、Ideation、部署说明、README 与 CONTEXT.md。
  • 没有新增 workflow ID、宿主命令、R2 schema、agent scheduler 或 R4 promotion。

验证方式与结果摘要

  • Decision Work 专项 17 项通过，覆盖真实并发、故障回滚、跨进程恢复、迟到/stale/篡改和 absorb。
  • P5 Must Fix 修复后风险定点 evidence 以 reproduced 通过，最终 Must Fix 0、Should Fix 0。
  • Workflow 合同 12 项通过，Router + 13 workflows 与 R1/R4 边界不变。
  • 完整 CI 在 Python 3.12.12 / uv 0.9.28 下 exit 0；四份 evidence 已归档并复核。
