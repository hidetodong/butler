# 并行迭代增强模式 — 概念设计

> **⚠️ 预研，未进入体系。** 经讨论判定：并行迭代概念**尚不成熟**，存在并行 lane 串扰串行核心的风险，**暂不推进**。本文置于 `docs/research/`（预研区），不进入 `docs/superpowers/specs/ → plans/` 落地管线、不被 `Coder/` 规则链引用。待概念成熟、串扰风险有解后，再评估是否转入 `specs/`。

> 本文是一次概念讨论的结晶，**只到概念层**：定清楚"是什么、为什么成立、边界在哪"，不含 schema 字段、不含代码、不含实施步骤。落地前需另起设计取舍 spec 与 plan。

## 0. 一句话定位

**串行迭代是不可改的原子；并行只是套在里程碑层外面的一个 opt-in 效率增强壳。** 默认永远串行，显式才并行，证不出安全就坍缩回串行。

---

## 1. 锚定原则（地基，不可动摇）

> 现有串行迭代模式已经好用，**不轻易改**。并行纯粹出于效率考虑，作为审慎使用的增强模式存在。

由此推出一条贯穿全文的硬约束：

- **串行迭代是原子**：一个迭代的 `P1–P5`、冻结门、固定路径四件套、台账行、hook —— 一个字都不动。
- **并行是迭代之上的调度属性**，不是迭代内部的属性。一个迭代永远不知道、也不关心别处是否有别的迭代在并发。
- 全模型里**真正松动的核心不变量只有一条**：`iteration-schema §2`「同一时刻最多只有一个 active 迭代」→「可有多个 active 迭代，**当且仅当**它们写集合不相交、各居独立 worktree」。其余因 worktree 隔离与既有归档层而自动成立。

---

## 2. 主语不是"开几个 CC"，而是"可分区性"

"开几个 Claude Code"是结果，不是概念。真正的原语是：

> **能不能把工作切成"写集合互不相交"的若干份。**

切得开 → 开几个实例是自然推论；切不开 → 开再多实例只是制造冲突。串行就是"分区宽度 = 1"的退化情形；并行只是把分区宽度放大。这让 butler **不必引入 git 式的"分支+合并"治理语义**——分区若一开始就不相交，就没有合并冲突（分片 shard，而非分叉 branch）。

---

## 3. 正确性判据：可串行化（Serializability）

> 一批并行迭代合法，**当且仅当**其最终状态等价于这几个迭代按某种顺序串行跑出来的结果。

保证可串行化的**充分条件**就是"写集合两两不相交"（不相交的改动彼此可交换，谁先谁后结果一样）。三句话收口安全论证：

1. **前置**：声明各 lane 写集合，证明两两不相交 → 证不出就退回串行。
2. **执行**：各 lane 原样串行迭代，互不知情。
3. **后置**：集成审计核对"声明的不相交"是否真成立（declared-disjoint ≠ actually-disjoint）。

### 关键精度

- **判据建立在"写集合"上，不是"读集合"。** 多个 lane 共享地**读**一个稳定定义，不破坏并行。
- **共享公共定义不是冲突，是依赖。** 若该定义还不存在/需创建，把它提成一个**必须先完成并冻结的前驱"基座迭代"**，下游再扇出（这正是 `lifecycle §6`「先定契约，再做扩展」被并行变成承重）。
- 于是模型不是"切饼"而是 **DAG**：**串行前缀（共享基座）+ 并行后缀（写不相交的叶子）**，"不相交"只作用于同层同辈。任务若几乎全是共享基座，DAG **自动坍缩回一条串行线**——框架会在"并行帮不上忙"时自己退回。

---

## 4. 协调机制：fork-join + 屏障，不要进程间通信

独立进程之间**没有也不该有**实时通知通道（轮询时机、中断半途的 P4……每一环都不可控）。因为写集合不相交，**一条 lane 的中途发现不可能在屏障之前破坏另一条 lane 半径内的工作**，所以根本不需要实时通知。

- lane 之间**永不通信、永不读对方状态**。
- 一条 lane 只有两种结局：跑完声明范围，或撞到半径外的事 —— **两种都一样：落盘、停下(park)、退出**，不通知任何人。
- 其它 lane 毫不知情，继续跑到自然停点（安全，因写不相交）。
- **协调者**在屏障处统一收集 park 状态再决定。

代价是**有界的浪费**（掉队者 straggler / 划错分区导致一波内部分返工），但永远不是静默损坏。

---

## 5. 协调者：混合模式（butler 今天没有的新角色）

- 串行 butler 无协调者（单时间线即协调）；并行必须有一个角色**拥有**：切 lane、声明写集合、预分配 ITER 号、跑两道审计、且是共享台账脊柱的唯一写者。
- **混合模式**：AI 跑机械预筛 + 起草"分区报告"，**人做最后一下 ACK 冻结分区**。
- 这没有引入新治理机制——它就是 butler 既有冻结门（AI 起草 AC_LIST → 人 ACK → frozen）**搬到更高一层**，对象从"单迭代验收项"换成"整批写集合与契约"。
- 人 ACK 的是**一页浓缩报告**（各 lane 写集合 / 求交结果 / 危险清单 / 推荐调度），不是 N 份原始 plan。

### 两道审计 = 两层 + 同构于 AC→VERIFY

| 屏障 | 时机 | 机械层（可硬化成门） | 语义层（协调者） | 类比 |
|---|---|---|---|---|
| ① | 全 lane P3 后、P4 前 | 写集合求交，撞=拒 | R-A-W / 缺基座 / 契约不一致 | "分区的 AC_LIST" |
| ② | 全 lane P4/本地P5 后 | 逐 lane diff vs 声明写集合 | 两两契约一致性 O(K²) | "分区的 VERIFY_REPORT" |

求交集"必要但不充分"：可串行化还取决于读写顺序与契约语义，后者需要会判断的脑子，所以机械层之上必须叠协调者语义审计。

---

## 6. Batch：软路线图与硬冻结之间的新单元

里程碑路线图是**故意非冻结、方向性**的（`milestone-schema §5.3`），但分区决策**必须冻结**（它门住 P4）。两者矛盾，用一个中间概念化解：

> **Batch = 从软路线图里切出、经审计并冻结的一波并发 lane。**

- 路线图负责"提议"（软、可演进）—— 原样不动。
- Batch 负责"承诺"（硬、审计过、冻结）—— 真正进入并行执行、预分配号、台账登记、两道审计作用的单元。

---

## 7. 失败恢复：可归因即局部回退，关系型即升级（同构于"修订/扩张"）

屏障②抓到违约时分两类，判别器是机械的：

- **一条 lane 越界（可归因）→ 选 1**：退回该 lane 到 P3 重做，其余不动。
  - 归因干净：每条 lane 在自己分支，diff 完全归它，`diff ∩ 声明写集合` 超了就是它。
  - 回退隔离：写不相交 → 退它不动别人。**"可归因"与"回退隔离"是同一个性质（即可串行化集合）。**
- **两条干净 lane 合不到一起（契约，关系型）→ 选 2**：错误属于这"一对"，无法单条归因。它**反证屏障①漏了一个公共基座** → 协调者裁定权威形状、提基座、依赖方重建。

> 这个二分同构于 butler 既有的"修订 vs 扩张"（`iteration-schema §5.3/§5.4`）：局部小问题原地修，结构性问题升级开新单元。

**硬时序规则：屏障②必须"先审后合"**——逐 lane 在各自分支里审，通过者才 merge。一旦"先合再审"，diff 混在一起，逐 lane 归因当场报废。

---

## 8. 落盘与隔离（worktree 的真实可靠性边界）

- sub-agent fork 出来**上下文是 clear 的**（不继承父会话，从磁盘读自己的产物 bootstrap）——契合 butler"不靠对话记忆"。但 **clear 的是上下文，不是文件系统**。
- git worktree 对**源码隔离**可靠，且 harness 一等支持；butler 的风险在 git 保证之外的三块：
  1. **`.ai/` 固定路径冲突（最毒）**：每条 lane 都写 `.ai/CONCEPT.md` 等同一组路径，若随分支提交则 Join 必冲突——即使源码不相交。
     **解法用既有三层落盘**：工作区四件套**worktree-local、瞬态、不参与合并**；Join 只合并 ①源码 + ②按号分目录的归档 `.ai/iterations/ITER-NNNN/`（路径天然不撞）；台账只由协调者写。
  2. **种子(seeding)**：fresh worktree 不带未跟踪文件 → 协调者须把该 lane 的 `.ai/` 与 hook 配置喂进去。
  3. **运行时碰撞**：lane 的 P5 若起服务/连库 → 端口/DB 需逐 lane 隔离。

---

## 9. 激活与定位契约（让它是"审慎增强"而非脚枪）

1. **形态 = 三件套**：① 对核心一处微创（`iteration-schema §2` 单 active → 不相交多 active）；② 对 `milestone-schema` 增量（写集合/依赖、Batch、两道审计、恢复）；③ 新 opt-in 引擎（建议 `75_Extension_Parallel/`，仿 `65_Extension_Dangerous`）。**绝大部分新增隔离在 opt-in 模块。** ✅ 已确认
2. **触发 = 默认串行、显式才并行**：`/parallel` 把里程碑某几个不相交路线项标成一个 Batch。
3. **前置信号清单**（仿"升级/启动信号"的可审计门）：≥2 路线项、写集合可证不相交、每条 lane 体量过"最小可并行阈值"、契约可事先冻结；任一不满足 → 留串行。
4. **与 `/dangerous` 的关系**：**禁止 parallel × dangerous 同开**（自治风险相乘）；但并行**复用** dangerous 的审计/回滚护栏来包裹无人值守执行段。 ✅ 已确认
5. **永远可坍缩回串行**：前置不满足 / 归因不清 / 审计存疑 → 一律退回被验证过的串行路。
6. **启动机制**：**B（sub-agent 扇出 + worktree，分阶段串接、阶段间留人类门）为默认**，**A（手开 N 个终端）为手动兜底**，二者不互斥（B 是 A 的自动化）。

## 10. 流程图一：原串行流程（核心，本次**不改**）

```text
  [里程碑 MILE-NNNN]   ← 松耦合·可选·方向性不冻结
        │
        │  拆分路线图  R1 ─→ R2 ─→ R3 ...   （顺序执行，一次一个）
        ▼
  ┌──────────────────────────────────────────────────┐
  │  迭代 ITER-NNNN   （单 active · 固定路径四件套）       │
  │                                                    │
  │    P1 ──→ .ai/CONCEPT.md                           │
  │    P2 ──→ .ai/AC_LIST.md ──[人 ACK]──→ ack-frozen  │ ◄─ 冻结门
  │    P3 ──→ .ai/TECH_PLAN.md ──[人 ACK]              │    (hook 机械拦截)
  │    P4 ──→ 写代码（纠错收口契约·绑 AC 探测）           │
  │    P5 ──→ .ai/VERIFY_REPORT.md + 交付总结           │
  │                                                    │
  │    收口：快照→ iterations/ITER-NNNN/                │
  │          交付→ deliveries/   台账行 closed          │
  └──────────────────────────────────────────────────┘
        │   current = none
        ▼
  下一个迭代 ITER-(N+1)  ...   （串行，一个接一个）
```

特征：**单 active、固定路径、每阶段人类门、一次一个迭代。**

### 两图接驳点（"核心没动"的证据）

- **每个 `Lane X` 方框 = 流程图一里一个原样的迭代**，P1–P5 / 冻结门 / hook 全不变。并行只决定"几个方框同时在飞"。

- `.ai/` 工作区瞬态不合并、只合并源码与按号归档、台账协调者独写 → 固定路径不冲突。

## 12. 诚实的边界与代价（不挑好听的）

- **红利有界**：只吃得到"真不相交"那部分工作的并行。多数真实特性有共享面 → 判为相交 → 退串行。这是**窄而安全**的增益。
- **决策数不减**：每条 lane 仍是完整迭代、各带 P2/P3 人类 ACK。并行**不减少你要做的决策数量**，省的是**墙钟**（P4 并发）与**上下文切换**（决策攒到屏障批量做、不用守每个 P4）。瓶颈是"决策次数"则几乎无益；瓶颈是"等执行"则收益大。
- **扇出上限是认知，不是机器**：协调者要同时理解 N 份 plan + 两两契约 O(K²) 检查 → lane 数被"协调者能盯住几条"卡住。
- **协调者是新单点故障**：整批正确性压在协调者跨 lane 判断 + 报告保真度上。报告压太狠→人 ACK 变橡皮图章；压太松→人回到读 N 份 plan 的瓶颈。这与 hook gate backlog 的"天花板 B"同源：门只能验"人点了 ACK"，验不了"报告给够了判断的料"，只能靠屏障②事后 diff 兜底。
- **不可约串行的外边界**：当契约与其消费者必须**共同演化**（用了才知道接口该长啥样）时，无法先冻结契约再扇出 —— 天然串行，并行不该硬上。
