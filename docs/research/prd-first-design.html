⚠ 你闻到的味道是真的：交叠点在实现，不在功能

PRD 先行时，同一份文档同时干两份活：既是定义里程碑范围的原始输入（brief 角色），又是实现细节真源（references 角色）。butler 现在把这两个角色分给两个通道（origin / references）。

所以重复风险 不在"要不要 references"，而在"要不要为 PRD 再造一套里程碑合成"。答案是不造——PRD 当 brief 喂给现有 /milestone，路线图照旧出；只额外加"切分+索引"这一步。

落地后三种情况

无 PRD

  • 只跑 brief 通道
  • 跟今天一模一样
  • → 满足"非 PRD 先行照常跑"

小 PRD

  • brief 通道 +
  • 整份塞 references/prd-xxx.md
  • 不切、不建索引

大 PRD

  • brief 通道 +
  • 切模块 + 00_INDEX
  • 指针渐进加载、只读用到的那片

结账：复用什么 / 只新加什么（＝没有平行机器）
