长程 / 无人值守下,人测卡点怎么解

MILE-0002 方向性推演 · 把「人测 web 桥」放进 /dangerous 与长程自治场景后暴露的死点,及其处置模型。

MILE-0002 预研 · 未进体系 2026-07-02 docs/research/

1问题的本质

人测 web 桥的机制是阻塞等人握手。而 /dangerous(无人值守)的契约恰恰是人不在环里。两者直接冲突:

人测桥机制

起服务 → 开浏览器 → 阻塞等人勾选提交 → 收到才续跑

⚔

/dangerous 契约

无人值守,跑到完;没有"人"可以握手

所以这不是"怎么等得更聪明"的问题——只要还在等人,就违背了 dangerous 的前提。要回答的是:当结构上就没有人时,人测残余该被怎么处置。

2长程任务把它加码

进一步:长程自治跑可能持续数小时到数天,人连"运行前预授权""收到通知在窗口内回"都无法保证。这打穿了所有"靠人在某个时刻出现"的方案:

  • 前置闸:开跑前让人一次性预授权残余延后 → 长程下人开跑时也未必在;且跨多迭代的残余无法一次预见。降级为机会主义、不承重
  • 通知 + 有界窗口:PushNotification 戳人,窗口内回 → 没有任何窗口是可靠的。降级为机会主义、不承重

真正承重的东西必须满足一个硬约束:在人零次触达的前提下,仍能正确地向前推进。

3三根承重柱

1残余异步入账 · 永不阻塞、永不假绿

长程跑跑完整个自动道,人测残余沉淀进一份持久欠债账,人按自己的节奏(几天后都行)来清。前进永远不等人。相较早先的"泊留",这里把它从阻塞终态改成非阻塞的持续入账:跑不停,账在攒。

2把自动化前沿推到「代理验证 + 分级置信」

对本来要人"扫一眼"的感知类项,造一个更弱但真实的自动检查(截图对基线视觉 diff、VLM 判读截图、启发式断言)。它不如真人,但是真信号。在 VERIFY_REPORT 里如实记置信档:

置信档含义手段举例能否收口
high 确定性断言,机器可复现 单测 / 集成断言 / 精确比对 可 · 直接绿
heuristic 代理验证,弱但真实的信号 视觉 diff、VLM 判图、启发式 可 · 记方法+档,人事后抽查
pending-human 连代理都造不出的真残余 真人审美 / 物理设备 / 外部人工闸 否 · 入欠债账

heuristic 可以收口——只要如实记"验证方法 + 置信档",这不是假绿,是一条可审计的真陈述。人事后只需抽查 heuristic + pending 这个小集合。即便主观类项,真残余也被压到接近空。

3依赖感知的准入闸 · 最要命的一根

真正的危险不是"有残余",是残余卡在关键路径上——下游依赖一个没验的项还硬闯,就是在错误地基上盖楼。按依赖位置分流:

残余项在哪? // 依赖图上的位置
在叶子(下游无依赖) → 入账、继续跑 → 安全延后
卡下游 → 造代理验证则下游按 heuristic 续;造不出则砍这条分支,其余独立分支照跑
迭代的关键路径 AC 连代理都造不出 → 不具备长程无人跑的准入资格,只允许有人时执行

即:长程 / dangerous 模式有一条入场体检。过不了的,老实留给有人的场次,而不是闯进去卡死或假绿。

4一条红线

绝不写一条假的 "verified"

无论怎么降级,假绿是唯一会腐蚀 AC 验收脊柱和 MILE-0001 刚硬化的冷启动一致性不变量的做法。heuristic 记档是诚实的"验到什么程度",pending-human 入账是诚实的"没验";两者都真。宁可停在门口,不可撒谎盖章。

注:这里不引入此前搁置的"半自治中间档"。泊留 / 入账只是 dangerous 现有引擎的终态,不是新档位。
