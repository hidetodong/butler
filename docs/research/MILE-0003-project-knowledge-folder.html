1目标与缘起

冷启动的"整体"产物今天是单文件 .ai/PROJECT.md——一份 ≤1500 tokens 的薄索引：几行关键词 + 指针"细节去读代码"。实操里它容易沦为"说几个关键词然后假装这套体系很有用"，AI 读完并不真正知道"项目里有什么"。

目标：要一份 AI 读完就真懂项目内容、且随迭代越来越完整的知识层，真正能用起来——而不是骨架。它与迭代日志是两个东西：

产物取向答什么
.ai/project/（新）整体 / 积分系统现在整体是什么、有什么、处于什么状态
ITERATIONS.md / CHANGELOG部分 / 增量一步步怎么走到今天（delta 流）

2愿景（用户定）

  • 解构成文件夹：单文件 PROJECT.md → .ai/project/ 知识文件夹，按主题拆分。
  • 有入口：文件夹含一个 00_INDEX.md，冷启动第一读、指向其余。
  • 越来越完整：内容随迭代持续补全，AI 越来越方便地知道"项目里有什么东西"。
  • 真能用：装消化过的真内容，不是关键词占位、也不是纯指针。
  • 通用 + dogfood：做成任何部署项目都能用的 SOP schema，butler 仓自身先吃自己的狗粮。

3结论：能，但这是一次哲学切换

能完成目标——但不是"把 PROJECT.md 切成几块"那么轻。它是从「薄索引」到「实体知识库」的有意识哲学切换，成立有 4 个硬前提（§5）。缺了，产出的会比现在更危险：看着完整、其实滞后，让 AI 自信地错。

要先认清在推翻现 project-digest-schema 的哪些明文价值：

现 schema（明文）本愿景（反转）
≤1500 tokens、"摘要不是百科"越来越完整、概括项目内容
指针化：深内容指向真源、不内嵌装真内容、读完就懂"有什么"
§5"多数迭代只动 0-2 行甚至不动，避免维护膨胀"随每次迭代折叠更新、持续补全

即 MILE-0003 本质是反转 §5 的维护哲学（从"按需微调"→"每次收口必折叠"）。换来"真能用"，代价是更高的维护纪律——这笔账要认下来。

4矛盾怎么消解（成立的关键）

"完整"与"不膨胀 / 不腐"能共存，靠三条重定义：

张力消解
完整 vs 有界 完整 = 覆盖广度，不是细节深度（地图 ≠ 疆域）。体积 ∝ 项目复杂度、不 ∝ 迭代数；每项到深处仍指针回代码 / 规则。
越来越完整 vs 禁纵向堆积 "完整" ≠ "变长"：完整靠覆盖 + 折叠折新，当前真相 overwrite，禁历史层；被取代的内容删除、不叠。
越来越完整 vs 反 harness 膨胀（LOOPS §VIII） 知识地图（要完整）≠ harness 机器（要精简），二者正交。好地图反而帮你看清哪些壳能删——不违反"删壳"。

5四个成立前提（成败在此）

1地图非百科

完整 = 广度覆盖；每份文件有界、可整篇读完，满则拆新文件；密度到"每项 + 它到底干什么 + 真源"（见 §7 样例），不是关键词、也不是复制代码。

2强制 + 可验证的收口折叠make-or-break

本迭代 delta → 按主题路由进对应文件，必做（非"按需"）；再加一条漂移自检不变量（文件夹 vs 现实是否脱节，脱节先暴露）。有现成先例可复用：MILE-0001 的冷启动 5 不变量 + 原子收口仪式。

成本可控：delta 已在 CHANGELOG 记好、绑 AC，收口是路由不是重推导——成本 ∝ 本迭代改动量、不 ∝ 文件夹大小。

3digest-and-point，已有真源不复制

butler 仓自己是最难的 dogfood（Coder/README.md / architecture-overview 已在）：架构类文件必须"摘当前全貌 + 补 README 没有的现状 / 成熟度层 + 指针"，不逐字抄。跑通 butler，就对任何项目通用。绿地项目则以知识文件夹为主场。

4推荐核心 topic 集 + 受控扩展

新内容 → 新 topic 文件，登记进 00_INDEX.md（沿用"注册进 README / 无隐式依赖"的老不变量）。这个受控扩展本身就是"越来越完整"的引擎。

6维护回路（整体靠部分喂养）

整体 = .ai/project/（积分，当前真相全貌）；部分 = 迭代 CHANGELOG（ADD/EDIT/DELETE 增量）。收口时把本迭代 delta 按主题折进对应文件——不是重写全份，是定向路由。写代码 = "改了什么"，收口 = 把"改了什么"折进"现在是什么"。这样它随迭代长、且不腐。

落点：把现有 iteration-schema §5.5 step④"按需前滚 PROJECT.md"从单文件 · 按需，泛化成文件夹 · 按主题 · 必做；里程碑收口同理（milestone-schema §7.4）。

7拟定结构 + 密度样例

按主题细拆（推荐核心集，可扩展）：

.ai/project/
  00_INDEX.md      # 入口：一段话讲清项目是什么 + 本文件夹读序/地图
  identity.md      # 定位/目的/使用者/边界

8最大风险

陈旧的完整，比诚实的薄更毒

现在的薄索引至少不骗人（"细节去读代码"）；一个立志完整却没被严格维护的知识库，会变成一份自信的谎——AI 信了滞后内容、做出错判。整套设计生死系于前提 2（强制 + 可验证的收口折叠）。它若不硬，MILE-0003 会精确地产出用户最讨厌的"假装有用"，只是更大份。
