你正在执行 butler 的 **主动升级**动作。本命令是**薄壳路由器**——只做三件事：① 保证把对的规则读进上下文，② 委托真源规则执行，③ 守住保护区不被覆盖。**侦察动作、迁移配方队列的执行细则、保护区契约、验证回退口径一律以被指向的规则文件为准，本文件不复述**（守 butler DRY 红线）。

> **路径约定（本命令可在任意项目里运行，当前目录不一定是 butler 仓）**：下文引用的 `Coder/…` / `templates/…` 都是 **butler 规则仓库**里的文件，一律相对 `$BUTLER_PATH`（`setup.sh` 全局安装时写入的环境变量）解析。升级**对象**是**当前项目**的 `CLAUDE.md` 与 `.ai/` 结构，绝不是 butler 仓自身（butler 仓自己的版本由 `versioning-schema.md` 切版流程管，不走本命令）。

> **项目根硬门**：侦察版本差前先按 `$BUTLER_PATH/Coder/20_Workflow_Lifecycle/mcv-deployment.md §0.1` 解析 `PROJECT_ROOT`。升级的所有读写只在该根下；用户点名路径优先，歧义时停止。

## 第 0 步（强制）先确认当前项目已部署 butler
升级的前提是当前项目**已经**装过 butler。开跑前先看当前目录有没有 `CLAUDE.md`（butler 管理区）与 `.ai/`：
- **有** → 正常往下走。
- **没有（当前项目从未部署 butler）** → 这是**首次部署**、不是升级：一句话告诉用户「当前项目还没接 butler，应走基地车部署（`mcv-deployment.md`）而非升级」，别硬跑升级流程。**不报错、不空跑。**

## 执行（委托真源，按迭代顺序走）
读 `Coder/20_Workflow_Lifecycle/butler-upgrade.md`，按其程序把当前项目同步到 `$BUTLER_PATH/VERSION` 最新版：

1. **§3 侦察**：读当前项目 `CLAUDE.md` 判有无 `<!-- user-managed -->` 保护区标记、扫 `.ai/` 过时命名 / 缺失字段、读 butler 仓最新模板、算版本 gap（目标戳 → 仓库 `VERSION`）。
2. **分派升级路径**：有保护区标记 + 有版本戳 → **§5 常规升级**（收集「目标戳 < vV ≤ 仓库 VERSION」区间的 `migrations/vX.Y.Z.md` 配方、按版本升序逐条幂等执行，每步起始态校验、漂移即停退回 ACK）；无标记 / 无版本戳（前版本化老项目）→ **§4 首次升级**（全量对齐）。
3. **§6 落地细则**：命名升级 / schema 字段补齐 / `[sync-hooks]` hook 副本同步 / `[split]` 文件夹化，按配方标签执行；**§6.3 不纳入升级范围**的项不碰。
4. **§7 验证与回退**：升级后核对 + 冲突或漂移时回退到 ACK，绝不带病覆盖用户内容。

**保护区红线**：`<!-- user-managed -->` 区、`origin/`、用户项目特有内容一律不覆盖（契约见真源 §5/§8）。

## 收尾
执行完，一句话回报用户：版本 gap（如 v2.4.0 → v2.7.0）、走了首次 / 常规哪条路径、执行了哪些配方步骤、有无待用户确认的漂移。
