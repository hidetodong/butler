你正在执行 butler 的 **里程碑录入 / 看板**动作。本命令是**薄壳路由器**——只做三件事：① 保证把对的规则读进上下文，② 按参数分派，③ 委托真源规则执行。**候办/正式落盘、里程碑号分配、录入协议和看板口径一律以被指向的规则文件为准，本文件不重写算法**（守 butler DRY 红线）。

> **路径约定（本命令可在任意项目里运行，当前目录不一定是 butler 仓）**：下文引用的 `Coder/…` 都是 **butler 规则仓库**里的文件，一律相对 `$BUTLER_PATH`（`setup.sh` 全局安装时写入的环境变量；编辑 butler 仓本身时就是仓库根）解析。产出（`.ai/MILESTONE.md`、`.ai/MILESTONES.md`、`.ai/references/prd/…` 等）一律落**当前项目**，绝不落 butler 仓。

> **项目根硬门**：读台账前先按 `$BUTLER_PATH/Coder/20_Workflow_Lifecycle/mcv-deployment.md §0.1` 解析 `PROJECT_ROOT`。上文“当前项目”一律指该绝对路径；用户点名路径优先，歧义时零写入。

## 第 0 步（强制）先确认当前项目已接 butler
里程碑建立在当前项目的 `.ai/` 台账之上。开跑前先看当前目录有没有 `.ai/`（尤其 `.ai/MILESTONES.md`）：
- **有** → 正常往下走。
- **没有 `.ai/`（当前项目没接 butler）** → 别硬建，一句话告诉用户「当前项目没接 butler，里程碑需要 `.ai/` 台账；请先部署基地车、或确认在对的目录」。**不报错、不空跑。**

## 按 `$ARGUMENTS` 路由

**分支 A ─ 留空，或给了一段里程碑方向说明 / brief 文件路径 → 录入**
读 `Coder/20_Workflow_Lifecycle/milestone-schema.md`——先按 **§6.1 启动信号** 判断这是不是该开里程碑，再按 **§6.4 录入（Brief）** 合成范围、理解和路线图。**soft 对齐只确认内容，不默认代表开工**：用户本轮已明确要立即推进，才按 **§7.1** 把内容写入 `.ai/MILESTONE.md`、从正式表最大号 +1 领 `MILE-NNNN`；用户暂缓或只是讨论，则按 **§7.6** 写 `.ai/milestone-backlog/<slug>.md` 并进 `MILESTONES.md` 待办区，不改 `current`、不占号。
　└ **若 brief 材料本身是大 PRD**（逐字权威规格）：按 §6.4 合成协议**并进**触发 `Coder/40_Context_Management/prd-split.md` 切成 `.ai/references/prd/`——一份输入同喂方向层路线图 + 细节层切片（见 §5.3 路线项↔slug 交叉指针）。

**分支 B ─ 以 `start <候办键>` 开头 → 候办提升**
读 §6.5/§7.1，核对候办索引与草稿一一对应，并确认当前没有 active 里程碑。通过后才领取正式表最大号 +1，将草稿提升为 `.ai/MILESTONE.md`，再删除候办行和草稿；任一步失败不得留下半提升状态。

**分支 C ─ 以 `status` 开头 → 只读看板**
读 §6.5，**只读汇总、不改盘**：汇报当前正式里程碑的范围、路线和迭代进度，并附待办区标题、暂缓日期与原因；无 active 里程碑时如实报明。**不写任何文件、不改状态。**

> 收口 / 废弃 / 演进 / 误开退回走语义（`milestone-schema.md §7.3–§7.6`）；命令面覆盖录入、候办提升和 status。

## 收尾
执行完，一句话回报用户：入库报候办键与“未占号”；开启/提升报新里程碑号与路线项数；status 报正式进度和候办数。
