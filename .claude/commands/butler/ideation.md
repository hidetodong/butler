你正在执行 butler 的 **需求脑暴**动作。本命令是**薄壳路由器**——只做两件事：① 保证把对的规则读进上下文，② 委托真源引擎执行。**脑暴的身份、阶段流程、压力测试维度、AC 收敛口径一律以被指向的规则文件为准，本文件不复述**（守 butler DRY 红线）。

> **路径约定（本命令可在任意项目里运行，当前目录不一定是 butler 仓）**：下文引用的 `Coder/…` 是 **butler 规则仓库**里的文件，相对 `$BUTLER_PATH`（`setup.sh` 全局安装时写入的环境变量）解析。脑暴产出（收敛后的 AC / 需求结论）落**当前项目**的对话与后续 `.ai/`，绝不落 butler 仓。

> **项目根硬门**：脑暴结果进入 P1/P2 并要落盘前，先按 `$BUTLER_PATH/Coder/20_Workflow_Lifecycle/mcv-deployment.md §0.1` 解析 `PROJECT_ROOT`。上文“当前项目”一律指该根；目标不唯一时只保留对话结论，不写 `.ai/`。

## 第 0 步 有没有接 butler 都能脑暴，但接了能更好衔接
脑暴是需求打磨、**不强依赖** `.ai/`——没接 butler 的项目里也能直接跑，帮用户把想法理清。但若当前项目**已接 butler**（有 `.ai/`），脑暴收敛出的 AC 可顺势接进 P1→P2（作 `CONCEPT`/`AC_LIST` 的输入）；开跑时留意这层衔接，别把脑暴结论丢在对话里不落地。

## 执行（委托真源）
读 `Coder/50_Extension_Ideation/ideation-engine.md`，按其 **§3 执行流程**自主推进：
1. **§3.1 意图探测**：提问厘清真正要解决什么、谁用、什么约束、有无倾向方案——**不假设、不脑补，用户回答前不进下一步**。
2. **§3.2 需求展开**：挖隐性需求（异常 / 边界路径、技术上必须处理的约束、与现有系统集成点）。
3. **§3.3 多维压力测试**：对展开后的需求做三维审视（按真源维度）。
4. 收敛为**可执行的验收清单**——脑暴的终点是把模糊意图变成能验收的 AC。

这是**独立脑暴动作、不进执行主线**：不冻结、不当 P2 的 ACK 门；产出用于喂后续 P1/P2，不替代它们。
